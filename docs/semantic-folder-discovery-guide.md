# 폴더 조사와 업무 생성 — 사내 시험 안내

기준일: 2026-09-15. 이 기능은 폴더 구조와 이름에서 프로젝트·의뢰·하중 경우를 만드는 핵심 흐름이다. 기존 예제는 결과 표시용으로 유지하며 실제 폴더를 예제에 맞출 필요가 없다. 결과 파일 읽기와 위젯 설정은 [기존 의미 매핑 안내](semantic-mapping-guide.md)를 이어서 사용한다.

## 시험 순서

1. 관리자로 **폴더/파일 스키마 → 의미 매핑 → 폴더 조사·업무 생성**을 연다.
2. 서버에서 접근 가능한 저장소 루트를 확인한다. 폴더 선택 창은 서버 저장소를 탐색한다. 접속한 사용자 PC의 Windows 탐색기와는 다르다. 저장소 미설정 상태에서는 관리자가 서버 경로를 설정한다.
3. 조사할 최상위 폴더를 선택하고 전체 조사를 실행한다. 저장소 전체는 선택창의 `root` 위치를 선택한다. 선택 폴더의 깊이는 0, 바로 아래 폴더는 1이다. 화면의 스크롤과 관계없이 서버가 하위 구조를 조사한다.
4. 조사 완료 뒤 폴더 깊이, 이름에 포함될 키워드, 직접 입력한 구분자, 번호 위치, 이름 시작 위치를 지정한다. 번호와 이름의 위치는 1부터 센다. 이름은 지정 위치부터 마지막 부분까지 합친다. 번호 위치 0은 폴더 이름 전체를 뜻한다. **구분자를 비우면 전체 폴더 이름을 이름으로 사용하고 코드는 비워 둔다. 구분자를 지정하면 해당 구분자가 들어 있는 폴더만 그 규칙에 일치한다.** 예를 들어 깊이 3·구분자 `_`인 규칙은 `LC03_하단낙하`를 선택하지만 `CAE`, `TEST`, `보고서`는 선택하지 않는다. 이 폴더들도 전체 조사 결과에는 남는다.
5. 생성 미리보기에서 신규 생성·기존 유지·충돌과 미분류 폴더를 확인한다. 프로젝트·의뢰·하중 경우를 만들 규칙을 저장하면 같은 위치의 다음 조사에서 다시 사용할 수 있다.
6. 불필요한 항목은 **이번 적용에서 제외**하고, 남은 충돌을 해소한 뒤 적용한다. 이 단계에서 실제 업무 항목이 생성된다. 조사나 미리보기만으로 업무 항목을 만들지 않는다. 같은 확정 내용을 다시 적용해도 중복 생성하지 않는다.
7. 생성한 하중 경우에 읽기 레시피와 표시 템플릿을 연결한다. 폴더 조사만으로 CSV/JSON을 읽거나 결과 Run을 생성하지 않는다.

## 첫 시험용 폴더

서버의 시험 저장소에 다음처럼 폴더를 준비한다. 이름과 번호는 회사 형식으로 바꾸어도 된다.

```text
시험루트/                  ← 깊이 0
└─ P001_신제품A/            ← 깊이 1: 프로젝트
   └─ R025_낙하검증/        ← 깊이 2: 의뢰
      └─ LC03_하단낙하/     ← 깊이 3: 하중 경우
         └─ 결과/           ← 규칙이 없으면 업무 생성 대상 아님
```

각 규칙에서 구분자 `_`, 번호 위치 `1`, 이름 시작 위치 `2`를 지정한다. 프로젝트 `신제품A`, 그 프로젝트의 의뢰 `낙하검증`, 그 의뢰의 하중 경우 `하단낙하`가 생성될지 미리보기에서 확인한다. 번호의 선행 0은 문자로 보존한다. 하중 경우의 해석 유형도 명시한다.

상위 프로젝트·의뢰 폴더의 정보는 하위에 이어진다. 일반 중간 폴더는 업무 항목으로 만들 필요가 없다. 같은 깊이에도 이름에 포함될 키워드로 규칙을 나눌 수 있다. 업무 번호와 이름은 폴더에서 추출하지만 내부 연결 ID는 별도로 유지한다. 하중 경우는 같은 깊이·같은 부모에서 이름이나 코드가 반복되어도 경로가 다르면 각각 생성한다. 같은 폴더가 여러 하중 경우 규칙에 동시에 일치하면 충돌을 표시한다.

## 생성 미리보기에서 제외

CREATE·CONFLICT·KEEP 행 모두 **이번 적용에서 제외**할 수 있다. 해당 경로와 하위 폴더의 모든 역할 행을 EXCLUDED로 표시하고 나머지 항목을 서버에서 다시 검증한다. 상위 제외로 빠진 하위 폴더를 복구하려면 상위 폴더의 **제외 취소**를 선택한다. 제외만으로 남은 충돌이나 불완전 조사 검사가 생략되지는 않는다.

KEEP 제외는 기존 프로젝트·의뢰·하중 경우나 결과 연결을 삭제하는 기능이 아니다. 이번 적용과 결과 연결 선택에서만 빠지며 기존 데이터와 연결은 보존한다. 이미 등록된 다른 폴더의 프로젝트·의뢰 코드를 재사용할 수 있게 해주는 기능도 아니다. 제외는 저장 규칙에 영구 저장되는 무시 목록이 아니므로 새 조사에서 다시 선택한다.

기존 공유 폴더 예시는 [SPDM 저장 폴더 연계](spdm-storage-workflow.md)와 `docs/shared_folder/` 사진에 있다. `Project_…/WR_…/CAE/모델/Drop/…`처럼 일반 폴더와 업무 폴더가 섞인 구조이며, 이 안내의 첫 시험용 폴더는 최소 동작 확인용이다. 깊이는 선택한 최상위 폴더 기준으로 계산하므로 예시의 깊이 3을 모든 실제 구조에 그대로 적용하지 않는다.

## 역할과 해석 종류 관리

관리자는 역할·해석 종류 설정에서 항목을 추가하고 표시 이름을 수정하거나 삭제할 수 있다. 삭제한 항목은 새 규칙의 선택 목록에서 제외하며, 이미 생성한 업무와 연결 이력은 보존한다. 변경을 저장한 뒤 미리보기를 다시 만든다.

역할에는 고유 키, 표시 이름과 처리 동작을 지정한다. 프로젝트·의뢰·하중 경우 동작은 해당 업무를 생성한다. 입력 폴더·결과 폴더 동작은 상위 하중 경우에 폴더의 용도를 기록하며 별도의 업무를 생성하지 않는다. 결과 폴더는 기존 결과 파일 연결 화면에서 레시피와 표시 템플릿을 지정해 처리한다. 새 역할이나 해석 종류를 추가하는 것만으로 새 파일 해석기나 자동 실행 프로그램이 만들어지지는 않는다.

해석 종류의 키는 업무에 저장하는 값이고 표시 이름은 선택창에 보이는 이름이다. 기존 이력이 참조하는 키와 역할의 처리 동작은 유지한다. 다른 의미의 값이 필요하면 새 항목을 추가한다. 코드가 비어 있는 폴더들은 경로와 내부 ID로 구별되므로 같은 부모 아래에서도 각각 등록할 수 있다.

## 핵심 범위와 보류 사항

- 전체 조사 실패·접근 불가·안전하지 않은 링크·조사 한도 초과는 불완전 조사로 표시하며 생성 적용을 막는다. 조사 후 폴더가 달라지면 다시 조사한다.
- 현재 한 번의 조사 한도는 폴더 5,000개, 전체 항목 50,000개, 깊이 64, 조사 시간 15초다. 한도를 넘긴 조사를 완료로 표시하지 않는다. 큰 저장소는 조사할 시작 위치를 나누어 선택한다.
- 확정된 폴더 연결은 재사용하고 예제 또는 비슷한 이름의 기존 업무를 임의로 합치지 않는다. 프로젝트·의뢰 번호 중복, 부모 누락, 이름 해석 실패는 미리보기에서 해소한다.
- 규칙을 저장했다고 기존 업무를 재명명하거나 삭제하지 않는다. 이름 변경·폴더 이동 자동 추적, 정규식 편집기, 주기적 자동 감시는 이번 핵심 구현 범위에 포함하지 않는다.
- 다음 새 폴더는 같은 규칙으로 **전체 조사 → 미리보기 → 적용**하여 등록한다.
- 공유 폴더는 서버 실행 계정이 읽을 수 있어야 한다. 폴더 경로와 사용자 데이터는 배포 패키지에 포함하지 않는다.

## 업데이트

소스 PC는 [Windows 배포 정책](windows-deployment-policy.md)에 따라 `update.bat`으로 업데이트한다. 신규 테이블은 백업 검증 후 migration 단계에서 적용하며 앱 시작 시 스키마를 변경하지 않는다. 이 안내는 실제 사내 공유 폴더 또는 폐쇄망 Server 2022 실기 완료를 뜻하지 않는다.
