# VOC 개선 의견 게시판

## 사용 방법

사이드바 **도움말 바로 아래 → VOC 게시판**에서 개선 의견을 텍스트로 입력하고 **등록**한다. 작성자 아이디·표시 이름은 로그인 계정에서 서버가 자동으로 기록하고, 등록 시각도 서버에서 정한다. 사용자가 다른 사람의 작성자 정보를 입력하거나 바꿀 수 없다.

승인된 로그인 회원은 게시판을 조회하고 의견을 등록하며 전체 목록을 **CSV 다운로드** 또는 **JSON 다운로드**로 받을 수 있다. 프로젝트 배정과 로컬 도우미 설치는 필요하지 않다. 가입 대기·중지 계정 및 비로그인 사용자는 접근할 수 없다. 게시글은 회원들이 공유하는 개선 의견이며, 이번 범위에는 첨부파일·댓글·수정·삭제·관리자 답변은 포함하지 않는다.

의견은 공백을 제외한 내용이 있어야 하며 최대 10,000자다. 줄바꿈을 유지하는 일반 텍스트로 표시하고 HTML로 실행하지 않는다. 등록 중 중복 클릭을 막고, 실패하면 입력을 보존해 다시 시도할 수 있다.

## 저장 및 다운로드

`voc_posts` 테이블에 게시글 ID, 작성자 사용자 ID, 작성 당시 아이디·표시 이름, 내용, UTC 등록 시각을 저장한다. 작성 당시 정보를 보관하므로 나중에 계정 표시 이름이 바뀌어도 기존 의견의 작성자 기록이 바뀌지 않는다. 비밀번호·세션·회원 전체 프로필은 저장하거나 내보내지 않는다.

목록은 최신순으로 페이지를 나누어 표시한다. 다운로드는 현재 페이지가 아닌 전체 게시글을 대상으로 한다. JSON은 원문 텍스트와 UTC 시각을 유지한다. CSV는 UTF-8 BOM과 표준 인용 처리를 사용해 한글·쉼표·따옴표·여러 줄 내용을 보존한다. 스프레드시트에서 수식으로 해석될 수 있는 셀에는 보호 접두어를 붙이며 원문이 필요하면 JSON을 사용한다.

데이터는 서버 DB에 남으므로 소스 업데이트나 서버 재시작으로 지워지지 않는다. 기존 PostgreSQL 전체 DB 백업에 포함된다. CSV/JSON 다운로드는 분석·의견 정리용 내보내기이며 DB 전체 복원을 대신하지 않는다.

## 구현 및 배포

- API: `GET/POST /api/voc/posts`, `GET /api/voc/export?format=csv|json`.
- 웹 경로: `/workspace/voc`.
- PostgreSQL: Alembic `0023_voc_posts` 마이그레이션으로 테이블과 목록 인덱스를 추가한다. 기존 계정·업무 데이터를 변경하지 않는다.
- DuckDB: 로컬 개발·검증 호환용 생성 경로만 유지한다. 운영 기본 DB는 PostgreSQL이다.

이번 업데이트에는 새 DB 테이블이 필요하다. 사내에서는 **`update.bat`**으로 기존 백업·마이그레이션·재시작 절차를 실행한다. `git pull` 후 시작 파일만 실행하는 방식으로는 PostgreSQL 마이그레이션이 수행되지 않는다. 별도 운영 배포 절차를 사용한다면 백업 후 `backend`에서 `alembic upgrade head`와 프론트 빌드를 적용하고 서버를 재시작한다.

내보내기는 1MB까지 메모리 임시 파일을 사용하고 이를 넘으면 OS 임시 파일로 전환한다. 파일 준비가 끝나면 DB 연결을 닫고 전송하므로 느린 다운로드가 DB 연결을 계속 점유하지 않는다. 응답 완료 후 임시 파일을 닫는다.

## 검증 기록 (2026-09-10)

- VOC API·저장·권한·메뉴·DB 경계 관련 pytest 18건 통과. 비로그인·가입 대기·중지 계정 차단, 작성자 위조 거부, 페이지 조회와 전체 내보내기, 한글·줄바꿈·수식 보호, UTC 시각 보존을 확인했다.
- 별도 임시 PostgreSQL에서 `alembic upgrade head`를 실행하고 `TIMESTAMPTZ`, 목록 인덱스, 일반·파워·관리자 메뉴 정책 생성을 확인했다. 검사 후 임시 서버와 데이터는 제거했다.
- Playwright 3건 통과: 도움말 바로 아래 메뉴, 텍스트 표시·작성자 자동 입력·재접속 후 유지, 저장·다운로드 실패 후 재시도, CSV/JSON 파일 내용, 다운로드 중 동시 목록 조회, 숨긴 메뉴의 직접 주소 차단, 프로젝트 없는 서버 사용을 검증했다. 데스크톱과 모바일 화면도 확인했다.
- 프론트 빌드, 라우팅 검사, 프론트 구조 검사 통과. 빌드에는 기존 대형 청크 경고가 남아 있다.
- 전체 백엔드 구조 검사는 이번 변경에 포함되지 않은 `app/routers/auth_accounts.py`의 기존 직접 SQL 호출 4건(허용 0건)으로 실패한다. 신규 VOC router에는 직접 SQL 호출이 없다.

브라우저 검증은 운영 DB와 분리된 DuckDB·로그인 fixture로 수행한다. 개발용 DuckDB에는 UTC로 변환한 시간대 없는 시각을 저장하고, PostgreSQL에는 시간대가 있는 시각을 저장한다. 실제 사내 배포 확인은 `update.bat` 적용 후 수행한다.
