## 4. 작업별 내용과 완료 조건

### W1 사이드바 숨김
- `AppSidebar.tsx`에 숨김 목록을 두고 그룹 구성에서 뺀다. 화면·경로·권한은 그대로, 직접 URL로는 열린다. "예제 및 참고" 그룹은 비어서 사라지고 도움말·VOC는 유지한다.
- 완료: 5개 메뉴 비노출, 직접 URL 동작, `access-policy` 등 관련 e2e 갱신·통과.

### W2 Final 복사 개편
- **복사:** 파일을 조각(예: 8 MiB) 단위로 읽고 쓰며 SHA-256을 동시에 계산한다. 메모리 사용은 파일 크기와 무관하다. 복사 함수는 저장소 계층(StorageProvider)의 기능으로 두어, 나중에 OS 복사 API(`CopyFile2`, SMB 서버 측 복사)를 "가능하면 먼저, 안 되면 조각 복사"로 끼울 수 있게 한다.
- **범위:** 형식 필터를 없애고 확정 Scene 폴더 아래 파일을 모두 CAE에 복사한다(입력 include 참조 포함). 제외: `~$*`, `*.tmp`, 숨김·시스템 폴더. 대시보드 표시 형식과 분리한다.
- **상한:** 파일 수·크기 상한 제거. 대신 시작 전 대상 드라이브 남은 공간 확인(필요량 + 여유분).
- **공개:** 같은 볼륨의 `Final/.finalizations/<Final ID>/staging/{CAE,Report}`에 쓰고 해시 확인 후 `Final/CAE/<Case>/<Final ID>`, `Final/Report/<Case>/<Final ID>`로 폴더째 이름 바꾸기. 완료 기록은 두 폴더가 모두 공개된 뒤에만 쓴다. 이름 바꾸기 실패(잠금·백신)는 재시도한다.
- **작업 스레드:** 확정은 작업을 등록하고 바로 응답한다. 백엔드 안의 작업 스레드가 실행한다(서버 전체 동시 1~2개, 같은 의뢰는 기존 의뢰 잠금으로 1개). 진행 상태(복사 완료 파일·해시·바이트)는 `.finalizations/<Final ID>/`의 파일에 기록한다. 새 DB 테이블·migration 없음.
- **이어하기:** 서버 시작 시와 상태 조회 시 미완료 작업을 찾아 같은 Final ID로 이어서 진행한다. 해시가 맞는 파일은 건너뛴다.
- **화면:** Final 창에 진행률(파일 수·용량·현재 파일), 닫아도 계속 진행, 실패 시 사유와 재시도.
- **보고서 업로드:** 기존 형식별 업로드(PPTX 64 MiB·HTML 320 MiB 상한과 검사)는 유지한다. 업로드된 보고서도 staging/Report로 들어간다.
- **기존 기록:** 이전 형식(v1·v2)의 완료 기록은 계속 검증·표시한다. 기존 Final 폴더는 옮기거나 지우지 않는다(D14).
- 완료: 수 GB 합성 파일 복사 성공(메모리 일정), 남은 공간 부족 시 시작 전 거부, 복사 중 서버 중단 → 재시작 후 이어서 완료, 공개 전에는 `CAE/<Case>/<Final ID>`가 보이지 않음, Working 무변경, 보고서 없이는 완료되지 않음.
- 검수: 경로·쓰기 경계 변경이므로 독립 검수(보안 포함). Codex Security 미가용 시 수동 검수로 대체하고 그렇게 기록한다.
- 구현(2026-10-06): 계획 3 형식, `LocalFsProvider.copy_stream`·`rename_no_replace`, `case_finalization_jobs` 작업 스레드, `GET /finalizations/{id}/job`, Final 창 진행률·헤더 `Final 복사 중 n%`·재시도. 계약은 [최종확정](../features/case-finalization.md). 실제 Server 2022·SMB·HPC 검증(W9)과 독립·보안 검수는 남음.

### W3 현재 Final·재지정
- 의뢰·환경당 현재 Final 하나. 재지정하면 이전 Final은 이력으로 남고 파일은 그대로다.
- 요약 파일(임시안 `Final/current.json`, 위치·형식은 SPDM 협의 후 확정): 현재 Final ID, Case, 지정자, 시각, CAE·Report 상대 경로, 파일 목록·해시, 이전 Final ID. 새 Final 공개 완료 후 임시 파일 쓰기 → 이름 바꾸기로 원자적 교체.
- 화면: Case 결과 상단에 현재 Final(Case·지정자·시각), 이력에서 이전 Final 구분, 다른 Case에서 "Final 다시 지정" 시 확인 문구.
- 완료: 재지정 후 요약 파일이 새 Final을 가리킴, 이전 Final 파일 보존, 동시 재지정 시 하나만 성공.
- 구현(2026-10-06): 현재 Final = 의뢰 잠금 안에서 마지막으로 완료를 커밋한 Final(동시 지정은 둘 다 완료되고 나중 커밋이 현재). 요약 파일 `Final/current.json`(임시안, 상수 하나), 서명 포인터 `.finalizations/designations.json`, `POST /finalizations/summary/repair`, 상태 `current_final`·`final_history`·`summary`, 헤더 현재 Final·재지정 확인란. 계약은 [최종확정](../features/case-finalization.md) "현재 Final과 재지정".

### W4 프로젝트 정리 (다른 세션 기본안)
- [운영 정리 계획](workspace-cleanup.md) 1·2절 그대로. 데모(고정 ID)와 등록 없는 프로젝트를 미리보기 → 확인 → 일괄 삭제, 예전 연결 기록 삭제(D15 예외), SPDM 파일 불변, 표 전수 조사 테스트, PostgreSQL 데모 미재생성, 등록 삭제 보완(하나씩 지워도 빈 프로젝트 안 남음).

### W5 Case 비교 화면
- Case 2~4개 선택, 같은 Run Option·같은 Scene끼리 값 나란히, 기준 Case 대비 증감, 최대값 강조. 사용·유통 환경 모두.
- 보고서에 "후보 Case 비교" 구역 선택 추가. 비교 화면에서 "이 Case를 Final 지정"으로 연결.
- 완료: 값이 각 Case 화면과 일치, Scene 이름 불일치 시 표시, 4K·18pt 화면 확인.

### W6 폴더 이름 경고
- 같은 Run Option 아래 대소문자·철자만 다른 Scene, Case 간 Scene 이름 불일치, 예상 밖 폴더를 Case 결과 화면에 경고(폴더는 고치지 않음). 깊이 스키마 이탈 코드와 문구를 맞춘다.
- 완료(2026-10-06): catalog `name_warnings` 추가 필드, 머리줄 "폴더 이름 확인 n건" 배지·목록, Scene 비교 아이콘. 기준·필드는 [폴더 이름 경고](../features/folder-name-warnings.md).

### W7 보고서 A안
- 템플릿 미적용 안내를 레이아웃 선택 옆에 항상 표시. Final 보고서가 보고서 창에서 고른 레이아웃을 쓰도록 연결(마지막 사용 레이아웃 기본값). 작성자 자동 입력, 개발단계·검토조건·결론 선택 입력칸(보고서 창·Final 창).

### W8 결과 등록 화면 축소
- 실제 사용은 직접 복사가 중심이므로 등록 화면을 "Scene 폴더 열기 + 끌어서 복사" 수준으로 줄이는 안을 사용자 확인 후 진행. 경로 경계·권한 검사는 유지.

### W9 실제 환경 검증
- Windows Server 2022 + 실제 공유폴더(가능하면 HPC 드라이브): 30초 자동 확인 부하, 수 GB Final 복사 시간·서버 부하, 이름 바꾸기 잠금·백신 영향, 대소문자 구분 여부, 서비스 계정 권한·경로 길이, 재부팅 후 미완료 Final 이어하기. 수행하지 않은 항목은 수행한 것으로 기록하지 않는다.

## 7. 공통 원칙

- 실제 사용자 DB·공유폴더·실행 중 서비스로 시험하지 않는다. 격리된 임시 환경과 합성 데이터로 검증한다.
- SPDM 폴더·파일은 지우거나 옮기지 않는다(앱이 만든 staging만 정리).
- 새 DB migration·런타임 의존성은 두지 않는 것을 원칙으로 한다. 필요해지면 배포 계약(lock·오프라인 패키지·빈 설치·기존 DB 업데이트 검증)을 같은 변경에서 갱신한다. 다른 세션 예약 번호(0034·0035)와 충돌하지 않게 한다.
- 데이터 삭제(W4)·쓰기 경계(W2·W3)·권한 변경은 독립 검수를 받는다.
- 다른 세션 담당 파일(`folder_auto_discovery.py`, `folder_discovery_environment.py`, `folder_schema_resolver.py`, `environment_folder_profiles.py`, `folder_environment_deletion.py`, 폴더 조사 화면, 깊이 스키마 계약·결정 기록)은 협의 없이 고치지 않는다. W2의 저장소 계층(StorageProvider) 확장은 그 세션과 인터페이스를 맞춘다.
- 알려진 기존 실패: e2e `simulation-dashboard`의 폐기된 capture-pin 검사 1건, `drop-video-grid` 기존 실패. W1 또는 W2 때 정리한다.
