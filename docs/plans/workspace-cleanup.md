## 0. 배경 (사용자 확인)

- 폴더 스키마 등록 이력을 모두 삭제하고 새로 등록했지만, 과거에 쓰던 프로젝트가 목록에 남았다.
- 원인은 "등록보다 먼저 있던 프로젝트"다(사용자 확인: 경우 ②). 예전 폴더 조사, SPDM 저장소 연결, 직접 생성으로 만들어진 프로젝트는 §13.2 소유 판정에서 기존 업무로 보아 보존한다(D15).
- 데모·예제 프로젝트도 함께 지우기로 했다(사용자 지시 2026-10-06 10:49).
- 운영 DB(PostgreSQL)는 앱 시작과 `update.bat`에서 예제 데이터를 만들지 않는다. 신규 설치는 `--seed-mode empty`를 쓰고, 예제 생성은 명시적 스크립트(`scripts/seed_database.py`)뿐이다. 따라서 한 번 지우면 다시 생기지 않는다. 개발용 DuckDB는 시작 시 `ensure_default_content`로 다시 채운다.

## 1. 프로젝트 정리 (관리자)

### 1.1 대상

| 구분 | 예 | 판정 |
|---|---|---|
| 데모·예제 | Orion 65 TV(`project-tv-001`), 기능 예제 모음(`project-feature-showcase`, 의뢰 7개), Radioss CSV 등록 검토(`project-d2f8298b56ce`) | 코드 상수의 고정 ID 목록. 이름으로 판정하지 않는다 |
| 등록 없는 프로젝트 | 등록 전부터 있던 75R9J_PV, CAD 단독 의뢰 프로젝트 등 | 살아 있는(DELETED가 아닌) 폴더 스키마 등록이 0건 |
| 등록된 프로젝트 | 깊이 스키마로 등록된 프로젝트 | 대상 아님. §13 등록 삭제로 안내 |

### 1.2 삭제 범위

| 지움 (선택한 프로젝트 것만) | 남김 |
|---|---|
| 프로젝트, 의뢰, 하중경우, 작업 단계·작업 항목·작업 계획, 실행 기록, 검증 | SPDM 폴더·파일 전부(Working·Final·`.finalizations`, D14) |
| 분석 페이지와 버전, Case·캡처·결과 자산, 결과 등록 초안·파일·이벤트 | 계정·권한, 감사 기록 |
| 프로젝트 전용 설정(품질 기준, 제품 정보, 멤버십·초대, 워크스페이스 레이아웃, 결과 프로필, 프로젝트 변수·어휘) | 공용 설정(보고서 레이아웃, 의뢰 유형·작업 카탈로그, 메뉴 정책) |
| 예전 연결 기록(`folder_discovery_registry`, `spdm_storage_*`, `semantic_folder_bindings`) — **D15 예외** | 폴더 조사·미리보기 이력 행(프로젝트·의뢰 ID만 NULL) |
| 다른 곳에서 참조하지 않는 미디어(데모 영상·이미지 청크) | 다른 프로젝트가 참조하는 미디어 |

D15 예외: 관리자가 이 기능에서 명시적으로 선택한 프로젝트에 한해 예전 연결 기록도 삭제한다. 계약 문서에 같은 변경에서 반영한다.

### 1.3 흐름

관리 › 폴더 스키마 › **프로젝트 정리** 탭

1. 목록: 이름, 구분(데모 / 등록 없음 / 등록됨), 의뢰 수, Case·이력 수. 사람이 직접 만든 데이터(분석 페이지, 실행 기록 등)가 있으면 경고하고 기본 선택에서 뺀다.
2. 체크 선택 → **미리보기**(프로젝트별·표별 삭제 건수) → "SPDM 폴더·파일은 삭제되지 않습니다" 확인 → 삭제.
3. 한 트랜잭션, 자식부터 삭제, cascade 없음. 차단 사유가 하나라도 있으면 전부 취소(409). `confirm_token`으로 미리보기 이후 변경을 거부한다(§13.6과 같은 방식).
4. 차단: 실행 중인 작업(관리형 실행·배치), 살아 있는 등록이 있는 프로젝트.
5. 삭제 후 목록·선택 상태를 다시 읽고, 삭제된 프로젝트를 보고 있었으면 선택을 해제한다. 필요한 프로젝트·의뢰는 폴더 자동 확인이 깊이 스키마로 다시 등록한다.
6. 감사 이벤트 `PROJECT_CLEANUP_DELETED`(건수 요약). 전역 관리자 전용.

### 1.4 재생성 방지

- PostgreSQL: 시작·업데이트에서 예제를 만들지 않음을 테스트로 고정한다.
- 개발용 DuckDB: "데모 제거됨" 표시(기존 설정 저장소 사용, 새 테이블 없음)를 `ensure_default_content`가 존중하게 한다. 테스트는 새 DB를 쓰므로 영향 없다.

## 2. 등록 삭제(§13) 보완

같은 프로젝트를 쓰는 등록을 하나씩 지우면 마지막 등록이 프로젝트를 "만든" 등록이 아니어서 빈 프로젝트가 남을 수 있다. 마지막 살아 있는 등록을 지울 때, 이미 DELETED된 같은 프로젝트의 등록까지 묶어 소유를 판정하도록 보완한다.

## 3. 사이드바 단순화 (사용자 지시 2026-10-06 13:40)

현 사용 시나리오에서 쓰지 않는 메뉴를 사이드바에서 숨긴다.

| 숨길 메뉴 | 메뉴 id | 위치 |
|---|---|---|
| 새 의뢰 | `intake` | 기본 메뉴 |
| 예제 및 참고(기능 예제 갤러리) | `examples` | 예제 및 참고 그룹. 그룹이 비어 그룹 자체가 사라진다. 도움말·VOC는 단독 링크로 유지 |
| 변수 카탈로그 | `variables` | 설정 및 관리 |
| 프로젝트 결과 구성 | `project_result_profiles` | 설정 및 관리 |
| 작업 유형 관리 | `workbench_admin` | 설정 및 관리 |

- 방식: `frontend/src/app/shell/AppSidebar.tsx`에 숨김 목록(`SIDEBAR_HIDDEN_MENUS`)을 두고 그룹 구성에서 제외한다. 화면·경로·권한은 바꾸지 않으며 직접 URL로는 열린다. 목록에서 id를 빼면 다시 보인다.
- 테스트 영향: `e2e/access-policy.spec.ts`의 역할별 메뉴 노출 검사 3곳(새 의뢰, 변수 카탈로그, 작업 유형 관리)을 "사이드바 비노출"로 바꾼다. 확인 대상 spec: access-policy, project-result-profiles, workbench-demo, request-centric-workspace, unified-request-workspace, ui-density-p5-root(URL 직접 이동이라 영향 없음 예상).
- 남은 진입점: 프로젝트 화면의 "해석 의뢰 접수" 버튼(`ProjectSetupState.tsx`) 등 사이드바 밖 진입점은 이번 범위가 아니다. 필요하면 별도로 정한다.
- 3절은 1·2절과 독립이며 작은 변경이다. 다른 세션 작업이 끝나면 먼저 적용할 수 있다.
