# 해석 결과 보고서 PPTX 내보내기 사양

문서 버전: 3.0

## 1. 목적과 범위

해석 대시보드에 등록된 프로젝트, 하중 케이스, 정량 결과, 시간 이력 및 미디어를 사용해 편집 가능한 PowerPoint 보고서를 생성한다. 생성 과정에는 LLM을 사용하지 않으며, 데이터와 명시적 규칙만 사용한다.

- 실행 환경: Linux/Windows에서 서비스 가능
- 현재 구현 위치: React 브라우저 클라이언트
- 출력: `.pptx`
- PDF: 본 기능의 직접 출력 범위에서 제외한다. 서버에서 LibreOffice headless 변환 기능을 추가할 수 있다.
- 원본 데이터, 판정 기준 및 사용자 입력 문구를 임의로 변경하거나 추론하지 않는다.

### 1.1 2.0 확장 범위

- 보고서 레이아웃을 드롭다운으로 선택한다.
- 표지 형식, 강조색, 근거 페이지 순서와 미디어 포함 여부를 편집한다.
- 결과 변수별 포함 여부, 출력 순서, `차트`·`표`·`차트 + 표` 표현을 설정한다.
- 레이아웃을 새 이름으로 저장하거나 기존 레이아웃의 새 버전으로 저장한다.
- 기본 레이아웃도 편집할 수 있지만 삭제할 수는 없다.
- 사용자 레이아웃은 비활성화 방식으로 삭제한다.
- 레이아웃 정의와 버전 이력은 DB에 저장하며 PostgreSQL 전환 후 JSONB로 유지한다.

### 1.2 3.0 시각 편집 및 PPTX 템플릿 범위

- 레이아웃 편집기는 슬라이드 목록, 16:9 캔버스, 속성·변수 패널의 3영역으로 구성한다.
- 캔버스는 32 × 18 논리 그리드를 사용하며 위젯의 이동·크기 조절 결과를 PowerPoint 인치 좌표로 변환한다.
- 제목, 텍스트, 판정, 결과 카드, 차트, 표, 이미지 위젯을 추가할 수 있다.
- 변수 카탈로그의 변수를 캔버스로 끌어 놓거나 속성 패널에서 연결한다.
- 슬라이드는 추가·복제·순서 변경할 수 있고, `series-variable`과 `media-item` 반복 규칙을 지원한다.
- 기존 2.0 레이아웃은 열 때 기본 `slides[]` 정의를 보충하며, 저장하기 전까지 DB 원본을 변경하지 않는다.
- 사용자가 만든 `.pptx`를 규칙 기반 템플릿으로 업로드하고 도형 이름 또는 텍스트 태그를 변수·보고서 필드에 연결할 수 있다.
- 업로드 템플릿은 원본 OOXML을 보존한 채 지정된 텍스트 플레이스홀더만 치환한다. 임의 PPTX 전체 편집은 범위에 포함하지 않는다.

## 2. 입력 데이터

대시보드의 `Overview` 응답과 내보내기 창의 사용자 입력값을 사용한다.

### 2.1 실행 위치와 평가 범위

- 프로젝트의 `해석 상세` 화면에서 실행한다.
- `오픈셀 파손 평가` 탭 바로 옆의 `보고서 내보내기` 버튼은 오픈셀 변수와 판정만 포함한다.
- `Chassis rear 휨 평가` 탭 바로 옆의 `보고서 내보내기` 버튼은 `chassis_rear_` 변수와 해당 판정만 포함한다.
- 평가 범위가 명시된 미디어는 같은 범위의 보고서에만 포함한다. 범위 메타데이터가 없는 공통 미디어는 양쪽 보고서에서 사용할 수 있다.
- 전체 데이터가 섞이지 않도록 선택 평가의 시간 이력, 정량 결과, 위치 결과 및 곡선 데이터를 내보내기 전에 필터링한다.

| 필드 | 필수 | 규칙 |
|---|---:|---|
| 프로젝트명 | 예 | 선택된 하중 케이스에서 자동 입력 |
| 작성자 | 예 | 사용자가 입력 |
| 개발단계 | 예 | `DV n차`, `PV n차`, `PR n차`; n은 1 이상의 정수 |
| 작성날짜 | 예 | `YYYY.MM.DD.` |
| 시뮬레이션 종류 | 예 | 낙하, Side Clamp, 적재 등 |
| 검토 목적 | 예 | 사용자 입력, 기본값은 해석 요청 제목 |
| 검토 사양 조건 | 예 | 사용자 입력, 기본값은 하중 케이스 파라미터 |
| 검토 결과 | 예 | 사용자 입력, 기본값은 정량 결과 요약 |
| 검토 결론 | 예 | 사용자 입력, 기본값은 전체 판정 규칙 문장 |

## 3. 슬라이드 구성

### 3.0 레이아웃 정의

```json
{
  "id": "report-layout-standard",
  "name": "표준 검토 보고서",
  "version": 1,
  "coverVariant": "balanced",
  "accentColor": "1898D5",
  "sectionOrder": ["series", "scalar", "media"],
  "variablePlacements": [
    {"variableKey": "top_edge_stress_time", "presentation": "chart", "order": 0},
    {"variableKey": "top_edge_max_stress", "presentation": "table", "order": 1}
  ],
  "includeMedia": true
}
```

3.0 정의는 기존 필드에 다음 구조를 추가한다.

```json
{
  "canvas": {"columns": 32, "rows": 18, "widthInches": 13.333, "heightInches": 7.5},
  "templateSource": "native",
  "templateAssetId": null,
  "templateBindings": {},
  "slides": [
    {
      "id": "slide-series",
      "name": "시간 이력",
      "kind": "series",
      "repeat": "series-variable",
      "elements": [
        {
          "id": "series-chart",
          "type": "chart",
          "label": "시계열 차트",
          "x": 1, "y": 4, "w": 23, "h": 12, "z": 1,
          "binding": {"source": "series", "key": "chart"},
          "rules": {"visibleWhenData": true}
        }
      ]
    }
  ]
}
```

- `kind`: `cover`, `series`, `scalar`, `media`, `custom`
- `repeat`: `none`, `series-variable`, `media-item`
- 위젯 좌표는 슬라이드 경계를 벗어날 수 없다.
- 브라우저 미리보기와 PPTX 생성기는 동일한 `slides[].elements[]` 좌표를 사용한다.
- `templateSource=pptx_upload`인 경우 `templateAssetId`가 필수다.

### 3.0.1 PPTX 태그 규칙

PowerPoint의 선택 창에서 도형 이름을 지정하거나 도형 텍스트에 태그를 입력한다.

| 구분 | 도형 이름 | 텍스트 태그 | 용도 |
|---|---|---|---|
| 변수 | `VAR:top_edge_max_stress` | `{{variable:top_edge_max_stress}}` | 변수 결과값·단위·판정 |
| 보고서 필드 | `TEXT:review_conclusion` | `{{field:review_conclusion}}` | 작성자 입력 및 프로젝트 정보 |
| 차트 위치 | `CHART:top_edge_stress_time` | `{{chart:top_edge_stress_time}}` | 현재 버전은 요약 텍스트로 치환 |
| 이미지 위치 | `IMAGE:contour` | `{{image:contour}}` | 현재 버전은 자산명·경로로 치환 |

- 업로드 직후 슬라이드 수, 태그, 도형 위치를 검사해 웹 미리보기에 표시한다.
- 텍스트가 여러 DrawingML run으로 분리돼도 도형 단위로 결합해 태그를 찾는다.
- `.pptm`, VBA, OLE, 임베디드 실행 개체, 외부 관계, 25MB 초과 파일을 거부한다.
- 차트와 이미지의 네이티브 개체 삽입은 후속 호환성 확장 범위이며, 현재는 원본 도형을 유지하면서 텍스트 대체값을 기록한다.

- `coverVariant`: `balanced`, `executive`, `evidence`
- `sectionOrder`: `series`, `scalar`, `media`를 중복 없이 배치한다.
- `variablePlacements`가 비어 있는 기본 레이아웃은 선택 평가 범위의 모든 변수를 포함한다.
- 저장된 사용자 레이아웃에서는 목록에 있는 변수만 출력한다.
- 데이터가 없는 선언 변수는 그래프 값을 추정하지 않는다.
- 저장할 때 현재 정의를 `report_layout_versions`에 스냅샷으로 추가한다.

기본 제공 형식:

1. 표준 검토 보고서: 시간 이력 → 정량 결과 → 미디어
2. 경영진 요약 보고서: 정량 결과 → 시간 이력 → 미디어, 결론 강조 표지
3. 상세 근거 보고서: 시간 이력 → 미디어 → 정량 결과, 근거 중심 표지

### 3.1 1페이지 — 결과 요약

- 제목: `[프로젝트명] 해석 결과 보고서`
- 제목 바로 아래 왼쪽: `[작성자] | [개발단계]`
- 같은 높이 오른쪽: `[작성날짜]`
- 우측 상단: 전체 판정 PASS/FAIL/NO_DATA
- 두 번째 행 왼쪽: 시뮬레이션 종류
- 두 번째 행 오른쪽: 검토 목적
- 본문 왼쪽: 검토 사양 조건
- 본문 오른쪽 위: 검토 결과
- 본문 오른쪽 아래: 검토 결론
- 첨부 사진을 참고해 청색 외곽선, 흰색 본문, 판정 강조색을 사용한다.

### 3.2 2페이지 이후 — 근거 해석 자료

1. 시간 이력 데이터의 변수별 응력/변형량-시간 그래프
2. 위치별 최대 응력 또는 휨량 비교 그래프와 결과표
3. 등록된 해석 이미지/스크린샷
4. 영상·애니메이션 자산 정보

시간 이력은 가독성과 파일 크기를 위해 최대 25개 지점으로 균등 다운샘플링한다. 원 데이터와 최대값 판정에는 영향을 주지 않는다. 단위가 서로 다른 위치별 결과는 절대값을 한 축에서 비교하지 않고, `결과값 ÷ 기준값 × 100`으로 계산한 기준 대비율(%) 그래프로 표시한다. 실제 값과 단위는 같은 페이지의 결과표에 유지한다.

## 4. 판정 및 문구 규칙

- 전체 판정이 `PASS`이면 기본 결론은 “검토 사양을 만족하여 PASS로 판정함.”
- 전체 판정이 `FAIL`이면 기본 결론은 “기준 초과 항목이 확인되어 FAIL로 판정함. 상세 근거와 개선 검토가 필요함.”
- 전체 판정이 `NO_DATA`이면 데이터 부족 문구를 사용한다.
- 사용자는 내보내기 전에 모든 기본 문구를 수정할 수 있다.
- 개발단계와 날짜 형식은 내보내기 직전에 검증한다.

### 4.1 DB 결측값 처리

- DB 변수 항목은 존재하지만 결과값이 `null`, 누락 또는 유효하지 않은 숫자이면 보고서의 값 셀을 공란으로 표시한다.
- 값이 없는 항목의 단위와 판정도 공란으로 표시한다.
- 기준값만 존재하는 경우 기준 셀은 표시하고 결과값과 판정 셀은 공란으로 둔다.
- 그래프에는 유효한 숫자 결과와 0이 아닌 기준값이 모두 존재하는 항목만 포함한다.
- 모든 그래프 값이 비어 있으면 그래프 영역은 빈 상태로 유지하며 임의의 0값이나 추정값을 생성하지 않는다.
- 결측값 때문에 PPTX 생성 전체를 실패시키지 않는다.

## 5. 차트 및 미디어 처리

- 차트는 PowerPoint 네이티브 차트로 생성해 출력 후 편집할 수 있게 한다.
- 이미지 자산은 PPTX에 포함한다.
- 영상 및 애니메이션은 PowerPoint/LibreOffice 간 호환성 차이 때문에 현재 자동 삽입하지 않는다.
- 영상은 대표 프레임을 `IMAGE` 자산으로 별도 등록하고, 원본 영상은 보고서와 함께 별도 전달하는 것을 권장한다.
- 이미지 로딩 실패 시 해당 슬라이드에 실패 안내와 자산 정보를 남긴다.

## 6. 파일명과 보안

- 파일명: `[프로젝트명]_[시뮬레이션 종류]_[검토 목적]_해석결과보고서.pptx`
- 운영체제에서 허용되지 않는 파일명 문자는 `_`로 치환한다.
- 보고서 생성은 브라우저 메모리에서 수행되며 별도의 외부 LLM 또는 외부 문서 생성 API로 데이터를 전송하지 않는다.

## 7. 수용 기준

- 필수 입력이 유효하면 `.pptx` 파일이 다운로드된다.
- 두 평가 탭 각각의 옆에 `보고서 내보내기` 버튼이 표시된다.
- 각 버튼으로 생성한 보고서는 선택한 평가 범위의 데이터와 판정만 포함한다.
- 1페이지에 요청된 8개 정보 영역이 모두 표시된다.
- 시간 이력 데이터가 있으면 변수별 그래프 페이지가 생성된다.
- 정량 결과가 있으면 위치별 비교 및 결과표 페이지가 생성된다.
- 이미지가 있으면 이미지 근거 페이지가 생성된다.
- 결과가 없는 종류의 페이지는 생성하지 않는다.
- DB 변수에 값이 없더라도 내보내기가 성공하고 해당 값 셀은 공란이어야 한다.
- Linux 및 Windows에서 동일한 프런트엔드 빌드가 동작한다.
- 레이아웃 드롭다운에 이름과 최신 버전이 표시된다.
- 버전 드롭다운에서 이전 스냅샷을 선택해 같은 형식으로 다시 출력할 수 있다.
- 레이아웃 편집에서 표지 형식, 강조색, 섹션 순서, 변수 배치를 변경할 수 있다.
- 기존 레이아웃 저장 시 버전이 1 증가하고 이전 정의가 보존된다.
- 다른 이름으로 저장하면 별도 레이아웃 v1이 생성된다.
- 기본 레이아웃 삭제는 거부되고 사용자 레이아웃은 비활성화된다.
- 선택한 레이아웃의 변수 포함·표현·순서가 PPTX에 반영된다.
- 슬라이드 캔버스에서 이동·크기 조절한 좌표가 생성된 PPTX에 반영된다.
- 사용자 슬라이드와 변수 위젯을 추가하고 저장한 후 버전을 다시 불러올 수 있다.
- 규칙을 지킨 PPTX 업로드 시 슬라이드별 플레이스홀더와 위치가 표시된다.
- 플레이스홀더를 보고서 필드 또는 변수에 연결한 뒤 원본 PPTX 디자인을 보존한 결과 파일을 내려받을 수 있다.
- 매크로·OLE·외부 관계가 포함된 템플릿은 저장 전에 거부된다.
