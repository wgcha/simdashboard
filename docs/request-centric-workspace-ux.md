# 결과 대시보드와 의뢰 중심 작업공간 GUI

- 기준일: 2026-09-08
- 상태: 구현 및 최종 검증 완료. 후속 GUI 개발의 현재 기준이다.
- 대상: 해석 수행자와 결과 검토자
- 범위: 기존 웹 앱의 메뉴, 의뢰 문맥, 작업 진행, 결과 탐색 및 정보 노출 순서

## 제품 원칙

첫 화면은 독립된 **결과 대시보드**다. 2026-09-08 추가 사용자 요청에 따라 기존 `/workspace/overview`에서 결과 요약을 먼저 보여주고, 의뢰 중심 작업공간은 `/workspace/requests`로 분리한다. 결과를 선택하면 해당 프로젝트·의뢰·하중 경우·Run을 유지하며 상세 검토 또는 의뢰 개요로 이동한다. 해석 용어는 유지하되 시스템 구현 용어와 드물게 사용하는 편집·운영 기능은 필요할 때 공개한다.

프로젝트가 있으면 선택 의뢰의 하중 경우·결과가 아직 없어도 대시보드, 작업 실행, 의뢰 접수를 열 수 있다. 프로젝트가 전혀 없는 최초 환경은 기존 프로젝트 생성 안내로 시작한다.

현재 값, 단위, 판정 기준, 선택한 결과 버전, 결과 없음과 데모 여부는 숨기지 않는다. 데이터를 추가로 가져오지 않았거나 관계가 확인되지 않은 경우 요약 수치·판정·원인을 추정하지 않는다.

## 화면 구성

| 영역 | 기본 노출 | 상세 접근 |
|---|---|---|
| 주 메뉴 | 결과 대시보드, 내 작업, 새 의뢰 | 설정 및 관리, 도움말 |
| 결과 대시보드 | 검토 필요·결과 보유·결과 대기, 최근 결과, 유형별 판정 | 결과 검토, 의뢰 보기, 기존 운영 현황과 편집 |
| 의뢰 문맥 | 의뢰명, 담당자·상태, 프로젝트·의뢰·하중 경우 | 다른 의뢰 선택, 결과 검토 시 Run 선택 |
| 의뢰 개요 | 선택한 의뢰 한 건, 현재 할 일, 주 행동, 작업 단계 | 의뢰 정보, 전체 작업 이력, 다른 의뢰 |
| 작업 실행 | 현재 작업, 필요한 입력, 실행 상태, 주 행동 | 진행도 편집, 배치 설정, 이벤트, 로그·데모 이력 |
| 결과 등록 | 선택한 의뢰/하중 경우의 결과 가져오기 | 프로젝트·하중 경우 생성, 등록 이력 |
| 결과 검토 | 실제 결과 기반 판정·수치·단위·기준·Run과 분석 | 결과 페이지, 비교, 보고서, 화면 편집 |

`내 작업`은 현재 선택한 의뢰의 작업공간 진입점이다. 서버가 반환하는 프로젝트 권한 범위는 그대로이며, 이 메뉴 이름만으로 본인 소유 의뢰 필터가 적용되었다고 간주하지 않는다.

결과 대시보드의 API는 기존 portfolio projection을 사용한다. 레코드는 하중 경우별 최신 `run_no`의 Run이며, 판정·결과 개수는 수치 결과 기준이다. Run은 있으나 판정이 없으면 `판정 없음`, 하중 경우는 있으나 Run이 없으면 `결과 대기`로 구분한다. 하중 경우 미지정 의뢰는 하중 경우 집계에 더하지 않는다. 업무 데모 이력은 분석 Run이 데모라는 근거로 사용하지 않는다. 단위가 다른 값을 합산하거나 평균하지 않는다.

개요 → 작업 실행 → 결과 등록 → 결과 검토는 같은 의뢰에 대한 탐색이다. 실행 dependency를 새로 정의하는 직선형 wizard가 아니다. 완료한 결과와 이전 단계는 권한에 따라 다시 열 수 있다. 실제 실행은 기존 서버 작업계획과 상태 전이를 따른다.

2026-09-08 후속 개선에서는 네 탭 모두 공통 의뢰 헤더를 사용하고, 실행·등록에서도 사이드바의 ‘내 작업’ 선택을 유지한다. 중복 ‘작업 도구’ 진입 메뉴는 제거하며 기존 직접 URL은 유지한다. 와이드 화면 조정과 검증 기록은 [후속 개선 계획](unified-request-workspace-plan.md)을 따른다. 아래 2026-09-07 구현·검증 기록은 당시 완료 범위다.

## 정보 연결과 화면 상태

- 메뉴별 기존 canonical path와 단일 route registry를 유지한다.
- 문맥을 URL에 보존하는 확장은 기존 deep-link 제외 결정을 대체한다. 식별자는 서버 권한 및 실제 부모·자식 관계로 검증한다.
- 의뢰 접수의 초기 프로젝트는 현재 선택을 따른다. 결과 등록에서는 의뢰와 하중 경우를 이어받는다.
- 작업 실행에서 다른 의뢰를 선택하면 상위 프로젝트와 하중 경우도 일치해야 한다.
- 결과의 Run 선택은 판정·그래프·비교·보고서에서 같은 데이터를 가리켜야 한다.
- 분석 페이지 탐색은 탭과 동일한 페이지 선택기를 중복 노출하지 않는다.
- 기존 비동기 문맥 guard, 편집 중 이동 보호, 권한 fallback, 빈 상태와 오류 표시를 보존한다.
- 의뢰 이동은 데이터와 URL이 모두 반영된 뒤 다음 행동을 허용한다. 로딩 중 이전 의뢰의 실행 버튼이나 Run 번호를 새 결과에 연결하지 않는다.
- 하중 경우가 아직 없는 새 의뢰도 선택 의뢰의 현재 작업을 표시한다. 실행 계획이 없으면 해당 의뢰를 유지하며 안내하고, 다른 배정 의뢰로 자동 전환하지 않는다.

## 유지하는 안전·데이터 계약

- 서버의 project scope, 사용자 역할, owner와 실행 권한 검사를 유지한다. 메뉴를 접는 것은 접근 권한 변경이 아니다.
- 업무 유형 버전, 의뢰의 work-plan/result-layout snapshot, 기존 Run은 불변이다.
- 다음 작업을 자동 실행하지 않으며, 서버의 dependency와 READY/IN_PROGRESS 등의 전이를 따른다.
- `DEMO ONLY`, `실제 해석 결과 아님`은 접힌 기술 상세 안으로 숨기지 않는다. 데모 실행을 실제 solver 실행이나 결과 발행으로 바꾸지 않는다.
- API, DB schema, 결과 적재·파일 계약, SPDM/Altair One adapter의 구현 범위는 이번 GUI 개편으로 변경하지 않는다.
- 새 UI가 범용 결과에 Open Cell/Chassis 수치나 판정을 임의 적용하지 않도록 결과 종류와 실제 데이터 유무를 확인한다.

## 디자인과 검증

기존 React·React Router·lucide·Recharts를 사용한다. 기능별 스타일과 컴포넌트를 분리한다. 기본 디자인은 흰 표면, 차가운 회색 배경, 짙은 텍스트와 절제된 파란 강조, Pretendard 계열 글꼴, 8px 모서리와 일정한 여백이다. 기존 테마·글자 크기 선택을 존중하고 데스크톱/모바일에서 조작 가능해야 한다.

글꼴은 번들 Pretendard와 시스템 고정폭 글꼴을 사용하며 외부 Google Fonts 요청을 제거했다. 네트워크가 차단된 환경에서도 글꼴 요청 오류 없이 화면을 표시한다.

검증은 정적 빌드만으로 완료하지 않는다. 의뢰 선택 → 실행/등록 이동 → 결과 검토 → Run 변경과 되돌아가기, 접힌 기능의 접근성, 빈 의뢰/결과, 권한 차이, 기존 편집/보고서 흐름을 확인한다. IAB 브라우저의 실제 화면 검증과 저장소 Playwright 회귀 검사를 사용한다.

### 구현 경계

- `app/shell/AppSidebar.tsx`: 축약 메뉴와 모바일 메뉴.
- `features/result-overview/`: 첫 화면의 독립 결과 대시보드. `PortfolioDashboard.tsx`가 기존 운영 화면과의 전환을 조립한다.
- `features/request-workspace/`: 의뢰 문맥, 공통 여정, 결과 요약.
- `features/requests/FocusedRequestOverview.tsx`: 선택 의뢰의 현재 작업과 접힌 이력.
- `app/routing/useWorkspaceContextRestore.ts`: URL 식별자의 부모·자식 관계와 Run/페이지 검증.
- `features/results/`, `features/reports/`: Run 전환, snapshot과 보고서 비동기 문맥 보호.
- `features/data/`, `features/workbench/`: 현재 선택을 이어받는 접수·실행·등록.

URL query는 `project`, `request`, `loadCase`, `run`, `view`, `page`를 사용한다. 임시 snapshot 화면 ID는 영속 페이지 ID로 기록하지 않는다. URL만으로 데이터 생성, 결과 등록 또는 snapshot materialize를 수행하지 않는다. 영속 분석 페이지는 선택한 Run을 복원한다. 미지정/고정 snapshot 화면(`view=custom`, page 없음)은 기존 최신 결과 계약을 따르며 Run 선택기를 제공하지 않는다. 해당 화면에서 Run까지 지정한 링크는 거절하고, 새로고침해도 임의의 도메인 분석 화면으로 바꾸지 않는다.

### 결과 대시보드 콘셉트 비교

- 첫 화면의 독립 경로와 제목, 프로젝트·의뢰 검색을 반영했다.
- 핵심 집계 3개를 클릭 가능한 필터로 연결하고 최신 Run 기준을 표시했다.
- 최근 결과는 왼쪽 목록, 유형별 판정과 대기 항목은 오른쪽에 배치했다.
- 목록은 5건씩 표시하며 실제 판정·완료일과 결과 검토·의뢰 이동을 연결했다.
- 콘셉트의 예시 수치와 유형명은 실제 API 값으로 교체했다. 설명 카드 대신 실제 대기 항목을 표시한다.
- 모바일에서는 메뉴를 접고 필터·카드·목록을 한 열로 표시하며, 기존 글자 크기와 수동 테마 선택을 유지한다.
