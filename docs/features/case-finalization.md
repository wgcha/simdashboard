# Working Case 최종확정

상태: 구현 완료, 격리된 Windows 환경에서 검증(2026-10-02). 검사 결과와 운영 검증 범위는 [구현 계획](../plans/folder-schema-working-final-implementation.md)에 기록한다.

Case 결과 화면의 해석 Case 선택기 옆 **최종확정**에서 사용자가 best Case와 수집 버전을 선택한다. 미리보기에서 상대 경로·파일 수·누락·목적지를 확인하고 **확정하고 파일 복사**를 누른다. 수집본이 없는 Case는 폴더 구조를 조회할 수 있지만 최종확정은 실행할 수 없다.

확정 Folder Schema의 Working Case와 Scene이 복사 범위다. Scene 직속 `.rad`·`.inc` 및 유효한 include 참조는 의뢰의 `Final/CAE/<Case>/<확정 ID>/`에, 선택 수집본의 결과·미디어와 확정 Scene의 PDF/PPT/XLSX 보고서는 `Final/Reports/<Case>/<확정 ID>/`에 저장한다. Case 내부 하중경우·Run·옵션·Scene 상대 경로를 유지한다. CAD는 복사 대상에 포함하지 않는다.

수집 결과는 선택 capture의 해시와 일치해야 한다. 입력과 보고서는 현재 확정 Scene에서 가져오는 파일임을 미리보기의 `source_basis`로 구분하고 미리보기 시점의 해시를 고정한다. 현재 위치와 호환되지 않는 수집 Scene은 제외하며 포함된 파일이 이후 변경되면 확정을 차단한다. RAD·보고서가 없는 경우 누락을 표시한다. INC만 있는 예제도 확정할 수 있다.

수집 후 새로 추가된 Scene의 입력·보고서를 과거 수집본에 끼워 넣지 않는다. 파일은 한 개당 32 MiB, 확정 전체 256 MiB·500개까지 허용한다. 결과 형식은 CSV/JSON·이미지·동영상, 보고서는 PDF/PPT/PPTX/XLSX를 지원한다.

기존 Final과 Working 원본은 덮어쓰거나 삭제하지 않는다. 의뢰별 운영체제 파일 잠금과 `Final/.finalizations/<확정 ID>/`의 계획·완료 기록으로 동시 실행과 중복 요청을 처리한다. 모든 목적 파일의 복사·해시 검증이 완료된 기록만 확정 상태에 표시하며 부분 실패는 같은 확정 ID로 재시도한다. 손상된 목적 파일을 정상 완료로 표시하지 않는다.

현재 폴더 구조 문맥에서도 이미 수집된 Case의 최종확정 이력을 표시한다. 확정된 수집본 ID·확정 ID·시각을 보여 주며 선택한 수집본과 다르면 구분한다. 재시도는 선택 수집본과 일치하는 요청에만 제공한다.

계획과 완료 기록은 기존 `AUTH_SECRET_KEY`로 용도를 분리한 HMAC 서명을 검증한다. 키를 로그나 SPDM에 저장하지 않는다. 배포·업데이트에서 기존 인증 키를 보존해야 과거 기록을 계속 검증할 수 있다. 키가 없으면 새 확정을 차단하고, 키 교체·기록 변조·목적 파일 손상으로 검증할 수 없는 기록은 파일을 보존한 채 확인 필요 상태로 표시한다. 서명 없는 기록을 자동으로 신뢰하지 않는다.

미리보기·확정은 해당 의뢰의 `RESULT_IMPORT`, 상태 조회는 `PROJECT_DATA_VIEW` 권한이 필요하다. 파일 경계·Windows 경로·링크/재분석 지점과 파일 개수·크기 제한을 검사한다. 새 DB migration이나 실행 의존성은 추가하지 않는다. Final은 일반 Case 조회·결과 등록·수집 대상에서 제외한다.

이력 JSON은 열린 파일 기준 4 MiB까지 읽고 서명을 검증한다. 지나치게 크거나 깊은 JSON은 검증되지 않은 이력으로 분리한다. 상태 조회의 전체 메타데이터 64 MiB·출력 검증 1 GiB·탐색 항목 1,000개 제한을 넘으면 일부 이력을 정상 최신본으로 표시하지 않고 명시적 오류를 반환한다. 기존 파일은 보존한다.
