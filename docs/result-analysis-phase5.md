# 결과 분석 5단계 — 대표 흐름과 추천 배치 미리보기

상태: 구현 및 기능 검증 완료 · 2026-09-12

## 사용 목적

기존 결과 위젯을 요약 → 분석 근거 → 영상 순서로 읽도록 배치를 제안한다. 새 위젯이나 고정 템플릿을 추가하지 않는다. 현재 위젯 종류를 기준으로 읽는 순서를 제안하며, 결과의 중요도·근본 원인·최적 설계를 자동 판단하지 않는다.

## 대표 업무별 확인

| 대표 화면 | 확인할 사용 흐름 | 배치 판단 |
|---|---|---|
| Open Cell/낙하 결과 | 판정·조건 확인 → 응력 위치/시간·표 → 영상 → 검토 의견 | 요약이 지도보다 아래에 있으면 먼저 읽도록 제안. 영상은 분석 근거 아래에 유지 |
| Chassis Rear 영구변형 | 요약 → 위치도와 비교 그래프 → 상세 표·의견 | 기존 요약 우선 배치를 존중하고 불필요한 재배치를 피함 |
| Run 비교 | 조건 차이 → 결과·기준 여유 → 시계열 → 검토 | 하나의 비교 위젯 안에서 완성된 흐름은 유지. 단일 위젯은 재배치할 이유가 없음 |

위 흐름은 제공된 예제와 제품 계약을 기준으로 검증한다. 실제 사용자의 분석 시간 단축이나 추천 선호도를 확인한 사용자 조사로 표현하지 않는다.

## 화면과 동작

1. 기존 **대시보드 편집** 진입 후 **추천 배치 미리보기**를 연다.
2. 현재 배치와 추천 배치를 위젯 제목이 있는 도식으로 비교한다. 실제 그래프·영상 컴포넌트를 중복 실행하지 않는다.
3. 닫기/Escape는 편집안을 변경하지 않는다.
4. **편집안에 적용**은 현재 브라우저 편집안의 x/y 좌표만 변경한다. 기존 **레이아웃 저장**을 눌러야 서버에 저장된다.
5. 적용 이후 다른 수정이 없는 동안 **적용 전 배치로** 복원할 수 있다. 이후 수동 이동/설정 변경이 있으면 해당 변경을 덮어쓰지 않는다. 기존 전체 편집 취소는 편집 시작 전으로 돌아간다.

## 유지할 계약

- 위젯 ID·타입·제목·배열 순서·크기(w/h)·설정·데이터 연결·보고서 포함 설정을 보존한다. 영상 가로/세로 및 재생 데이터도 그대로다.
- 추천 정책은 12열 좌표를 계산한다. 경계 밖/겹침/중복 ID/잘못된 크기는 검증하고 RGL의 기존 세로 압축 후에도 제안과 실제 배치가 일치해야 한다.
- 추천 적용과 복원은 기존 레이아웃 편집 경로를 사용한다. 새 API/DB 저장 계약을 만들지 않는다.
- 조회자와 편집하지 않은 화면에는 적용 제어를 노출하지 않는다. 고정 snapshot 원본을 변경하지 않으며, 기존 편집 진입의 별도 페이지 생성 경로가 선행된 경우에만 해당 편집 페이지에 적용한다.
- 의뢰·하중 경우·페이지·편집 세션이 바뀌면 이전 추천과 복원 기록을 폐기한다. 미리보기 중 원본 편집안이 달라지면 오래된 제안을 적용하지 않는다.
- 추천할 변경이 없는 화면·단일/빈 위젯은 이유를 안내하고 불필요한 저장을 유도하지 않는다.
- 기존 위젯 크기를 유지한 채 세로 압축 후 읽는 순서가 성립하지 않으면 적용을 비활성화하고 이유를 안내한다. 사용자가 기존 편집 기능으로 크기와 배치를 조절할 수 있다.
- 안전한 정수 좌표를 요구하고 y 10,000·높이 1,000행을 넘는 입력은 자동 배치에서 제외하여 비정상 배치의 계산을 제한한다.

## 검증 계획

- 순수 정책: 기존 필드 보존, 5×4 설정, 경계/겹침, 잘못된 입력, 같은 입력의 결정성, 재적용 안정성 및 RGL 압축 일치.
- 브라우저: 닫기 무변경, 적용 전 서버 미저장, 복원, 설정 수정 후 복원 차단, 명시적 저장·재조회·새로고침, 조회 권한 및 단일 위젯, 데스크톱/모바일 도식과 키보드.
- 기존 영상 배치와 4단계 비교 기능 회귀.
- Browser plugin not available: 기존 Playwright의 격리 서버로 확인한다. QA 산출물은 저장소 밖 Codex visualization 작업 폴더 `phase5-qa`에 보관한다.

## 구현 기록

- Terra: 순수 배치 정책과 자체 검사. Luna: 현재/추천 도식, 편집안 적용·복원, 기존 grid 분리. Sol: RGL 콜백·권한·snapshot·복원 문맥 검수. 루트: 대표 사례 설계, 통합/브라우저 검사와 화면 보정.
- 설치되어 있는 react-grid-layout의 세로 압축 함수를 재사용하여 미리보기와 실제 적용의 좌표를 맞춘다. 별도 배치 라이브러리나 서버 API를 추가하지 않았다.
- 추천 정책은 요약을 다른 위젯보다 앞에, 영상을 모든 비영상 위젯 뒤에 배치한다. Chassis의 표/의견 병렬 배치처럼 이미 조건을 만족하는 구성은 유지한다.
- 복원 상태는 위젯 전체 정보와 페이지·하중 경우 문맥을 비교한다. 현재 화면의 편집권한/편집상태 및 제안 시점의 정보가 일치할 때만 적용한다.
- 검수에서 RGL 콜백의 추가 필드 때문에 복원 상태가 즉시 소멸할 수 있던 비교와 첫 수동 이동을 건너뛸 수 있던 콜백 억제를 제거했다. 기존 콜백을 전달하며 현재 위젯 정보로 복원 가능 여부를 판단한다.
- 시각 검사 후 투명해지던 dialog 배경을 기존 테마 색상으로 연결하고, 위젯 내부 타입명·중복 요약을 제거했다. 긴 위젯 제목은 두 줄로 표시하고 작은 화면은 도식을 세로로 배치한다.
- 최초 테스트 수집의 괄호 오류를 수정했다. 저장 검사에서는 기존 저장 경로의 빈 settings 정규화를 확인하여 실제 저장된 기본값을 기준으로 비교하며, 그 외 크기·제목·타입·설정·배열 순서를 검증한다.

## 최종 검증 결과

- 신규 브라우저 3개 최종 통과(1.1분): 닫기/Escape/초점 복귀, 미저장 적용·복원, 명시적 저장·새로고침, 제목/타입/크기/설정 보존과 영상 5×4, 추가 설정 수정 후 복원 차단, 모바일 조작, 조회자 제어 숨김, 기존 Chassis 및 단일 Run 비교 유지.
- 회귀 6개 통과: 4단계 기준 여유/비교 축 4개, 기존 영상 배치 1개, 의뢰 유형의 결과 snapshot 1개. Snapshot 조회 시 dashboard materialize 호출이 없고 추천 제어도 나타나지 않음을 확인했다. Snapshot 편집 materialize 정확히 1회 호출은 이번 새 추천 테스트의 직접 검증 범위가 아니다.
- 순수 정책 검사 통과: RGL 압축과 좌표 일치, 겹침/경계/안전 정수/중복 ID, 모든 비영상 뒤 영상, 요약 우선, 기존 설정 참조·배열 순서, 동일 추천 재적용 안정성과 기존 좋은 배치 유지.
- 타입 포함 빌드와 프런트엔드 아키텍처 검사(164 source files) 통과. 기존 500 kB 번들 경고는 유지된다. 서버 코드/DB 계약 변경 없음.
- Chromium 격리 예제 서버 15173/API 18000, 데스크톱 1505×1045·모바일 390×844. 실제 캡처에서 불투명 배경, 제목 가독성, 현재/추천 배치 비교, 내부 스크롤, 고정된 닫기·적용 버튼을 확인했다.
- 전체 1~5단계 구현과 정의한 기능 검증을 완료했다. 실제 업무 데이터의 추가 사용자 피드백과 영상/그래프의 시간 매핑 자동 연동은 별도 후속 범위다.
