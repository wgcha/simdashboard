3.2 수치 읽기
사용환경에서 JSON과 CSV는 동일 결과의 대체 형식이다. 동일 해석·방향·조건의 JSON 우선, JSON이 없을 때만 CSV 탐색을 적용한다. 둘 다 존재하면 JSON을 선택하고 CSV는 대체 원본으로 연결하며 중복 관측값을 만들지 않는다. CSV가 다른 방향/조건의 파일이면 대체 후보가 아니다.

해석 항목	JSON 원본 키	기본 차원	표시
Settle	Set Tilt Angle @ Settle (deg)	공통	안착 Tilt 각도
Wobble	Wobble Disp. (mm)	front/back, center 원문 보존	전·후 변위
Horizontal_Force_Angle	Set Tilt Angle Difference (deg)	front/back	전·후 대체각도
Slope_Angle	Slope Angle (deg), OK/NG	front/back	전·후 각도 및 판정
Slope_Angle_360	OK/NG	front/back	전·후 판정
Settle 공통값을 전·후 두 값으로 복제하지 않는다. 360 결과의 각도는 샘플에 있지만 설명 엑셀에서 지정한 필수 항목은 OK/NG다. 각도 추가 노출은 매핑 검토 대상으로 남긴다. 공백·점·괄호가 있는 JSON 키를 정확한 경로로 식별한다. 음수와 0은 보존하고 결측을 0으로 바꾸지 않는다. 승인 없는 절댓값 변환/판정 계산을 하지 않는다.

오류 처리 제안: JSON 존재 시 문법/필드 오류는 오류로 표시한다. 이를 파일 부재로 간주해 CSV로 조용히 대체하지 않는다. 명시적 CSV 대체 선택은 별도 검토 항목이다. result2, bushing은 형식만 다른 결과가 아니므로 기본 결과와 자동 병합하지 않는다.

위 차이를 손상으로 단정하지 않는다. 추출 영역, 처리 시점, 요약 생성 방식 차이를 확인할 필요가 있다. 요약값을 상세 최대값으로 덮어쓰거나 노드 위치를 임의 결합하지 않는다.
대표 이미지(DAMP-13/Scene08/C23) 범례 Max는 107.0이고 CSV 네 라인 최대는 109.1이다. 이미지 프레임/평균화/추출 범위가 동일하다는 근거가 없어 두 값을 동등한 결과로 취급하지 않는다.
대표 JPG 한 장을 육안 확인했다. 여섯 장 모두의 범례·프레임을 검증한 것은 아니다.
6. 노드·라인·위치의 데이터 구조 개선안
6.1 네 라인과 코너를 보존하는 형태
사용자 정의: 바깥쪽부터 Line 1 → Line 2 → Line 3 → Line 4. CSV의 Layer_14, L1L4는 이 라인 번호로 연결한다. 두께 적층/시간 단계로 취급하지 않는다.

데이터	차원/값

코너 관측값	Scene, Component, CORNER, TOP_LH/TOP_RH/BOT_LH/BOT_RH, node_id, stress_value

원본 코너 요약	Scene, Component, 코너, reported_max
파생 최대	Scene, Component, 집계범위, computed_max, 발생 위치/라인/샘플 목록, 원본 근거
이미지	Scene, Component, 결과종류, Mid 등 표기, 이미지 자산 ID, 범례/시간/프레임 메타데이터의 확인 상태
LAYER_ALIGN은 한 행의 Node_id/좌표 옆에 네 라인 값이 정렬되어 있다. 네 라인 각각의 실제 Node_id가 동일하다는 증거는 없다. 우선 alignment_node_id로 저장하고 L2~L4 실제 노드 번호로 복제하지 않는다. CORNER_DATA에는 라인 번호나 좌표가 없으므로 행 순서/노드번호로 임의 라인을 부여하지 않는다.

LH → left, RH → right, TOP → top, BOT → bottom; 코너는 네 방향 조합으로 표시한다. 원문은 유지한다. 카메라 시점에 따른 좌우 반전을 가정하지 않는다. Scene의 Corner235(낙하 접촉 꼭짓점 코드)와 결과 위치 TOP_LH(Component 응력 위치)는 서로 다른 의미다.

6.2 최대값의 범위와 추적
원본 요약 최대와 상세 추출값 최대를 별도 지표로 제안한다.

상세 추출값 최대: 선택한 Scene/Component의 유효 SIDE 라인 값과 CORNER 노드 값 중 최댓값. 위치·라인·해당 원본 행까지 추적한다.
원본 요약 최대: MAX_RESULT와 CORNER_MAX_RESULT의 지정 범위 최댓값. 상세와 맞지 않으면 불일치 상태를 함께 표시한다.
이미지 전체 최대: 범례에 표시된 별도 값. 자동 OCR을 수치 집계의 기본 입력으로 사용하지 않는다.
기본 그래프를 1번으로 둘지 2번으로 둘지는 검토 후 확정한다. 확정 전 UI 설계에는 집계 기준 선택과 상태를 명시한다. 둘을 섞어 최대값을 만들지 않는다. 네 라인·코너의 최대를 Component 전체 영역의 최대라고 부르지 않고 **'추출 영역 최대응력'**으로 표시한다.

동률 최대 위치는 모두 보존한다. 숫자 반올림 전 비교하고 표시 자릿수는 별도 적용한다. 누락·비수치·단위 불명·요약 불일치·일부 위치 누락은 각각 구분한다. 일부 자료로 산출한 최대는 '부분 데이터' 상태다. L1만 선택하면 L1 범위만 비교하고 라인 번호가 없는 코너를 자동 포함하지 않는다. 코너 포함 여부를 따로 선택한다.

확인용 상세 추출 최대 예시(단위 미확인, 기본 판정값으로 확정한 것이 아님):

7. 유통환경 대시보드와 위젯 개선안
7.1 화면 선택 문맥
프로젝트 → 의뢰 → Simulation Case → 하중경우 → run #: 원본폴더명 → INDIVIDUAL/CUMULATIVE → Component

한 번 선택한 문맥을 모든 이미지·표·그래프에 공통 적용한다. 여기에 결과 수집 버전, 응력종류/단위, 라인 범위, 코너 포함 여부, 집계 기준을 표시한다. 다른 Run/방식의 데이터를 자동 혼합하지 않는다. Case 비교는 설계변경 비교, Run 비교는 같은 설계의 반복해석 비교로 구분한다.

7.2 Scene 컨투어 그리드
20개 Scene이면 20개 Scene 카드를 넓은 화면에서 5열×4행으로 보는 안. 화면 크기에 따라 열 수를 줄인다. 20으로 고정하지 않고 실제/선언된 Scene 수에 맞춘다.
카드 하나는 해당 Scene의 선택 Component의 컨투어 한 장. 현재 샘플의 C23/C24는 선택 전환하거나 비교 모드에서 나란히 표시한다. 20 Scene을 서로 다른 20 Component라고 해석하지 않는다.
카드 제목: 순번 / Scene 번호 / 낙하·Clamp 조건 / 반복차수. 하단: 집계 범위 최대값, 위치·라인, 자료 상태.
이미지 클릭: 원본 비율로 확대, 범례 확인, 같은 Scene 상세값/네 라인 그래프 열기.
원본 JPEG의 색상 범례를 유지한다. 씬별 자동 범례가 다르면 색만으로 응력 크기를 비교하지 않도록 범례 차이를 표시한다. 통일 범례는 원본 재출력/별도 지원이 필요한 확장이다.
선언된 20 Scene 중 3개만 있으면 3/20과 결측 카드를 표시한다. 선언 목록이 없으면 '발견 3개'로 표시하고 누락 17개를 임의 생성하지 않는다.
이미지 지연 로딩/썸네일로 화면 부하를 줄이고 파일 접근 권한은 기존 자산 경로를 재사용한다.
7.3 최고응력–Scene 비교
X축: 확정된 실행 순서로 정렬한 순번 / Scene번호 / 회차; Y축: 선택 집계범위 최대응력.
막대 / 점 / 점과 선 전환. Component별 계열 또는 선택 Case/Run의 비교 계열 제공.
툴팁: 원문 Scene, 값·단위, SIDE/CORNER 위치, 라인, 원본 요약/상세 여부, 원본 근거.
점/막대 클릭 시 같은 Scene 카드와 위치 상세를 강조한다.
점과 선은 Scene 표시 순서를 연결한 것이며 시간 이력/물리적 연속성/사이값 보간을 뜻하지 않는다. 누적 모드의 순서도 실제 시간값과 구분한다. 순서가 미확인인 샘플은 원문 식별자를 표시하고 실행순서 미확인을 명시하며 점과 선 연결을 보류한다. 누락점은 0으로 채우거나 연결하지 않는다.
7.4 최고응력 발생 위치–Scene 비교
위치명은 범주형이므로 top/right/corner를 숫자 높이로 바꾼 막대는 피한다. 다음 조합을 제안한다.

위치 맵: X축 Scene, Y축 left/right/top/bottom 및 네 corner 이름, 최고값 발생 위치에 점. 점 색/크기로 응력 크기를 표시하고 정확한 값은 툴팁 제공. 동률이면 여러 점.
위치별 응력 비교: 각 Scene의 8개 위치 최대를 묶은 막대 또는 선택 위치의 점과 선 그래프. 최대 위치를 색/표식으로 강조.
필요 시 Scene×위치 열지도 추가. 범주형 위치의 변화 자체를 연속선으로 연결하지 않는다.
7.5 Scene 상세: 네 라인 분포
Scene/Component/변 선택 → L1~L4 네 곡선 표시.
X축은 원본 ref_coord, Y축 응력. 좌표 단위 미확인 시 단위를 추정하지 않고 표시한다.
Node_id를 임의 거리축으로 사용하지 않는다. ref_coord가 비단조/중복이면 명시적 처리 규칙을 확정하고 원본 행 순서도 보존한다.
최대 위치 강조와 원본 행 확인. 코너는 별도 노드 목록·점 그래프를 제공하며 좌표/라인 없는 값에 거리를 만들어 넣지 않는다.

A. 공통 Scene 축·Case 비교 계약
그래프 X축의 Scene number는 표준 Scene 폴더 맨 앞 숫자다. 3_Face_Drop_Scene03_Face6_1st는 3, 20_Face_Drop_Scene12_Face3는 20이다. 내부 Scene12를 X축 12로 대신 쓰지 않는다. scene_sequence_number와 scenario_number를 별도 저장한다.
순번 숫자로 정렬한다. Case별로 같은 순번에 다른 하중 자세가 있을 수 있으므로 비교 정렬은 운송 프로파일(Parcel/LTL 등), 하중경우, 자세/접촉코드, 회차의 대응까지 검증한다. Parcel/LTL의 Scene 목록·개수는 서로 다를 수 있고 20/30개를 고정하지 않는다. 프로파일은 확인된 메타데이터/명시 선택으로만 지정한다.
기존 샘플 DAMP-2 접두사의 숫자는 표준 선행 숫자 문법과 다르다. 별칭/매핑 확인 전 임의로 2라고 확정하지 않는다. 이 예외가 표준 20_...의 순번 규칙을 미확정으로 되돌리지는 않는다.
범례의 해석 Case는 Simulation Case다. 각 비교 Case에 하중경우·사용자 Run·Mode·capture·Component/물리 역할을 명시적으로 선택한다. 같은 이름의 Run이나 최신 파일을 조용히 고르지 않는다. 이전 Run 비교는 Case 비교와 별도 기능이다.
공통 비교축에는 대응 가능한 Scene만 같은 위치에 놓고 미대응/누락은 빈칸과 사유로 남긴다. 문자열 순번/배열 인덱스만으로 Case 간 서로 다른 Scene을 합치지 않는다.
Case마다 고정 색/패턴을 사용하고 네 엣지 패널과 두 비교표까지 유지한다. Scene 설명표는 순번 → Face/Edge/Corner·접촉코드·회차를 보여준다. Case 간 목록이 다르면 해당 프로파일/Case 문맥을 표시한다.
B. 결과 요약: Open Cell 엣지 맵과 Scene 최대응력
공통 선택: 의뢰 / 비교 Case / 하중경우 / Case별 Run·Mode·capture / Component
표시 엣지: 상단 [ ] 하단 [ ] 좌측 [ ] 우측 [ ]
[ Open Cell 직사각형 엣지 맵 + 선택 Scene 정보 ] [ Scene별 엣지 최대응력 비교 그래프 ]
우측 그래프: X축=선행 Scene 순번, Y축=Stress. Case별 계열의 막대/점/점과 선과 확대 기능. 기본 요약 대상은 **선택한 엣지의 최대값(envelope)**이며 코너를 포함한 기존 '추출 영역 최대'와 다른 지표다. 선택 엣지가 모두 해제되면 0 대신 선택 없음 표시.
그래프의 막대/점을 클릭하면 해당 Case + Run + Mode + capture + Scene + Component + 집계기준을 선택하고 좌측 맵을 즉시 갱신한다. Case가 두 개이면 같은 Scene의 서로 다른 막대가 서로 다른 Case를 선택한다.
좌측 맵에는 top/bottom/left/right별 최대값·단위를 실제 테두리 위치에 표시하고 선택/최대 엣지를 강조한다. 인치·하중 자세·날짜·제조사·제품모델명은 확인된 메타데이터가 있을 때만 표시한다.
이 직사각형 엣지 맵은 기존 'Scene×발생위치 범주 맵'과 별도 위젯이다. 정확한 좌표가 없으면 특정 노드 위치를 테두리 위의 임의 점으로 그리지 않는다. 좌표계/기하 대응이 확인된 경우에만 실제 피크 위치를 추가한다.
평가 기준이 없으면 기준선/합격 색을 표시하지 않고 미판정으로 둔다. 그래프 집계와 맵 값은 같은 엣지·라인 범위/원본요약 또는 상세 기준을 사용한다. 선택 범위 중 자료 누락이 있으면 최대값이 있어도 부분 결과 표시.
C. 상세 결과 1: 네 엣지 패널
상단: Scene 번호 설명표, 비교 Case 선택/전체 선택·해제, 패널 크기, Case 순서·Scene 순서·그룹 표시 설정.
본문: Left / Right / Top / Bottom 네 패널을 기본 2×2 배치. 각각 X축=Scene 순번, Y축=해당 엣지 응력, 범례=Simulation Case. 예시 30 Scene도 대응하며 화면 폭에 따라 스크롤/확대를 제공한다.
정렬은 Scene별 Case 막대 교차 표시 또는 Case별 묶음 표시를 지원하는 안으로 구체화한다. 화면 정렬은 표현 순서만 바꾸며 CUMULATIVE 원본 실행 순서/식별자를 수정하지 않는다.
컨셉의 Upper/Lower 및 U/L은 추가 측정 구분이지만 현재 CSV와의 대응은 미확인이다. C23/C24나 L1/L4를 Upper/Lower라고 단정하지 않는다. 명시 매핑이 제공되면 Case와 별도 surface/측정 구분 차원으로 표현한다.
응력값 라벨, 방향/라인/표면 구분, 기준선은 근거가 있는 데이터만 표시한다. 패널 막대 클릭도 B와 같은 문맥으로 엣지 맵/Scene 상세를 갱신한다.
D. 상세 결과 2: Case×Scene 최종 프레임 컨투어 비교
행: Scene 순번 + 자세/충돌 설명 | Scale bar | Case A | Case B | Case C ...
각 교차 셀: 해당 Case의 선택 Run/Mode/Scene/Cell 컨투어 + 값/상태
상단 Case 헤더: 설계변경 설명·참조 모델 이미지(있는 경우)
행/열 바꾸기는 실제 전치 기능이다. 전치 후 행=Case, 열=Scene으로 바뀌되 선택·확대·수치/이미지 연결은 동일한 셀 ID를 유지한다. 단순 카드 정렬과 구분한다.
첫 열에는 낙하 자세(Face/Edge/Corner, 접촉 코드, 1차/2차 충돌 설명)와 관련 그림을 제공한다. 자료 없는 자세도는 임의 생성하지 않고 텍스트/없음 상태로 둔다.
사용자 제목의 Cell Tmax 마지막 Frame Contour는 선택 Scene의 최종 프레임 컨투어 요구로 기록한다. Tmax가 물리량/시각/최대 발생 시점 중 무엇인지 별도 확인이 필요하며 '응력 최대 발생 프레임'으로 자동 대체하지 않는다.
자산에는 frame_role, frame_index, time_value, time_unit, 확인 근거를 보존한다. 파일명 Max_Stress만으로 FINAL_FRAME을 부여하지 않는다. 최종 프레임 검증 전에는 프레임 미확인, 자료가 없으면 없음 표시.
Scale bar는 물리량·단위·범위·평균화·표면·시점을 비교할 수 있을 때만 공통으로 표시한다. 서로 다른 원본 이미지의 컬러 범위를 재색칠하지 않는다. 미확인이면 셀별 원본 범례와 차이 안내를 보존한다.
셀 밑의 Left Max 같은 수치는 대응하는 엣지/집계 범위를 명시한다. 시간 집계 범위가 다른 CSV 최대를 최종 프레임 이미지의 측정값으로 오인시키지 않는다. 이미지와 수치의 시간 정합성 미확인도 표시한다.
컨투어 이미지 클릭 확대, 긴 Case/Scene 이름 툴팁, 누락 셀 유지. 데이터 없음을 0 또는 인접 Case 이미지로 채우지 않는다.
E. 상세 결과 3: 선택 Scene의 Cell/Cushion/Box 거동
좌측 Scene 선택과 자세/충돌 정보. 우측은 열=비교 Simulation Case, 행=Cell / Cushion / Box로 배치한다.
각 셀은 해당 물리 대상 역할의 이미지 또는 영상이다. C23/C24를 Cell/Cushion/Box에 임의 대응하지 않고 subject_role과 Component 원문 ID를 별도 관리한다.
정적 이미지가 있으면 정적으로 표시한다. 영상이 있으면 재생·일시정지·확대를 제공하는 안이다. Case 간 동기 재생은 시간 기준/시작점이 정합한 경우에만 허용하는 후속 정책이며, 같은 프레임 번호라는 이유로 동기라고 주장하지 않는다.
Cushion/Box 자료는 조사한 CSV/JPG 샘플에서 확인되지 않았다. 슬롯은 요구사항으로 설계하되 실제 매핑/영상 기능을 검증했다고 기록하지 않는다. 미제공 상태를 유지한다.

8. 폴더 인식·파일 연결·오류 처리
저장소 루트와 프로젝트 경계를 확인하고 상대 경로 목록을 조사한다. 링크를 따라 허용 루트 밖으로 확장하지 않는다.
선택한 환경별 규칙으로 폴더 역할 후보를 만든다. 단순 절대 깊이만 보지 않고 부모 역할+토큰+표준 경로를 함께 검증한다.
사용환경은 Case 아래 해석/방향을, 유통환경은 Case/하중경우/Run/방식/Scene을 각각 연결한다.
수치/영상/이미지/모델/로그 역할을 분류한다. 모르는 파일도 목록에 남기되 실행하거나 임의 수치 파싱하지 않는다.
내용 헤더·필수 필드와 파일명 메타데이터를 대조한다. 잘못된 Component/Scene 이름 충돌은 검토 대상으로 둔다.
수치와 미디어를 문맥·Component·결과종류·수집 버전으로 연결한다. 같은 폴더나 파일 수정시각만으로 다른 결과를 묶지 않는다.
파일이 쓰이는 중이면 안정화 후 재검증한다. 해시와 규칙 버전으로 중복 등록을 방지하되 서로 다른 사용자 Run을 파일 내용이 같다는 이유로 합치지 않는다.
FINAL/보고서/템플릿/CAD/기본 모델은 별도 역할이다. 작업 결과와 최종 복사본을 중복 집계하지 않는다.
데이터 상태(정상/없음/읽기 오류/모호/부분/불일치)와 평가 판정(OK/NG/기준 없음)을 분리한다. 운영 재검색은 원본 이동·수정·DB reset·서비스 조작을 수행하는 절차가 아니다.

그리드/종합표/비교/상세 위젯 구성을 검토한다.
승인 후 구현 모듈·API·저장 계약·검증 계획을 상세 지침서로 보강한다. 문서 승인은 코드 수정 승인과 별개다.
향후 구현 수락 조건: 사용환경 JSON/CSV 중복 방지와 실제 CSV 대체, 오류 JSON 구분, 다섯 항목 한 Case 조회, 별도 Run/모드 격리, 중복 Scene 번호/회차 보존, 3개 샘플과 20 Scene 합성 자료 그리드, C23/C24 전환, 네 라인 순서, 좌우/코너 구분, 요약 불일치, 동률·결측·부분결과, 이미지/수치 문맥 일치, 과거 버전 조회, 비교 가능한 단위/범위만 비교.
