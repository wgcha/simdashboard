# 사용환경 결과 파일·JSON 검수 개선계획

작성: 2026-09-21. 상태: 구현 완료(사내 원본 적용 검증 전). 최신 사용자 요청을 우선한다. 기존 좌측 영상 그리드·중앙 다섯 평가 종합 표를 유지하며 데스크톱만 대상으로 한다. 사용자의 후속 구현 지시에 따라 아래 계획을 적용했으며 원본 파일은 변경하지 않는다.

## 1. 확인한 근거와 원인 구분

- 기준: [상세.md 3.2](상세.md), [GitHub #30 사용Json](https://github.com/wgcha/simdashboard/issues/30). 이슈는 파일명·키·값을 정리한 표이며 완전한 원본 JSON 파일이나 중첩 구조는 제공하지 않는다. 댓글은 없다.
- Settle 예시 파일은 `75R9J_Set0907_Stand0907_Force_spg0.1_settle_result.json`, 키는 `Set Tilt Angle @ Settle (deg)`, 값은 `1.18`이다. 앞부분은 프로젝트/모델/조건에 따라 달라지므로 고정하지 않는다.
- 현재 `dashboard_capture._usage_identity`는 해당 접미사를 지원하고 `dashboard_queries.USAGE_KEYS`도 위 키를 사용한다. 이 이름과 최상위 키로 만든 합성 JSON은 현재 순수 함수에서 `1.18 / READY`로 조회됨을 확인했다. 접두사 때문에 읽지 못한다고 단정할 수 없다.
- 실제 결함 경로: `domains/dashboard/parser.py::_pick_usage`는 평가 폴더의 모든 JSON/CSV를 후보로 넣는다. 접미사가 맞지 않는 파일도 남고 `_usage_payload`는 식별 실패를 common으로 처리한다. 같은 Settle 폴더에 `{}`인 `settings.json`을 추가한 합성 예에서는 `AMBIGUOUS / null`이 재현된다. 실제 사내 자료의 실패 원인은 파일 선택·키 경로·값 형식·기존 capture를 함께 확인해야 확정할 수 있다.
- `dashboard_queries.py::USAGE_KEYS`가 일부 평가명을 한국어로 번역한다. 프런트는 이 이름과 원시 상태 코드·quality_issues를 노출한다.
- 미지원 확장자는 이미 본문을 파싱하지 않고 `UNPROCESSED_FILE` 진단에 기록된다. `SOURCE_PARSE_ERROR`는 선택된 JSON/CSV의 문법·형식 오류와 구분해야 한다. 목록을 숨기는 것만으로 수치 결측 원인이 해결되지는 않는다.

## 2. 결과 화면: 원문 평가와 값 중심

- 좌측 영상 그리드, 중앙 종합 표, 기존 그래프 배치를 유지한다. 새 차트·새 라이브러리를 추가하지 않는다.
- 평가명은 `Settle`, `Wobble`, `Horizontal_Force_Angle`, `Slope_Angle`, `Slope_Angle_360`을 그대로 표시한다. 측정 항목 이름도 아래 JSON 원문 키를 사용한다. 한국어 별칭으로 대체하지 않는다.
- 표의 평가명 아래 원문 측정 키를 보조 텍스트로 표시하고, 그래프 제목·툴팁·비교에도 같은 메타데이터를 사용한다. 조작 버튼과 일반 안내 문구는 한국어를 유지한다.
- `SOURCE_PARSE_ERROR`, 미지원 확장자 목록, 원시 경로 오류 패널은 결과 대시보드에서 제거한다. 과거 capture의 진단도 같은 표시 정책을 적용하되 저장된 진단 자체는 삭제하지 않는다.
- 읽지 못한 선택 수치는 `—`와 짧은 `검수 필요`, 실제 자료가 없는 항목은 `자료 없음`으로 구분한다. 잘못된 값을 정상값·0으로 표시하거나 다른 capture 값으로 채우지 않는다. 관리자에게만 관련 등록 이력의 `파일·값 검수`로 이동하는 링크를 제공한다.
- 진단 패널의 이동은 이번 사용환경 흐름에 먼저 적용한다. 유통환경의 CSV 결과 읽기·오류 계약을 일괄 변경하지 않는다.
- 과거 capture에 원문 키 메타데이터가 없으면 표준 평가→키 사전으로 항목 이름만 표시한다. 해당 키가 과거 원본에 실제 존재했다고 주장하거나 저장 payload를 소급 변경하지 않는다. 새 사용자 매핑이 있는 결과는 해당 수집 버전의 확정 키를 표시한다.

## 3. 기본 파일 선택 계약

기본 선택은 수치용 JSON + 현재 지원하는 영상·이미지다. JSON은 사용자 요청의 수치 표시를 위해 필요한 예외다. CSV는 기본 해제하고 필요할 때만 고급 설정에서 명시적으로 선택한다. 기존 3.2의 무조건 JSON 부재 시 CSV 탐색보다 이번 선택 계약이 우선한다.

| 평가 | 기본 파일 패턴 | 원문 키 | 방향 |
|---|---|---|---|
| Settle | `*_settle_result.json` | `Set Tilt Angle @ Settle (deg)` | common |
| Wobble | `*_wobble_center_{front,back}_result.json` | `Wobble Disp. (mm)` | front/back |
| Horizontal_Force_Angle | `*_horizontal_force_angle_{front,back}_result.json` | `Set Tilt Angle Difference (deg)` | front/back |
| Slope_Angle | `*_slope_angle_{front,back}_result.json` | `Slope Angle (deg)`, `OK/NG` | front/back |
| Slope_Angle_360 | `*_slope_angle_{front,back}_360_result.json` | `OK/NG` | front/back |

위 `{front,back}`는 두 패턴을 줄여 쓴 문서 표기다. UI는 전방·후방 규칙을 구분한다. 360 패턴은 일반 Slope 패턴과 겹치지 않게 검사한다.

### Slope_Angle의 두 측정 항목 (사용자 추가 확정)

`Slope_Angle`은 방향별 한 파일에서 `Slope Angle (deg)`의 숫자와 `OK/NG`의 판정 문자열을 각각 읽는다. 평가 하나를 값 하나로 제한하지 않고, 종합 표에서 Slope_Angle 아래 두 하위 행으로 표시한다. 전방과 후방은 각 방향의 파일에서 독립적으로 읽는다.

| 평가 | 원문 항목 | front | back |
|---|---|---|---|
| Slope_Angle | Slope Angle (deg) | 15.79 | 15.79 |
|  | OK/NG | OK | OK |

위 값은 이슈 #30 표의 예시이며 기본값으로 채우지 않는다. 검수 화면에서도 두 키의 경로·타입·값·상태를 각각 보여 준다. 각도는 숫자, 판정은 원문 OK/NG로 취급하며 판정을 각도에서 재계산하거나 수치로 변환하지 않는다. 한 키가 누락/오류여도 정상인 다른 키의 값은 보존하고, 문제가 있는 항목만 검수 대상으로 표시한다. 사용자가 부분 게시를 선택하면 해당 결측 항목만 비워 둔다. 그래프는 각도를 수치로 사용하고 판정은 표/문자 배지로 표시하며 Reference 비교도 항목별로 판단한다.

사내 Slope_Angle 결측도 보고되었으나, 두 키가 있다는 사실만으로 현재 오류 원인을 확정하지 않는다. 현재 코드에도 숫자와 verdict를 읽는 경로는 있으므로 실제 파일 선택·키 일치·값 타입·저장 capture를 확인한다. 이번 추가 지시는 두 키를 모두 독립 검수·표시해야 한다는 요구사항을 확정한 것이다. Slope_Angle_360은 기존의 `OK/NG` 필수 계약을 유지한다.

- 폴더 역할·파일 접미사·방향·조건을 함께 확인하고, 식별 실패를 common으로 자동 간주하지 않는다. Settle common은 front/back에 복제하지 않는다.
- 영상·이미지의 기본 허용 형식은 현재 지원하는 MP4/WEBM/JPG/JPEG/PNG로 한정한다. 파일 형식 선택이 새 디코더 지원을 뜻하지 않는다. 기존 영상 연결 동작과 미디어만 있는 평가의 표시를 유지한다.
- 확장자가 맞더라도 결과 패턴과 맞지 않는 JSON은 `선택 제외`다. 해당 파일의 본문을 파싱하거나 평가 후보로 넣지 않는다.
- 미선택 형식은 제외 건수로만 요약한다. 필요한 경우 폴더 스키마의 접힌 제외 목록에서 이름·제외 사유를 확인하며 대시보드 오류로 올리지 않는다.
- 같은 평가·방향·조건의 후보가 둘 이상이면 자동으로 첫 파일을 고르지 않는다. 검수 화면에서 정확한 원본을 선택한다. 조건이 서로 다른 파일을 하나의 값으로 합치지 않는다.
- CSV를 켠 경우에도 동일 조건의 JSON 오류를 CSV로 조용히 대체하지 않는다. 대체 원본 선택은 사용자 검수에 남긴다.

## 4. 폴더 연결의 3단계 안에 사전 검수 추가

기존 폴더 선택→구조 확인→등록·결과 확인 흐름을 유지한다. 3단계를 열면 아직 게시하기 전인 `파일·값 검수`를 먼저 보여 준다. 검수 완료 후 `등록하고 결과 읽기`로 확정한다. 별도 메뉴를 오가거나 같은 경로를 다시 입력하지 않는다.

```text
③ 등록·결과 확인
읽을 형식  [✓ JSON 수치] [✓ 영상] [✓ 이미지] [고급: CSV]

평가 / 방향       선택된 파일          JSON 원문 키              원본 값   상태
Settle / common   …_settle_result.json Set Tilt Angle @ Settle (deg) 1.18     확인
Wobble / front    …_front_result.json  Wobble Disp. (mm)          -21.424   확인

[확인 필요만 보기]  [선택 파일·키 상세]
선택 N개 · 제외 M개 · 확인 필요 K개          [검수] [등록하고 결과 읽기]
```

- 첫 화면에는 평가별 선택 원본·키·값·상태만 표시한다. 긴 이름 전체와 파일 목록·JSON 트리는 선택 행의 접힌 상세에서 확인한다.
- 파일 형식/패턴을 선택한 뒤 서버가 대상 파일만 읽고, 실제 키 경로·타입·원본 값·표시 단위·평가 방향을 미리 보여 준다. 문법 오류, 키 없음, null, 값 타입 오류, 중복 후보를 별도로 진단한다.
- JSON 키는 공백·점·괄호·슬래시를 포함한 원문을 보존한다. 내부 경로는 segment 배열 또는 JSON Pointer로 저장하며 점으로 나누지 않는다. `OK/NG` 역시 하나의 키다.
- 키가 다르면 실제 JSON 키 목록에서 명시적으로 연결한다. 공백 차이는 후보 추천만 하며 원문을 임의 정규화하거나 자동 연결하지 않는다. 이슈 #30의 Horizontal Force 키 주변 다중 공백은 표/HTML 복사 영향일 수도 있어 원본 파일 확인 전 확정하지 않는다.
- 숫자 0·음수·소수와 원본 OK/NG를 보존한다. null·누락·배열·객체·문자열 숫자는 구별하고 변환 정책을 명시한다. 기본으로 임의 단위 변환·절댓값·판정 계산을 하지 않는다.
- 선택된 파일에 문법 오류·키 오류·중복이 있으면 게시를 막고 수정 또는 명시적 제외를 요구한다. 실제 평가 파일 누락이나 사용자 제외로 일부 결과만 게시하는 경우는 해당 평가가 자료 없음으로 남는다는 요약을 확인시킨다. 다섯 평가가 전부 있어야만 등록되는 정책으로 바꾸지 않는다.
- 등록 이력에서도 동일한 검수 정보를 다시 열 수 있다. 오류 해결 후 새 결과 버전을 게시하며 과거 값을 덮어쓰지 않는다.

## 5. 저장·수집·재시도의 일관성

- 기존 환경 프로파일에 사용환경 `파일 선택 규칙 + 평가별 키 경로`를 버전 관리하는 계약을 추가한다. 반복 작업에서 재사용하되 조건별 한 번의 원본 파일 선택은 해당 preview에 저장한다.
- 검수 API와 최종 수집은 같은 선택기·파서·매핑 함수를 호출한다. 화면 미리보기와 게시 시의 재해석 차이를 없앤다.
- 검수 기록은 profile id/revision, Case/방향/조건, 선택 파일 상대경로·내용 해시, JSON 경로·값 타입, 제외 사유를 포함한다. 파일/매핑/규칙이 검수 이후 바뀌면 오래된 검수 승인을 무효화하고 다시 검수한다.
- 선택 규칙·실제 선택 원본·매핑 버전을 capture fingerprint에 포함한다. 선택 제외 파일 변화만으로 정상 수집 버전이 불필요하게 늘어나지 않게 한다. 조사 안전 한도와 접근 실패는 정상 제외와 별도 관리한다.
- 최초 게시와 실패 재시도 모두 확정된 선택을 사용한다. 읽을 수 없어진 파일·변경된 바이트는 재검수 대상으로 남기며 다른 파일로 자동 전환하지 않는다.
- 기존 프로파일·capture는 보존한다. 기존 프로파일에 새 필드가 없으면 기존 계약을 유지하고 새 기본 규칙 전환은 검수 화면에서 명시한다. 현재 값 없음 capture는 코드 업데이트만으로 바뀌지 않으므로 새 검수·수집 버전을 만들어 결과 링크로 연다.
- DB 컬럼 추가가 필요한지는 기존 JSON 저장 계약으로 검토 후 결정한다. 필요할 때만 additive migration과 빈 설치/기존 데이터 업데이트 검증을 추가한다. 배포 진입점과 비DDL 앱 시작 정책은 유지한다.

## 6. 구현 순서·검수

1. 원본 선택 계약과 합성 회귀를 먼저 고정: 이슈 #30의 접두사 있는 파일명/키/값, 360 구분, 추가 settings.json에 의한 충돌 재현.
2. 공통 파일 선택·JSON 경로 검수 서비스를 구현하고 프로파일/preview/게시/재시도에 연결한다.
3. 폴더 연결 3단계의 형식 선택·키/값 검수와 이력 진입을 구현한다. 기존 테이블·입력 컴포넌트와 데스크톱 밀도 정책을 재사용한다.
4. 결과 화면의 평가/측정 키를 영어 원문으로 통일하고 기술 진단을 검수 화면으로 이동한다. 수집 실패와 결측 상태의 의미는 유지한다.
5. Terra가 수집·검수 계약, Luna가 화면을 담당하되 공통 API 계약을 먼저 합의한다. **최신 사용자 지시(검수 최소화)를 우선**하여 변경 경로의 집중 검사와 Sol의 독립 검수 1회, 지휘 Astra의 통합 확인으로 제한한다. 별도 Astra 검수와 다단계 보안 플러그인 검사는 수행하지 않으며, 기존 권한·안전한 경로 접근 계약의 보존은 같은 변경분 검수에 포함한다. 전체 회귀·모바일 검수·중복 검사는 범위에 넣지 않는다.

## 7. 인수 기준

- 이슈 #30의 Settle 파일 접두사가 달라도 `1.18`을 common 한 칸에 표시한다. 같은 폴더의 비대상 JSON/CSV/해석 중간 파일이 이를 AMBIGUOUS/parse error로 만들지 않는다.
- 다섯 평가명과 측정 키는 영어 원문이며 Wobble 음수, 숫자 0, 소수, OK/NG가 보존된다. Slope 360의 각도를 미승인 필수값으로 추가하지 않는다.
- Slope_Angle의 front/back 각각에서 각도와 판정 두 항목을 동시에 표시한다. 각도만 누락, 판정만 누락, 각도 0, NG 판정을 포함해 정상인 다른 항목이 사라지지 않는지 검증한다. 한 파일의 두 키는 중복 원본 후보로 계산하지 않는다.
- 선택한 손상 JSON·중복 후보·키 누락·중첩 키·공백 차이는 게시 전에 확인한다. JSON 오류를 CSV로 숨기지 않는다.
- 제외 형식의 본문을 읽거나 파싱하지 않음을 검증한다. 경로/파일 크기·개수 제한과 기존 권한 검사를 유지한다.
- 결과 대시보드에는 원시 오류 패널·제외 확장자 목록이 없고, 해당 항목의 결측/검수 상태는 거짓 정상값 없이 표시한다. 상세 진단은 권한 있는 사용자의 해당 검수/이력에서 확인된다.
- `usage_hides_raw_diagnostics_but_keeps_review_state`, `legacy_capture_labels_do_not_mutate_payload` 회귀 시나리오로 원시 진단 비노출/의미 상태 보존과 과거 payload 불변을 각각 검증한다.
- 미디어만/수치만/평가 일부 누락, 비교, 과거 capture, 유통환경 CSV, 재시도·파일 변경·프로파일 변경을 회귀 검증한다.
- 데스크톱 브라우저에서 형식 선택→원문 키·값 확인→등록→동일 Case/capture 결과 이동을 검증한다. 모바일 전용 작업은 제외한다.

## 8. 계획 단계의 검증 이력

문서·코드·GitHub 이슈 표 대조와 DB를 열지 않는 순수 함수 합성 재현만 수행했다. 사내 원본 JSON 전체와 사내 실패 capture는 읽지 않았으므로 현장 결측의 최종 원인은 미확정이다. 구현 테스트·배포·commit/push는 수행하지 않았다.

## 9. 적용 후 사내 확인 순서

1. 폴더 스키마 → 폴더 연결규칙에서 사용환경을 선택하고 기존처럼 구조를 확인한다.
2. 3단계에서 JSON 수치·영상·이미지 선택을 확인하고 파일·값 검수를 실행한다. CSV는 필요할 때만 선택한다.
3. Settle의 선택 파일이 `*_settle_result.json`인지, 실제 `Set Tilt Angle @ Settle (deg)` 값이 보이는지 확인한다. 다른 위치에 있는 키라면 상세의 실제 키 목록에서 연결한다.
4. Slope_Angle은 front/back의 `Slope Angle (deg)`와 `OK/NG`를 각각 확인한다. 후보가 여러 개면 사용할 조건의 파일을 고르고, 오류 항목은 수정 후 다시 검수하거나 명시적으로 제외한다.
5. 일부 평가가 없거나 제외됐다면 부분 결과 확인을 체크하고 `다시 검수`한다. 여러 Case가 있으면 각각 검수를 마친 뒤 등록한다. 등록 결과의 새 수집 버전 링크에서 수치를 확인한다. 과거 수집 버전은 원본이 바뀌어도 그대로 유지된다.
6. 검수 후 원본 파일이나 저장 규칙이 바뀌었다는 안내가 나오면 다시 검수한다. 이미 등록된 이전 결과를 덮어쓰지 않는다.
7. 반복해서 사용할 형식·키 연결은 `이 파일·키 규칙을 저장`에서 저장 규칙으로 보관한다. 규칙을 저장한 뒤에는 다시 조사하여 새 버전을 적용한다. 개별 파일 선택과 제외 사유는 이번 등록에만 남는다.

## 10. 구현 계약과 검증

- 새 화면은 preview에 `require_usage_review: true`를 명시한다. 모든 Case의 검수·부분 게시 승인을 서버와 화면에서 확인한다. 기존 클라이언트/프로파일의 미검수 경로는 호환 목적으로 보존한다.
- `usage_source_review.py`의 선택기와 검수기를 등록 전 검수 및 수집에서 함께 사용한다. 선택 원본과 미디어의 해시 변경, 규칙 revision 변경은 게시/재시도를 차단한다. 미선택 파일은 본문을 읽지 않으며 제외 목록 변경은 capture fingerprint에 넣지 않는다.
- 형식·키 경로는 프로파일 `rules.usage_sources`, 개별 선택·제외·승인과 검수 스냅샷은 기존 preview JSON에 저장한다. 등록 이후에는 해당 스냅샷을 바꿀 수 없다. DB migration과 새 런타임 의존성은 없다.
- 조회는 `value_status`와 `verdict_status`를 분리하여 정상값을 보존한다. 추가 미디어는 수치 후보와 분리하여 정상 Settle 값을 AMBIGUOUS로 바꾸지 않는다. 과거 payload는 수정하지 않는다.
- 집중 검증: 결과 조회 17개, 선택기/기존 파서·프로파일 32개를 확인했다. 서버 게이트 보완 후 검수 API 5개와 선택기 5개, 추가 프로파일 경로 검사 1개가 통과했다(앞선 선택기 검사와 일부 중복하므로 합산 수치가 아님). 결함 수정으로 필요한 검사만 재실행했다.
- 데스크톱 1440×1000 결과 화면 검사 1개가 통과했다. Slope 두 행, 정상/부분 값, 원시 진단 비노출, 환경 전환, 프레임워크 오류 부재를 확인했다. 테스트 실행기의 Windows 자식 프로세스 종료 정리는 오류로 끝났으며 테스트 성공과 구분한다. 종료 후 테스트 포트의 리스너는 없었다.
- 실제 사내 원본 JSON, 실제 사용자 DB/서비스, Server 2022 폐쇄망 설치는 검증하지 않았다. 모바일·전체 회귀·별도 다단계 보안 스캔은 최신 최소 검수 지시에 따라 실행하지 않았다.
- OpenAPI 클라이언트를 갱신했고 TypeScript와 Vite production build가 통과했다. Vite 임시 파일 접근 오류 1회 후 재시도는 통과했다. 폴더 검수 전체 흐름의 브라우저 E2E는 별도로 실행하지 않았으며 API 통합 검사와 변경분 검수로 범위를 제한했다.
- Sol의 집중 독립 검수에서 발견한 서버 게시 gate, 재시도 profile revision 검사, 프런트 `entries.values` 타입 누락을 보완했고 지휘 Astra가 테스트·빌드와 최종 통합을 확인했다. commit/push는 이번 구현 단계에서 수행하지 않았다.

- 최종 CSS 구조 검사에서 원문 키의 고정 max-width를 제거하고 caption 토큰·줄바꿈으로 보완했다. 프런트 architecture 검사(229 source files / 5 reviewed imports)와 수정 후 Vite build가 통과했다. 기존 큰 chunk 경고는 남아 있다.
