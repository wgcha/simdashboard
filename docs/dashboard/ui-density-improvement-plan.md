- 최초 계획 검수: Sol 독립 검수 승인, Astra 최종 검수 완료. 후속 P0와 구현 단계 검수는 각 단계 문서에 별도로 기록하며 이 승인을 재사용하지 않는다.

## 적용 대상 정책 — 데스크톱 전용

- **2026-09-20 사용자 영구 지침:** 앞으로 모든 UI 계획·구현·검수는 데스크톱을 대상으로 한다. 사용자가 명시적으로 변경하기 전까지 유지한다.
- 모바일 전용 UI 개선, 모바일 최적화, 모바일 뷰포트 검수, 신규 모바일 테스트는 수행하지 않으며 완료 조건에도 포함하지 않는다. 기존 자동 테스트 전체 실행에 포함된 모바일 사례는 별도 모바일 개선 작업으로 확장하지 않는다.
- 기존 반응형 코드·과거 테스트·검증 기록을 일괄 삭제하라는 의미는 아니다. 모바일 대응을 이유로 데스크톱 구현을 확대하거나 완료를 지연하지 않는다.
- 이 정책은 아래 계획 및 과거 P0~P3 문서의 모바일 요구보다 우선한다. 과거 실제 수행 기록은 사실대로 남긴다. P4 이후는 데스크톱 크기·글자·테마·기능 흐름으로 검증한다.

## 1. 목표와 현재 확인 결과

넓은 화면의 작업 공간을 활용하고, 글자 역할과 컨트롤 크기를 일관되게 만들어 한 화면에서 결과를 더 쉽게 비교한다. 밀도 향상을 이유로 사용자 글자 설정이나 중요 정보를 줄이지 않는다.

| 항목 | 현재 코드 확인 | 계획 반영 |
|---|---|---|
| 글자 설정 | `app/preferences/workspacePreferences.ts`: 기본 14, 허용 11~18, pt 저장 키와 이전 키 지원 | 저장 키·값·범위·기본값 유지 |
| 글자 주입 | `App.tsx`, `app/shell/WorkspaceShellLayout.tsx`에서 shell에 `--ui-font-size`를 pt로 주입 | 모든 shell·별도 route·portal의 적용 경로 조사 |
| 역할 구분 | `styles.css` 끝의 span/strong/small/code, 제목, Recharts 대상 전역 `!important`가 존재 | 이전 완료 영역부터 강제 규칙 적용을 해제 |
| 결과 목록 | `ResultOverviewDashboard.tsx`의 `PAGE_SIZE = 5`, 클라이언트 배열 slice | 기본 25건과 10/25/50 선택을 제안하고 필터·페이지 문맥 검증 |
| 스타일 로드 | `main.tsx`: styles → theme → grid 라이브러리 → focused-shell | tokens를 styles 앞에 추가하되 실제 기능 CSS cascade도 확인 |
| 구조 검사 | `check-architecture.mjs`에 코드 상수와 JSON의 상한 대조가 있음 | 같은 방식을 CSS 검사로 확장 |

원문의 CSS 개수·폭 종류·컨트롤 종류 및 파일 줄 번호는 당시 조사값이다. 구현 착수 시 CSS 전체 선언과 최종 computed style을 재집계한다. MatNexus 저장소를 이번 작업에서 재조사하지 않았으며, 외부 저장소에 관한 내용은 제공 문서의 참고 설명으로만 사용했다.

## 2. 원안에서 보정할 사항

1. **14px 루트로 바로 바꾸지 않는다.** 기존 14pt는 CSS 기준 약 18.67px이며 14px와 다르다. 11pt≈14.67px, 18pt=24px를 보존한다. 본문 1배를 기준으로 제목과 보조 문구에 역할별 배율을 적용한다.
2. **전역 `!important`부터 일괄 삭제하지 않는다.** 토큰·프리미티브·대상 화면의 규칙을 먼저 만들고, 이전한 subtree만 기존 blanket selector에서 제외한다. 같은 글자 크기 `!important`를 새 파일에 추가해 덮는 방식은 피한다.
3. **본문 폭 제한과 읽기 폭 제한을 구분한다.** 작업 화면 wrapper의 cap은 해제하되 도움말 본문, VOC 글, 폼 dialog, 보고서 canvas, 이미지·영상의 고유 비율은 별도 정책으로 유지한다. 도움말 전체 shell까지 좁힐 필요는 없다.
4. **25건은 페이지 크기다.** 첫 화면에 25행을 강제로 넣거나 25행만큼 고정 높이를 만들지 않는다. 현재 목록 구조와 두 줄 메타데이터를 유지할 수 있도록 최소 행 높이와 여백부터 조정한다.
5. **rem은 html 기준이다.** shell의 CSS 변수만 바꾸어도 rem이 변한다고 가정하지 않는다. 점진 이전 중에는 shell의 pt 기반 변수와 `calc()` 토큰으로 크기를 연결하고, 전역 영향 검증 후 html root와 rem을 함께 전환한다.

## 3. 크기·폭 설계 초안

다음 값은 구현 전후 화면 비교로 확정할 초깃값이다. 기본 글자 크기 자체의 축소는 포함하지 않는다.

| 범주 | 제안 | 제약 |
|---|---|---|
| 글자 역할 | 본문 1배, 보조 0.875배, 소제목 1.125배, 섹션 1.25배, 페이지 제목 1.5배 | 핵심 결과·입력·메뉴는 본문 기준. 모든 역할이 사용자 설정에 비례 |
| 컨트롤 | compact / default / comfortable 3단, 14pt 기준 최소 높이 32/38/44px 후보 | 글자 확대 시 함께 확대하고 고정 height보다 min-height 사용 |
| 표·목록 행 | 단일행 40px, 두 줄 목록 52px 최소 높이 후보 | 14pt 기준. 내용·확대에 따라 성장, 잘림 금지 |
| 간격 | 4/8/12/16/24/32 계열 토큰 | 내부 중복 padding부터 축소. 모든 공간을 기계적으로 축소하지 않음 |
| 모서리 | 4/8/12px 세 단계 | 기존 색·테두리 유지, 새 시각 테마 도입 안 함 |
| shell 좌우 여백 | 데스크톱 `clamp(24px, 2vw, 40px)`, 좁은 화면 12~16px | header와 본문 시작선 일치, 중첩 padding 제거 |
| 폭 | 작업 본문 `width:100%`, `min-width:0`, 불필요 max-width 제거 | 사이드바를 제외한 가용 폭 사용. 읽기 영역은 별도 예외 토큰 |
| 표 overflow | 표 wrapper 내부 가로 스크롤, 식별자·수치 열 nowrap | 페이지 전체 가로 overflow 금지. 긴 설명은 열별 정책, 원문 접근 유지 |

필터와 동작 버튼은 작은 화면에서 자연스럽게 줄을 바꾼다. 표 내용의 비의도적 줄바꿈을 막는 규칙을 버튼·전체 페이지에 확대 적용하지 않는다. 포커스 테두리와 키보드 조작을 보존한다.

## 4. 구현 순서와 독립 작업 단위

### P0 — 기준선과 인터페이스 확정

- 실제 CSS의 압축된 장문 선언까지 파싱해 max-width, font-size important, 컨트롤 높이, radius, breakpoint 목록을 만든다. 기존 값의 존재와 화면에 실제 적용되는 값은 구분한다.
- Case 결과, 결과 개요, 폴더 연결, 의뢰 작업공간, 기존 Run 대시보드, 도움말·폼을 대표 화면으로 선정한다. 합성 데이터와 동일 viewport·글자 설정으로 전후 증거를 남긴다.
- Astra가 토큰 이름, 이전 영역 표시 방식, 폭 예외 목록, 기본 프리미티브 API를 확정한다. 이 계약 이후에 Luna/Terra 병렬 구현을 시작한다.
- 완료 조건: 14pt/11~18pt 설정 계약, 이전 대상과 유지 예외, 비교 화면 기준선이 기록되어 있음.

### P1 — 토큰·가드레일과 작업 본문 폭

- Terra: `frontend/src/tokens.css`, `main.tsx` 로드 순서, 구조 검사 확장. 기존 스타일에 영향 없는 토큰 정의부터 도입한다.
- Luna: `styles.css`, `focused-shell.css`의 작업 wrapper, 데이터·모델링 화면의 폭 제한과 중첩 여백 정리. 각 화면의 읽기/편집 특성을 확인하고 cap을 제거한다.
- 1920/1500/1440/1280 등 숫자 전역 치환 금지. 데스크톱 media query가 다시 cap을 덮는지 확인한다.
- 완료 조건: 대표 작업 화면이 데스크톱 가용 폭을 사용하고 페이지 전체 가로 넘침이 없으며, 도움말·dialog의 읽기 폭이 유지됨. P1 당시 모바일 검증은 과거 수행 기록으로만 유지한다.

### P2 — 공통 프리미티브와 대시보드 시범 적용

- Terra: `shared/components/Button.tsx`, `Input.tsx`, `Select.tsx`, `Table.tsx`와 독립 스타일. native HTML 속성·ref·label 연결·disabled·focus를 보존하는 얇은 래퍼로 만든다.
- Table은 의미론적 table·header·cell과 스크롤 wrapper만 담당한다. 데이터 조회·정렬·페이지·선택 상태는 기능 모듈에 둔다. 현 결과 목록이 table이 아니면 불필요한 DOM 전환을 강제하지 않는다.
- Luna: Case 결과와 결과 개요에 토큰/프리미티브 적용, 헤더·필터·결과 영역 간 간격 정리. 기존 단일 후보 축약, 수집 이력, Case/Run Option/capture 선택 문맥을 유지한다.
- 결과 개요는 25건 기본과 10/25/50 선택을 적용한다. 아래 재설정 계약에 따라 페이지를 처리하고 빈 상태·마지막 페이지를 검증한다.
- 페이지 크기는 컴포넌트 세션 상태로 두고 새 저장 키는 추가하지 않는다. 페이지 크기·검색어·프로젝트·필터·data 변경은 현재 동작을 확장해 모두 page=0으로 재설정한다. 렌더 시 유효 범위 clamp는 보조 안전장치로 유지한다.
- 완료 조건: 같은 데이터·14pt·1366×768에서 기존보다 결과 영역의 첫 화면 노출량이 줄지 않고 불필요 여백이 감소함. 페이지 크기 확대를 화면 밀도 향상의 증거로 대체하지 않음.

### P3 — 글자 크기 강제 규칙 단계적 해제

- Terra가 글자 설정 적용 경로와 root 수명주기를 담당하고, Luna가 기능별 타입 역할 매핑을 담당한다. 공용 CSS 편집 소유자는 단계별로 한 명으로 고정한다.
- 시범 영역에 이전 표시를 두고 기존 selector가 해당 영역을 제외하도록 한다. portal의 dialog/tooltip도 표시·변수 전달을 확인한다. 미이전 화면은 기존 pt 동작을 유지한다.
- 순서는 표/컨트롤 → 일반 본문/보조 문구 → 제목 → 차트/SVG·개별 위젯 글자 설정 → shell/나머지 화면이다. 기능별 사용자 글자 override와 전역 설정의 우선순위를 먼저 기록한다.
- 설정 적용은 공통 어댑터 하나로 모은다. 입력은 기존 저장 설정, 출력은 11~18 범위로 정규화한 pt 변수다. 두 shell의 중복 주입을 통합하되 이 단계에서는 shell 범위만 적용한다. localStorage v1·legacy migration, 증감 버튼의 11/18pt 경계 disabled도 유지한다. 본문 computed font-size 기대치는 11pt≈14.67px, 14pt≈18.67px, 18pt=24px이며 제목·보조 문구는 표의 역할 배율로 검사한다.
- react-grid-layout의 JS pixel `rowHeight`, 차트 축 여백, 영상·canvas의 비율은 rem만으로 해결되지 않는다. 글자 확대 시 내용 영역/스크롤을 검증하고 저장된 grid 좌표·배치를 임의로 재저장하지 않는다.
- grid의 기존 rowHeight·margin 기본값은 유지하고 사용자 글자 배율과 자동 연동하지 않는다. Workflow·기존 결과·보고서 canvas별 저장 h/y와 행높이 계약을 P0에서 확인하며, 별도 설계 없이 좌표의 의미를 바꾸지 않는다.
- 현재 코드에서 확인한 rowHeight 기본값은 WorkflowView 84px, GenericResultLayoutWorkspace 70px, ReportLayoutEditor 20px(maxRows 18)이며 이번 개선에서 유지한다.
- 후속 P0 조사에서 확인한 ResultsWorkspaceGrid의 74px도 같은 보존 대상이다.
- 완료 조건: 시범 화면의 11/14/18pt에서 글자 역할 구분과 조작 가능성이 유지되며 해당 subtree만 blanket font-size important 적용에서 제외됨. 미이전 화면의 규칙과 html root는 유지한다.

### P4 — 후속 화면 확산과 최종 검수

- 폴더 연결·의뢰/등록·비교/모델링·도움말/설정 순으로 적용한다. 앞 단계에서 확인된 부작용을 해결한 뒤 확산한다.
- Sol 독립 1차 검수 후 Astra 최종 검수. 화면 단위 변경으로 나눠 문제가 발생하면 해당 화면 변경을 되돌릴 수 있게 한다. 사용자 설정·저장된 레이아웃의 reset은 rollback 수단으로 쓰지 않는다.
- 각 단계의 변경·검증·남은 예외는 `log/work-log.md`에 남긴다. 완료 전 이 계획과 문서 지도의 상태를 구현 완료로 바꾸지 않는다.

### P5 — root 전환과 전역 규칙 정리

- P4의 모든 대상 화면과 portal 이전 후에만 공통 어댑터가 `document.documentElement`에 사용자 pt 값을 주입하도록 바꾸고 rem 기반 크기를 적용한다. 이전 root 값 보관과 unmount/logout 복원을 한 구현으로 공유한다.
- 모든 route 및 로그인/로그아웃·별도 shell 전환을 검증하고 전역 blanket font-size important를 제거한다. 기능상 필요한 scoped 예외는 사유와 함께 유지한다.
- 완료 조건: 전역 강제 규칙을 다시 추가하지 않아도 전체 화면의 글자 설정이 작동하고, shell 해제 후 root에 이전 사용자의 설정이 잔류하지 않음. Sol 재검수와 Astra 최종 검수 후 전체 완료로 기록한다.

## 5. CSS 가드레일 6종

1. font-size `!important` 선언: legacy 기준 상한 고정, 이전 완료 영역은 0, 위젯 예외는 selector와 사유 지정.
2. 작업 wrapper max-width: 읽기·dialog·canvas 예외 외 새로운 cap 금지.
3. 컨트롤 height/min-height: 이전 영역의 하드코딩 금지, 3단 토큰 사용.
4. radius: 이전 영역은 공통 3단 사용, 원형/특수 그래픽 예외 구분.
5. breakpoint: P0에서 채택한 공통 지점·기능 예외 외 새 값 증가 금지.
6. 전역 CSS 성장: styles.css의 줄 수와 선언 수를 함께 제한하고 새 기능 CSS의 전역 selector 유출 검사.

CSS 파일 탐색을 검사기에 명시적으로 추가한다. 압축·복수 selector·media 내부를 놓치지 않도록 CSS 파서를 재사용하며, 필요하다면 이미 의존성 그래프에 있는 파서의 직접 devDependency 고정과 lock 갱신을 검토한다. 신규 런타임 UI 라이브러리는 전제하지 않는다.

코드 상수와 JSON 상한을 함께 pin하고 JSON만 높인 fixture가 실패하는 검사를 추가한다. legacy는 증분 감소, 이전 완료 영역은 엄격 검사로 분리한다. 포맷 변경에 따른 줄 수 증가는 선언 수와 diff를 검토해 별도 기록하며 압축해서 상한을 우회하지 않는다.

## 6. 인수 검증

- 화면: 데스크톱 1366×768, 1920×1080, 2560×1440. 변경 영향에 따라 기존 정책의 2048/1707 유효 폭도 확인한다. 모바일은 구현·검수·완료 조건에서 제외한다.
- 글자·테마: 기본 14pt 및 11/18pt, 라이트/다크. 핵심 대시보드는 전체 조합, 나머지는 기본과 큰 글자·좁은 폭 중심으로 검사한다.
- 기능: 검색·필터·페이지 크기·마지막 페이지, Case/환경/Run Option/capture 이동과 새로고침, 표 스크롤·행 선택·키보드 포커스, tooltip/dialog, 차트/영상 확대, grid 드래그·크기 조절·저장 배치 복원.
- 페이지 경계 자료는 0/1/5/6/25/26건을 포함한다. 검색·프로젝트 변경 시 page reset, 페이지 크기 변경 시 범위 보정, 25/50건의 긴 문서 스크롤·탭 순서·옆 패널 높이 불균형을 확인한다. 25건 기본이 사용성을 떨어뜨리면 10건 기본으로 조정한 근거를 남긴다.
- 25건 설정에서 0/1/5/6/25건은 페이지 이동이 필요 없고, 26건은 두 번째 페이지에 1건이다. 10건 설정은 5/6건 모두 한 페이지이고 10/11건 경계를 추가한다. 첫/마지막 페이지 이전·다음 disabled와 P2의 page=0 재설정 계약을 검증한다.
- 글자 11↔18pt 저장·재로드·legacy migration·버튼 경계·로그인 전환을 검사한다. 글자만 바꿨을 때 저장된 grid x/y/w/h가 같고 drag/resize 없이 배치 저장 callback이 발생하지 않아야 하며 18pt에서 내부 내용이 잘리지 않아야 한다.
- 시각: 제목/본문/보조 크기, header/본문 시작선, 행·컨트롤 높이, 결과 첫 화면 노출, clipping/overflow를 전후 스크린샷과 computed style로 비교한다.
- 자동 검사: `pnpm --dir frontend check:architecture`, `test:architecture`, `test:preferences`, 타입 검사·production build 및 해당 E2E를 수행한다. 시나리오 통과와 runner의 종료 오류는 별도로 기록한다.
- 테스트는 합성 fixture·격리 환경에서만 한다. 실제 사용자 DB·설정·운영 서비스를 사용하지 않는다. 기존 API/수집·DB 계약은 유지하며 배포 진입점 변경을 포함하지 않는다.
- 프런트 정적 빌드·자체 호스팅 Pretendard를 유지한다. 의존성 변경이 필요하면 lock·Windows/offline 패키지 검증을 함께 갱신한다. Server 2022 폐쇄망 설치·업데이트·재부팅 실기를 하지 않았으면 미실시로 기록한다.

## 7. 이번 계획의 검토 범위

이번에는 제공 분석 문서, 관련 기준 문서, 현재 글자 설정·전역 스타일·페이지 처리·빌드/검사 구성을 확인했다. 실제 렌더, CSS 전체 인벤토리, 정확한 첫 화면 행 수와 성능 수치는 P0에서 측정한다. 이미지 시안·앱 코드·DB 변경은 이번 계획 작성에 포함하지 않는다.
