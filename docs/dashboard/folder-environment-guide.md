# 환경별 폴더 연결과 결과 확인

이 안내는 `환경별 폴더 규칙과 결과 조회 UX 개선계획` 구현에 따른 화면을 기준으로 한다. 관리자 계정으로 `폴더 스키마` 메뉴를 열면 기본 화면은 **폴더 연결·규칙**이다. 서버 저장소 루트는 관리자가 먼저 설정해야 한다. 브라우저가 실행되는 PC의 임의 경로가 아니라 서버에서 접근할 수 있는 저장소를 선택한다.

최초 설치 직후에는 초기 데이터 구성 화면의 **폴더 연결·규칙** 버튼으로 들어간다. 이 기능을 열기 위해 기존 하중경우나 결과를 먼저 만들 필요는 없다.

## 1. 사용환경: Case 결과까지 연결

예시 구조:

```text
Project_1042
└─ WR_1042_SimType1
   └─ Assy_RES_Main
      ├─ Settle
      ├─ Wobble
      ├─ Horizontal_Force_Angle
      ├─ Slope_Angle
      └─ Slope_Angle_360
```

1. 상단 환경을 **사용환경**, 저장 규칙을 **기본 규칙으로 시작**으로 선택한다.
2. `업무 연결`에서 **폴더에서 프로젝트·의뢰 찾기**를 선택한다. 프로젝트·의뢰가 이미 있으면 **기존 프로젝트·의뢰에 연결**을 선택한 뒤 두 항목을 고른다. 이때 Case 폴더부터 조사할 수 있다.
3. **폴더 찾아보기**로 조사할 위치를 열고 **이 폴더 선택**을 누른다. 경로를 비우면 저장소 전체를 조사하므로 처음에는 해당 프로젝트나 의뢰 폴더를 선택하는 편이 확인하기 쉽다.
4. **조사 시작**을 누른다. 구조 확인에서 `Project_...`는 **프로젝트**, `WR_...`는 **의뢰**, `Assy_RES_...`는 **해석 Case**, 그 아래 다섯 폴더는 **평가 항목**인지 확인한다.
5. 다른 이름 때문에 인식되지 않았다면 왼쪽 폴더를 누르고 오른쪽 **폴더 역할**을 바꾼다. 업무와 무관한 중간 폴더는 **일반 중간 폴더**, 읽지 않을 하위 트리는 **이번 등록에서 제외**로 지정한다. 사용환경에는 하중경우나 Run Case를 만들지 않는다.
6. **등록 내용 확인**을 누른다. 확인 필요 항목이 있으면 **구조 수정**으로 돌아가 해결한다. 새로 등록할 업무와 기존 연결을 확인하고 **등록하고 결과 읽기**를 누른다.
7. Case별 **결과 보기**를 누른다. 해당 프로젝트·의뢰·환경·Case·수집 버전을 포함한 결과 화면이 열린다. 경로를 다시 입력하거나 폴더를 다시 조사할 필요가 없다.
8. 사용환경 결과는 Case를 선택한 뒤 다섯 평가를 보여준다. Case가 하나면 선택 상자를 줄여 표시한다. 평가 파일이 빠져 있으면 해당 평가의 자료 없음 상태를 확인한다.

폴더 역할 지정만으로 모든 파일 형식을 읽을 수 있는 것은 아니다. 결과 파일은 기존 대시보드의 JSON/CSV 및 미디어 읽기 계약에 맞아야 한다. 읽지 못한 파일과 이유는 결과의 품질 안내에서 확인한다.

## 2. 유통환경: 선택적인 Run Option

```text
프로젝트 / 의뢰 / 해석 Case / 하중경우 / Run Case
                                      ├─ Scene_01 / 결과
                                      ├─ Individual / Scene_01 / 결과
                                      └─ Custom Fatigue / Scene_01 / 결과
```

같은 세 단계를 사용하되 환경을 **유통환경**으로 선택한다. Case 아래는 **하중경우 → Run Case**로 확인한다. `Individual`, `Cumulative` 외의 옵션 폴더도 실제 폴더를 선택해 **Run Option** 역할을 지정할 수 있다. 폴더 이름은 원문 그대로 사용하며 이름으로 계산 방법을 결정하지 않는다.

- Run 바로 아래 Scene은 **옵션 없음**이다. 빈 옵션 폴더를 만들지 않는다.
- Run 아래 옵션 폴더가 있으면 **Run Option → Scene**으로 확인한다.
- 직접 Scene과 옵션 폴더가 함께 있어도 서로 다른 결과로 유지한다.
- **미확인**은 옵션 없음과 다르다. 기존 capture의 UNKNOWN이나 분류가 모호한 결과를 임의로 옵션 없음으로 바꾸지 않는다.
- 결과 화면에서는 Case → 하중경우 → Run Case → Run Option 순으로 확인한다. 후보가 하나인 항목은 자동 선택되고, 여러 개면 사용자가 선택한다.

## 3. 사내 폴더 규칙 저장·재사용

구조 확인에서 **구조를 규칙으로 저장**을 누른 뒤 **확인한 구조에서 가져오기**를 누른다. 규칙 이름을 입력하고 부모 역할·이름 패턴·역할을 확인한다. 예를 들어 부모 역할 `의뢰`, 이름 패턴 `Model_*`, 역할 `해석 Case`로 저장할 수 있다. 일반적인 설정에서는 깊이를 비워 부모 역할을 기준으로 찾는다.

**규칙 저장** 후 폴더 연결로 돌아가 그 규칙을 선택하고 다시 조사한다. 저장 자체는 기존 업무·결과를 바꾸지 않는다. 이후 **저장된 규칙**에서 수정하면 개정 번호가 증가하며, 수정 전에 만든 미리보기는 다시 조사해야 등록할 수 있다. 여러 역할 규칙이 같은 폴더에 겹치면 확인 대상으로 남는다.

예전에 저장한 규칙은 **기존 폴더 스키마**에서 계속 사용할 수 있다. 새 화면의 **기존 깊이 규칙에서 복사**로 새 환경 규칙을 만들 수도 있다. 원본은 보존하며 기존 `하중경우`와 이름·코드 추출은 자동 변환하지 않는다. 새 Case/Run 역할을 구조 확인에서 지정한 뒤 사용한다.

## 4. 실패·이력·과거 결과

- 등록은 완료됐지만 결과 읽기에 실패하면 업무 연결을 다시 만들지 않고 **미완료 결과 다시 읽기**를 누른다.
- 창을 닫았으면 **등록 이력**에서 해당 작업을 열어 상태 확인·재시도·결과 이동을 이어 간다.
- 조사 뒤 폴더 구조·저장소·규칙이 바뀌었다면 새로 조사한다. 오래된 미리보기를 강제로 적용하지 않는다.
- 결과의 **수집 이력**에서 과거 버전을 선택한다. URL로 열었던 버전은 새 수집이 생겨도 자동으로 바뀌지 않는다.
- 원본이 사라지거나 접근할 수 없으면 원본 경로를 확인한다. 기존 capture와 기존 업무를 삭제하는 방식으로 복구하지 않는다.

사내 기존 규칙과 실제 원본은 별도로 대조해야 한다. 개발 검증은 합성 폴더와 임시 DB로 수행하며 실제 사내 자료의 정확성을 대신 확인한 것은 아니다.
