# 사용자 권한과 선택형 로컬 도우미

승인된 사용자는 로컬 도우미를 설치하지 않아도 운영 대시보드와 허용된 결과를 조회할 수 있다. 로컬 도우미는 해당 PC의 해석 프로그램 실행·프로그램 등록·PC 연결에 사용하는 선택 기능이다. 조회자나 관리자에게 일괄 설치를 요구하지 않는다.

## 역할 구분

현재 권한은 프로젝트별 일반·파워·관리자 역할과 별도의 전역 관리자 지정으로 관리한다. 같은 사용자가 프로젝트마다 다른 역할을 가질 수 있다.

| 역할 | 주요 권한 |
|---|---|
| 일반 사용자 | 대시보드·결과 조회, 보고서 내보내기, 본인에게 배정된 작업 실행 |
| 파워 사용자 | 일반 권한 + 의뢰 작성·편집, 작업 흐름 편집, 결과 등록·검토 |
| 프로젝트 관리자 | 파워 권한 + 해당 프로젝트 구성원·대시보드·레이아웃·기준값·변수 관리 |
| 전역 관리자 | 전체 프로젝트 관리 + 회원 승인·전역 관리자 지정·시스템 설정·메뉴 정책·감사로그 관리 |

회원 가입 승인은 계정을 활성화하는 작업이다. 일반 회원을 승인했다고 파워 사용자나 관리자가 되지는 않는다. 프로젝트에 배정되지 않은 승인 회원도 기존 서버 정책에 따라 대시보드·프로젝트 데이터 조회와 보고서 권한을 가지며, 프로젝트 작업·편집 권한은 별도 역할을 배정해야 한다.

`사용자·프로젝트 권한`에서 계정 승인과 프로젝트 역할 배정을 구분한다. 프로젝트를 선택하고 승인된 사용자를 일반·파워·관리자 중 해당 역할로 배정한다. 전역 관리자 지정은 전체 시스템 관리가 필요한 사용자에게만 사용한다. 권한 정보는 DB의 계정 및 프로젝트 멤버십에 저장되며, 로컬 도우미 설치 상태와 무관하다.

## 도우미가 필요한 경우

- 웹에서 대시보드·의뢰 현황·결과·보고서 보기: 설치 불필요.
- 사용자 승인·권한 관리·웹 설정 변경: 설치 불필요.
- 해당 PC의 해석 프로그램을 등록하거나 로컬 작업 실행: 그 PC에 설치하고 본인 계정으로 연결.

같은 사용자가 여러 PC에서 로그인해도 도우미는 설치·연결한 PC에서만 로컬 프로그램을 실행한다. 프로젝트 역할이 있어도 로컬 실행 환경이 자동으로 설치되거나 다른 PC에 연결되지는 않는다.

## 사용자 관리의 새로고침

사용자 관리의 새로고침은 사용자 목록과 선택한 프로젝트 구성원을 조회하는 기능이다. 서버 중지·재시작 또는 프로그램 업데이트를 실행하지 않는다.

조회는 15초 후 시간 초과로 안내하며, 실패한 목록의 변경 버튼을 잠그고 재시도를 제공한다. 프로젝트를 바꾸면 이전 조회 응답을 무시한다. 권한 저장 중에는 프로젝트 선택과 다른 변경을 잠가 대상이 섞이지 않게 한다. 프로젝트가 없는 초기 서버에서도 전역 관리자는 사용자 승인 목록에 접근할 수 있다.

화면 오류만으로 웹/API 프로세스가 종료됐다고 단정하지 않는다. 재발 시 표시된 오류 문구와 다시 `start.bat`을 실행했을 때의 결과(이미 실행 중/새 시작)를 함께 확인한다. 실제 종료 여부가 불분명하면 발생 시각의 `backend/uvicorn-error.log`, `frontend/vite-error.log`를 확인한다. 로그를 공유할 때는 비밀번호·토큰·DB 연결 문자열을 제외한다.

## 변경 기록과 사내 적용

2026-09-10: 프로젝트 역할별 그룹 및 명시적 사용자 배정, 사용자 검색 `q` 파라미터 수정, 새로고침 실패·지연·프로젝트 전환 방어를 추가했다. 승인된 무소속 사용자를 내 PC 설정으로 강제 이동시키던 조건을 수정했다. 대시보드 초기 로딩에 필요한 의뢰 목록 GET의 중복 멤버십 제한을 제거하여 기존 `project.data.view` 권한과 일치시켰다. 의뢰 작성·편집·실행 권한 검사는 유지한다.

DB 스키마·패키지 변경은 없다. 기존 계정과 프로젝트 역할은 그대로 보존한다. 현재 Windows 실행 방식에서는 `git pull --ff-only` 후 `stop.bat` → `start.bat`으로 적용하고 브라우저를 새로고침한다. 정적 빌드로 배포하는 환경은 프론트 빌드도 갱신하거나 기존 `update.bat` 절차를 사용한다.

## 검증

- 격리된 로컬 테스트 서버 `http://127.0.0.1:15173`, Chromium 1280×720 및 390×844에서 확인했다. Browser plugin not available — 저장소 Playwright를 사용했다.
- `node scripts/run-e2e.mjs access-admin-refresh.spec.ts account-auth.spec.ts access-policy.spec.ts`: 8개 통과. 실제 가입·승인·로그인, 도우미 없는 무소속 대시보드 진입 및 브라우저 새로고침, 일반→파워→관리자 저장, 저장 중 프로젝트 전환 잠금, 목록 검색, 반복 조회, 503·15초 지연 이후 복구, 프로젝트 없는 서버의 계정 관리, 역할별 메뉴를 검증했다.
- 주요 화면 내용·경로·프레임워크 오류 화면 부재·브라우저 pageerror 부재를 확인했다. 데스크톱/모바일 캡처에서 그룹과 모바일 새로고침 노출, 가로 넘침 부재를 확인했다.
- `npm.cmd run build -- --configLoader runner`: 통과. 기존 번들 크기 경고는 남아 있다.
- 백엔드 `test_project_request_queries_slice.py` 6개 통과 후, 무소속 사용자 GET 200/같은 토큰의 담당자 변경 PATCH 403 회귀 사례를 추가해 해당 테스트를 다시 통과했다. `test_project_result_profiles.py`의 회사 조회 허용 및 프로젝트 관리자 범위·일반 사용자 쓰기 금지 테스트도 각각 통과했다. 테스트 전용 최초 관리자 fixture를 보완했으며 전체 백엔드 suite를 실행한 결과는 아니다.
- 회사 PostgreSQL 및 실제 사내 서버의 프로세스 종료 현상은 이번 로컬 검증 대상이 아니다. 테스트용 임시 DB를 사용했으며 운영 DB와 `.env`는 변경하지 않았다.
