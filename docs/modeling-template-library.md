# 제품·로드케이스별 모델링 템플릿

자동화 템플릿 화면은 모델링 설정 CSV를 재사용하기 위한 라이브러리다. 제품명·로드케이스명·템플릿명으로 카드를 만들며, 특정 의뢰의 실행 이력과 구분한다. 기존 자동화 실행 기록은 삭제하거나 CSV 카드로 임의 변환하지 않는다.

## 사용 방법

1. 자동화 템플릿에서 새 템플릿을 열어 제품, 로드케이스, 이름을 입력한다. 제품·로드케이스는 재사용 분류명이며 특정 의뢰의 데이터와 독립적이다.
2. 카드를 선택하고 CSV 폴더 또는 개별 CSV 파일을 고른다. 폴더 선택은 최상위 선택 폴더 이름과 하위 상대 경로를 포함한다. 개별 파일은 지정한 저장 폴더 아래에 들어간다.
3. 등록 파일과 경로를 확인한 뒤 저장한다. 기본 추가/갱신 방식은 같은 경로의 파일을 교체하고 기존의 나머지 파일을 보존한 새 버전을 만든다. 전체 교체는 선택한 CSV들만 포함한 새 버전을 만든다. 이전 버전은 두 방식 모두 보존한다.
4. 버전을 선택한 뒤 전체 다운로드로 ZIP을 받는다. 압축 해제하면 해당 버전의 CSV 폴더 구조가 복원된다. 파일별 다운로드는 해당 CSV의 원본을 받는다.
5. 통합 검색으로 제품·로드케이스·이름을 찾거나 제품/로드케이스 필터를 함께 사용한다.

한 버전은 최대 200개 CSV, 총 25 MiB까지 저장한다. CSV가 아닌 파일과 빈 폴더는 수집 대상이 아니다. CSV 내용의 인코딩, BOM, 줄바꿈, 숫자 표현은 변환하지 않고 원본 바이트로 저장한다. 파일 내용 편집이나 모델링 프로그램 실행은 이 라이브러리의 기능에 포함하지 않는다.

## 저장·권한 계약

카드 메타데이터, 버전 메타데이터, 파일의 상대 경로·SHA-256·크기·바이너리 원본을 DB에 저장한다. 서버의 임의 로컬 경로 또는 SPDM 결과 저장소에 복사하지 않는다. DB 백업에는 라이브러리 파일도 포함되며, 전체 CSV 다운로드는 DB 백업을 대신하지 않는다.

`/api/modeling-templates` 기능 API는 기존 권한 체계의 조회 권한과 카탈로그 관리 권한을 적용한다. UI도 서버의 `can_manage` 응답을 따른다. 같은 카드에 동시 저장하면 최신 버전을 확인하여 충돌을 알리고 다른 사용자의 변경을 덮어쓰지 않는다.

다운로드 ZIP 경로는 Windows에서 복원 가능한 상대 경로만 허용한다. 상위 경로 이동, 절대 경로, 예약 파일명, 대소문자만 다른 중복 및 파일/폴더 충돌을 거부한다. 파일과 버전은 하나의 트랜잭션으로 저장하므로 일부 파일만 등록된 버전은 노출하지 않는다.

## 업데이트

기존 배포 브랜치에서 pull한 후 프런트엔드를 다시 배포한다. PostgreSQL 설치는 앱을 중지하고 `0021_modeling_templates`까지 migration을 적용한 뒤 재시작한다. DuckDB는 시작 시 호환 스키마를 준비한다. 자세한 명령은 [사내 Git 업데이트](windows-git-update.md)를 따른다.
