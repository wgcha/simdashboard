# 내 작업 탭 통합과 와이드 화면 개선

- 기준일: 2026-09-08
- 상태: 구현·검증 완료
- 대상: 현재 의뢰 중심 GUI의 후속 개선

## 목표와 결정

‘의뢰 개요 / 작업 실행 / 결과 등록 / 결과 검토’를 같은 의뢰 작업공간의 네 탭으로 표시한다. 탭을 바꿔도 의뢰 제목, 상태, 담당자, 프로젝트·의뢰·하중 경우 선택 영역과 사이드바의 ‘내 작업’ 선택이 유지된다. 각 기능의 기존 URL, 권한, 결과 연결 계약은 유지한다.

기본 탐색은 ‘결과 대시보드 / 내 작업 / 새 의뢰’로 단순화한다. 현재 실행·등록은 독립된 전체 관리 기능보다 같은 의뢰의 중복 진입 경로이므로 사이드바에서 제거한다. 기존 URL과 기능 모듈은 유지하며, 향후 여러 의뢰를 실제로 일괄 관리하는 기능이 생길 때 별도 ‘전체 작업’ 메뉴를 검토한다.

2560×1440에서는 화면을 일괄 확대하지 않고 본문 폭, 글자, 행 높이를 조정한다. 실제 브라우저 폭에 따라 작업 본문과 참고 영역을 나누고, 좁은 폭에서는 한 열로 전환한다. 공간을 채우기 위한 허구 정보나 새 통계 카드는 추가하지 않는다.

## 구현 순서

1. 공통 의뢰 헤더와 활성 탭 모델을 네 화면에 적용하고 문맥 유지·뒤로 가기·직접 URL 접근을 연결한다.
2. 실행·등록의 의뢰 내부 모드에서 중복 선택기와 제목을 줄인다. 재사용 가능한 기능 모듈의 독립 모드는 기존 선택 기능을 유지한다.
3. 메뉴 그룹, 공통 간격·글자·입력 높이, 넓은 본문과 좁은 화면의 전환을 정리한다. 기존 사용자 글자 크기 조절과 테마 선택을 존중한다.
4. 기능 회귀와 실제 브라우저 화면을 검증한다.

## 완료 기준

- 네 탭의 의뢰 헤더와 활성 표시가 일관되고 선택한 의뢰가 바뀌지 않는다.
- 실행·등록 탭에서 ‘내 작업’ 메뉴가 유지된다. 하중 경우가 없는 의뢰도 실행·등록 화면에 진입할 수 있다.
- 결과 등록에서 결과 검토로 이동할 때 프로젝트·의뢰·하중 경우·Run이 연결된다.
- 직접 URL, 새로고침, 뒤로 가기와 기존 권한 제한이 유지된다.
- 2560×1440, 2048×1152 및 1707×960 정도의 유효 폭과 모바일에서 가로 넘침·겹침이 없다.
- 글자 크기 설정을 올렸을 때 주요 메뉴·탭·입력·본문에도 반영된다.
- TypeScript/Vite 빌드, 관련 구조·라우팅 검사 및 영향 범위 E2E를 통과한다.

## 보존과 검증 기록

변경 전 UI 소스는 `backups/unified-workspace-before-20260908/source-before.zip`에 보관한다. 미커밋 Windows 시작 지연 보완은 별도 패치와 모듈 파일로 함께 보존한다. DB와 사용자 환경 파일은 이번 UI 수정 대상이 아니다.

## 반영 내용

- `app/workspace/RequestWorkspaceShellHeader.tsx`에서 공통 의뢰 헤더·탭·Run 선택기를 조립한다. 기능별 실행·등록 모듈은 내부 동작을 유지한다.
- 실행·등록의 내부 모드에서는 중복 제목과 선택기를 제거하고 의뢰 상단의 선택기를 사용한다. 실행의 데모 표시와 실제 결과가 아니라는 안내는 유지한다.
- 경로 이동이 완료될 때까지 상태→URL 동기화를 보류해 실행/등록에서 결과 검토로 이동할 때 이전 경로로 되돌아가지 않게 한다.
- 등록 대상 변경 중에는 등록을 비활성화하고 이전 검증 결과를 지운다. 파일 읽기·예제 다운로드·검증·등록의 늦은 응답은 시작 문맥과 현재 문맥이 일치할 때만 화면에 반영한다.
- 실행·등록에서 검토로 이동하기 전 현재 결과 조회를 확인한다. 조회 실패는 선택한 문맥을 유지하며 오류로 표시하고, 과거 Run 선택은 그대로 전달한다. 하중 경우가 없으면 이 조회를 생략한다.
- 1440px 이상에서는 실행 상세와 작업 순서를 좌우로 배치한다. 등록 화면의 고정 최대 폭을 해제하고 공통 헤더와 본문 여백을 맞춘다. 작은 화면에서는 한 열과 스크롤 가능한 탭을 사용한다.
- 기존 14pt 기본값과 사용자 글자 크기 설정을 유지하며 메뉴·탭·컨트롤에 반영한다. 기본 메뉴는 항상 표시하고 보조 설정·예제는 펼쳐서 연다.

최종 미해결 회귀 없음. 브라우저 검사는 격리된 테스트 DB에서 수행했고, 125%·150% 배율에 해당하는 유효 viewport 폭을 검증했다. 실제 사내 모니터의 Windows 배율 설정 자체를 변경해 시험한 것은 아니다.

`docs/README.md`와 기존 GUI 기준 문서에 후속 변경의 우선순위를 반영했다. 과거 ‘작업 도구’ 메뉴 설계는 이번 통합 탭 기준을 대체하지 않는다.

새 패키지나 DB migration은 추가하지 않았다. 기존 설치·실행 배치와 루프백 주소 계약을 유지한다.
