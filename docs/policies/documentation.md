# 문서 관리 정책

## 문서 역할

- 정책은 현재 여러 기능에 공통으로 적용하는 규칙을 기록한다. 기존 배포 정책과 ADR은 원래 경로를 유지한다.
- 기능 문서는 현재 코드와 지켜야 할 동작·권한·데이터 계약을 기록한다.
- 계획은 아직 남은 승인 작업만 기록한다. 완료한 단계별 구현 계획과 검증 내역은 보관한다.
- 작업 로그는 날짜순 활동·검증 기록이다. 현재 사용 절차나 계약의 대체 문서로 쓰지 않는다.
- archive는 과거 결정과 완료 이력을 보존한다. 기본 작업 탐색 경로에서는 제외한다.

## 탐색과 갱신

새 문서는 공통 규칙이면 `policies/`, 현재 기능이면 `features/`, 진행 계획이면 `plans/`, 완료·대체 기록이면 `archive/<연도>/`에 둔다. 기존 아키텍처와 ADR은 경로를 유지한다. 같은 계약을 여러 문서에 복제하지 않고 기준 문서 한 곳에 정의한 뒤 링크한다. 단순히 줄 수를 줄이기 위해 문서를 쪼개지 않는다.

계획이 완료되면 확정된 동작을 현재 기능 문서에 반영하고 계획·검증 상세를 보관한다. 보관 문서와 전체 작업 로그는 기본 탐색에서 제외한다. 하위 에이전트에는 관련 경로와 필요한 계약만 전달한다. 긴 테스트 로그·스크린샷·자동 생성 보고서는 기준 문서에 복사하지 않고 산출물 위치를 링크한다.

작업은 [문서 지도](../README.md)에서 시작해 해당 영역의 현재 기준과 기능 문서를 먼저 읽는다. 조건에 맞는 계획 또는 상세 카탈로그가 필요할 때만 링크를 따라간다. 계획의 제목에 `plan`이 있다는 이유만으로 현재 계약으로 취급하지 않는다.

코드와 문서가 다르면 실행 가능한 코드·migration·검증 결과와 승인된 ADR, 명시된 현재 기준 문서를 대조하고 실제 변경과 함께 기준 문서를 갱신한다. 기능 문서는 상태, 기준일, 구현 경로, 남은 범위를 분리해 적는다. 과거 문서를 이동할 때 들어오는 링크를 유지하거나 새 기준으로 고친 뒤 보관본 링크를 남긴다.
