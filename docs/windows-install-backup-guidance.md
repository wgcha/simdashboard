# Windows 설치·백업·복원 안내 기준

- 기록일: 2026-09-10, 배포 경로 갱신: 2026-09-14
- 상태: 설치와 DB 이관을 구분하는 사용자 안내 기준
- 현재 배포: [배포 정책](windows-deployment-policy.md), [소스 설치](windows-one-click-deployment.md), [폐쇄망 설치](windows-server-offline-installation.md)를 우선한다.

2026-09-14에 `deploy`는 전용 런타임 준비와 비파괴 PostgreSQL 준비를 호출하도록 수정했다. 일반 배포에서 기존 `setup.ps1` Fresh/Transfer 메뉴를 호출하지 않으며, 비대화형 DB 준비 옵션도 전달한다. 아래 2026-09-10 불일치 기록은 과거 상태다. `backup.bat` / `restore.bat`는 여전히 미구현이며 기존 DB 전송 도구와 구분한다.

## 사용자 요청과 명칭

사용자는 현재 최초 설치에 `deploy.bat`, 이후 업데이트에 `update.bat`를 사용하고 있다. 다른 PC로 DB를 옮기려면 원본에서 백업을 만들고 파일을 복사한 뒤 대상에서 복원해야 하므로, 이 작업을 `setup`이라는 이름으로 안내하지 않기를 원한다. `backup`, `restore`, `transfer`처럼 목적을 드러내는 이름을 사용한다. `migration`은 DB 스키마 변경과 혼동될 수 있으므로 사용자용 PC 이관 진입점 이름으로는 우선하지 않는다.

다음은 대화에서 제안하여 문서화한 정리 방향이다. 새 배치 파일이 구현되었다는 뜻은 아니다.

| 진입점 | 정리할 역할 | 현재 상태 |
|---|---|---|
| `deploy.bat` | 프로그램 최초 설치 | 파일 존재. 아래 `setup` 호출 불일치 확인 필요 |
| `update.bat` | 프로그램 업데이트와 기존 데이터 유지 | 파일 존재. 업데이트는 다른 PC의 DB를 가져오는 기능이 아님 |
| `start.bat` / `stop.bat` | 프로그램 실행 / 종료 | 파일 존재 |
| `backup.bat` | DB와 관리형 첨부파일을 검증 가능한 백업 묶음으로 저장 | 제안 명칭, 미구현 |
| `restore.bat` | 백업 묶음을 선택해 현재 PC에 복원 | 제안 명칭, 미구현 |
| `setup.ps1` | 설치기가 호출하는 내부 실행 환경 준비 | 향후 정리 방향. 현재는 DB 선택 기능도 포함 |

## 향후 사용자 안내

1. 이미 설치해서 사용 중이면 `setup`을 추가로 실행하라고 안내하지 않는다.
2. 소스 복사·최초 설치·업데이트만으로 다른 PC의 DB 데이터가 자동 이관되지는 않는다. 프로그램은 해당 PC에 설정된 DB 연결을 사용한다.
3. 서버의 기존 데이터를 유지하는 경우와 원본 PC의 데이터로 대상 DB를 교체하는 경우를 먼저 구분한다. PC 간 이관은 두 DB의 자동 병합을 의미하지 않는다.
4. 목표 사용 흐름은 **원본 PC에서 백업 → 백업 폴더를 대상 PC로 복사 → 대상 PC에 프로그램 최초 설치(미설치 시) → 대상 PC에서 복원 → 실행·데이터 확인**이다. `backup.bat` / `restore.bat` 구현 전에는 이 이름을 실제 실행 명령으로 제시하지 않는다.
5. 복원 시 기존 대상 DB가 있으면 교체 대상을 명확히 보여주고, 교체 전 자동 백업·검증을 수행하도록 정리한다. 이는 향후 사용자 흐름 요구사항이며 새 배치의 검증 완료 기록이 아니다.
6. 실제 이관 요청이 오면 해당 소스 버전의 내보내기·가져오기 옵션과 백업 범위를 먼저 확인한다. DB 연결 비밀번호나 인증 키를 대화·문서에 기록하지 않는다.

## 2026-09-10 당시 구현과 불일치 (과거 기록)

2026-09-10 파일 확인 기준:

- `deploy.ps1`은 `setup.ps1`을 내부 호출한다. 호출부는 실행 환경 준비 전용으로 가정하며 `-SkipFrontendBuild`, `-NetworkMode` 옵션을 전달할 수 있다.
- 현재 `setup.ps1`에는 위 두 옵션이 없고 `Fresh`, `Transfer`, `Keep` 메뉴가 있다. 메뉴는 프록시 설정과 의존성 설치 이후 표시된다. 따라서 메뉴 확인만을 위해 실행하는 것도 읽기 전용 동작이 아니다.
- `deploy.ps1 -NonInteractive`도 `setup.ps1`로 전달되지 않으므로 설치 전체가 비대화형이라고 안내하지 않는다.
- 현재 `Fresh`는 DB 초기화 도구에 `--replace-existing`을 전달한다. `Transfer`도 검증 후 가져오기 도구에 해당 옵션을 전달한다. 기존 데이터가 있는 사용자에게 일반 설치 준비 단계로 무조건 실행하도록 안내하지 않는다.
- `Keep`은 기존 PostgreSQL 연결 검증이다. 다른 PC의 데이터를 가져오지 않는다.
- 실제 PostgreSQL PC 이관 진입점은 `export-postgresql-transfer.ps1`과 `import-postgresql-transfer.ps1`이다. 가져오기 래퍼는 `-Bundle`, `-ValidateOnly`를 지원한다. 세부 절차는 [PC 간 이관 가이드](postgresql-pc-transfer-guide.md)를 참고하되 설치 단계는 이 문서의 불일치를 우선 확인한다.
- 독립 `import-postgresql-transfer.ps1`은 `--replace-existing`과 `--backup-dir`을 전달하지 않는다. `setup`의 `Transfer` 경로와 동일한 교체 동작이라고 안내하지 않는다. 배포 중 자동 백업 역시 사용자용 수동 백업·복원 진입점과 구분한다.
- 전송 번들은 DB dump와 관리형 `backend/assets`를 다룬다. `.env`, DB 비밀번호, `AUTH_SECRET_KEY`는 포함하지 않는다. 외부 경로의 모든 업무 파일까지 자동 포함된다고 안내하지 않는다.

## 후속 구현 시 확인할 일

- `deploy`와 `setup`의 역할 및 옵션을 먼저 맞추고, 환경 준비와 DB 교체·이관 동작을 분리한다.
- 기존 전송·검증·복구 도구를 재사용하는 `backup.bat` / `restore.bat` 진입점을 검토한다.
- 빈 대상 PC와 기존 DB가 있는 대상 PC 모두에서 백업, 복원, 실패 시 원상 복구, 계정·첨부파일 보존을 검증한다.
- 구현과 검증이 끝난 후 이 문서의 미구현 표시, 설치 안내, PC 이관 가이드를 함께 갱신한다.
