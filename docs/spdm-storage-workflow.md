# SPDM 저장 폴더 연계

- 기준일: 2026-09-08
- 상태: 구현 완료, Windows 로컬 검증 통과
- 요구사항: GitHub [#13 폴더구조](https://github.com/wgcha/simdashboard/issues/13), [#14 확장자](https://github.com/wgcha/simdashboard/issues/14)

## 구현 범위

1. 기존 소스와 미커밋 변경을 `backups/spdm-storage-before-20260908/`에 보존한다.
2. SPDM 전용 저장소 설정·폴더 탐색·의뢰 연결·파일 저장 서비스를 독립적으로 추가한다.
3. 결과 등록 화면에서 저장 위치를 확인하고 업로드하며, 결과 검토에서도 연결된 원본을 열 수 있게 한다.
4. 직접 복사 후 새로고침, 중복 방지, 권한, Windows 파일 복사 중 처리와 실패 복구를 검증한다.
5. Git에 반영하고 사내 PC 업데이트 절차를 제공한다.

## 연결 기준

저장소의 최상위 폴더 아래 `Project_번호_모델_단계/WR_번호_SimType1또는2/CAE/…` 구조를 사용한다. Project는 프로젝트, WR은 의뢰, CAE 아래 모델·해석·Scene 경로는 하중 경우에 연결한다. 폴더 연결은 DB에 보존한다. 이름이 비슷하다는 이유로 기존 의뢰를 임의로 합치지 않는다. 기존 의뢰에 연결할 때는 결과 등록 화면에서 해당 하중 경우의 상대 경로를 지정한다.

사용 환경 해석은 `CAE/모델/Deflection` 같은 해석 폴더가 기준이다. 유통 환경은 `CAE/모델/Drop/해석명/INDIVIDUAL/Scene폴더`처럼 Scene까지 포함한다. `__LIB_TEMPLATE__`와 임시 파일은 결과로 등록하지 않는다.

결과가 없어 `WR` 폴더만 있는 의뢰도 하중 경우 0개의 대기 의뢰로 발견한다. 기존 DB 의뢰를 재사용하려면 **전체 새로고침 전에** 해당 의뢰의 하중 경우에서 폴더를 연결한다. 이후 같은 Project/WR 아래 새 해석을 발견하면 그 기존 의뢰를 재사용한다. 새로 구성하는 저장소는 최상위 경로 설정 후 전체 새로고침을 바로 실행하면 된다.

## 파일별 저장 위치

아래에서 `해석 기준 폴더`는 선택한 하중 경우에 연결된 해석 또는 Scene 폴더다. 업로드 화면이 실제 상대 경로를 표시한다.

| 파일 종류 | 저장 위치 | 처리 |
|---|---|---|
| 수치 결과 CSV·JSON | `해석 기준 폴더/results/` | 지원 결과 형식을 검증한 뒤 Run으로 등록 |
| H3D·TXT·PKL 원본 | `해석 기준 폴더/solver/` | 원본 파일 연결·다운로드; PKL을 역직렬화하거나 실행하지 않음 |
| 그림·영상·모델 뷰 파일 | `해석 기준 폴더/media/` | 원본 파일 연결·다운로드 |
| FEM·RAD·XML·HM·MDL·PRT·X_T | `해석 기준 폴더/inputs/` | 해석 입력·CAD 원본 연결 |
| PDF·PPT·PPTX | `WR 폴더/보고서/CAE 아래의 전체 상대 경로/` | 모델·해석명·개별/누적·Scene을 모두 보존하여 보고서 연결 |

기존 해석 폴더에 직접 저장된 파일도 확장자를 분류해 연결하며 파일을 이동하지 않는다. CSV·JSON이라는 확장자만으로 모든 파일을 수치 결과로 해석하지 않는다. 지원 형식과 맞지 않으면 오류 이유를 표시한다. H3D·보고서·해석 입력 파일 자체를 수치 데이터로 변환하거나 실행하지 않는다.

## 두 가지 등록 흐름

**웹에서 등록:** 의뢰 → 결과 등록 → 하중 경우 선택 → 저장 폴더 연결 → 저장 위치 확인 → 파일 업로드. 원본을 저장한 뒤 수치 결과를 등록한다. 동일 이름·동일 내용은 재사용하며, 내용이 다른 기존 파일을 덮어쓰지 않는다.

**폴더에 직접 저장:** 연결된 해석 폴더에 파일 저장 → 복사 완료 → `저장 폴더 새로고침`. 전체 새로고침은 새 프로젝트·의뢰·하중 경우를 탐색하고, 하중 경우의 새로고침은 해당 연결 폴더만 처리한다. 브라우저 F5는 화면을 다시 읽는 동작이므로 파일 탐색·등록에는 저장 폴더 새로고침 버튼을 사용한다.

같은 경로·같은 내용은 새 Run을 만들지 않는다. 내용이 달라지면 기존 결과 이력을 보존하고 새 Run으로 처리한다. 원본 파일을 삭제해도 과거 Run은 삭제하지 않는다. 파일 저장 후 결과 검증이나 DB 등록이 실패하면 원본을 보존하여 수정·재시도할 수 있게 한다.

## 저장소 설정과 기존 수집 기능

관리자가 저장소 최상위 경로를 설정한다. 환경변수 `SIMDASH_SPDM_ROOT`를 지정한 배치는 해당 설정을 우선한다. 사내 공유 경로는 서버를 실행하는 Windows 계정이 접근할 수 있어야 한다. 사용자에게 보이는 파일 경로는 저장소 기준 상대 경로를 사용한다.

현재 업로드 한도는 원본 파일당 512 MiB, 수치 CSV·JSON은 5 MB다. Windows는 파일을 읽는 동안 기존 writer와 쓰기 공유를 배제하며, 작성 중 파일은 대기로 남긴다. 업로드는 같은 폴더의 임시 파일에 기록한 뒤 기존 파일을 덮어쓰지 않는 rename으로 게시한다. 다른 플랫폼의 직접 저장 수치 파일은 해당 파일의 SHA-256과 `state: READY`를 포함한 `<파일명>.simdashboard-complete.json`을 마지막에 게시해야 한다. Windows의 일반적인 직접 파일 복사는 이 보조 파일을 사용자가 만들 필요가 없다.

기존 `SIMDASH_IMPORT_ROOT`의 canonical manifest 수집은 별도 기능이다. 기존 read-only root, readiness marker, POSIX snapshot 및 publisher 계약을 유지한다. 새 SPDM 저장소는 의뢰 탐색과 사용자가 요청한 파일 쓰기를 위한 별도 adapter이며 기존 canonical Windows 제한을 해제하지 않는다.

## 검증 기록

백엔드 51개 검사와 실제 브라우저의 업로드·직접 복사·다운로드·수치 조회를 검증했다. 상세 결과와 화면은 [저장소 검증 기록](spdm-storage-validation.md)에 정리했다. 사내 공유 폴더의 실제 접근과 파일 게시 동작은 사내 배치 후 확인한다.

업데이트 방법은 [사내 PC Git 업데이트](windows-git-update.md)를 따른다.
