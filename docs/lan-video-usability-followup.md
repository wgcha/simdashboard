# 사내 접속과 영상·와이드 화면 보완

2026-09-14 사용자 요청. 기존 대시보드 위젯 방식과 저장된 배치는 유지한다.

## 사내 접속

- 별칭이나 사내 DNS를 등록하지 않는다. 실행 서버의 실제 컴퓨터 이름과 사내 IP로 접속한다.
- 기본 주소는 `http://컴퓨터이름/home/` 또는 `http://사내IP/home/`이다. `/home` 입력은 슬래시가 있는 경로로 연결된다.
- 인증된 Windows 설치에서 `WINDOWS_WEB_HOST`를 생략하면 사내 수신 주소 `0.0.0.0`을 사용한다. 명시한 수신 주소·경로는 설치와 업데이트 후에도 유지한다.
- 인증 없는 개발 환경은 로컬 수신을 유지한다. 기존 로그인·계정·DB 설정은 변경하지 않는다.
- 실행 창에 컴퓨터 이름과 IP 주소를 표시한다. 다른 PC에서 컴퓨터 이름을 찾지 못하면 IP로 접속한다. OS 이름 확인·회사 방화벽 정책을 앱이 변경하지 않는다.
- 상세 설정은 [사내 접속 기본값](lan-access-persistence.md)을 참고한다.

## 영상 배치

이전 기능은 편집 모드의 설정 아이콘 안에 있어 찾기 어려웠다. 결과 화면에 `영상 배치 편집` 버튼을 추가하고, 영상 위젯의 설정 버튼에 `영상 배치`를 표시한다.

사용 순서: **결과 검토 → 영상 배치 편집 → 영상 배치 → 가로·세로 선택 → 설정 완료 → 레이아웃 저장**.

- 2×2, 3×2, 4×3, 5×4 빠른 선택과 개별 가로·세로 설정을 제공한다.
- N×M 합계는 최대 20개다. 현재 배치를 `가로 N × 세로 M`으로 표시한다.
- 저장 전에는 편집안이며 기존 저장 경로를 사용한다. 새로고침 후에도 설정을 유지한다.
- 조회자에게 편집 진입 버튼을 제공하지 않는다. 작은 화면은 읽을 수 있는 열 수로 표시하되 저장된 N×M은 유지한다.

## 와이드 모니터

확대 보기의 기존 최대 1440×860 제한을 제거하고 브라우저 가용 영역을 사용한다. 큰 화면에서는 5×4 영상의 행 높이를 조정하여 더 많은 영상을 함께 볼 수 있게 한다. 화면이 작거나 행 수가 많으면 스크롤을 유지한다.

화면 사용 면적의 개선이며 영상 원본의 픽셀 해상도를 증가시키지 않는다. 더 선명한 영상은 고해상도 원본이 필요하다.

## 검증 범위

실제 서버의 컴퓨터 이름/IP로 `/home` 로그인 화면과 API 연결을 확인한다. 영상 설정·저장·새로고침, 조회 권한, 와이드/노트북/모바일 화면은 운영 DB와 분리한 Playwright 환경에서 검사한다. 다른 직원 PC의 방화벽 통과는 별도로 확인해야 한다.


검증 결과:

- Windows 설정 Python 테스트 29개, Windows 웹 설정 자체 검사, LAN 프록시 자체 검사 통과.
- 실제 `http://laptop-tjp4higd/home` 및 `http://192.168.45.146/home`의 Chromium 로그인 화면: HTTP 200, 제목 확인, 빈 화면·Vite 오류 화면·페이지 런타임 오류 없음.
- 영상 설정·권한 E2E 최종 2개 통과(38.3초), 기존 추천 배치 회귀 3개 통과. 최초 상태 표시 검사의 접근성 이름 선택자를 실제 텍스트 선택자로 수정했다.
- 2560×1440에서 5×4 전체 카드가 외부 스크롤 없이 표시되고 20개 영상 재생 준비 상태를 확인했다. 1366×768에서 확대 닫기, 390×844에서 한 열 표시와 N×M 저장 유지 확인.
- 타입 포함 빌드 및 아키텍처 검사(164개 소스 파일) 통과. 기존 500kB 번들 경고 유지.
- Browser plugin not available: 저장소의 Playwright를 사용했다. 검증 캡처·로그는 저장소 밖 Codex visualization 작업 폴더의 `lan-video-qa`에 보관한다.
