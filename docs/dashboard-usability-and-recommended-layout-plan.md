# 결과 분석 사용성 개선 — 실행 계획

- 갱신일: 2026-09-11
- 상태: 1차·영상 배치 설정·2단계 비교 근거/설계 검토 흐름 구현 및 검증 완료
- 이 문서는 앞서 작성한 추천 레이아웃 3종 중심 후보안을 대체한다.

## 1. 합의한 목표

기능 수를 늘리는 대신 현재 결과로부터 문제를 발견하고, 원인 후보를 좁히고, 다음 설계·추가 해석 방향을 판단하기 쉽게 만든다. 기존 위젯 UI, 데이터 연결, 편집·저장 방식은 유지한다. 실제 근거로 확인된 사실과 원인 가설은 구분한다. 대시보드가 자동으로 근본 원인을 증명하거나 설계를 승인한다고 표현하지 않는다.

## 2. 최선의 사용 시나리오

| 순서 | 사용자 질문 | 기존 화면에서 할 일 |
|---|---|---|
| 결과 선택 | 어떤 조건의 결과인가? | 의뢰·하중 경우·Run·데이터 상태 확인 |
| 전체 파악 | 무엇이 문제인가? | 주요 값·단위·기준·FAIL 확인 |
| 근거 확인 | 어디서, 언제 발생했나? | 표·그래프·위치도·영상 읽기 |
| 비교 | 이전과 무엇이 다른가? | 기존 Run 비교로 변화와 조건 확인 |
| 해석 | 어떤 원인이 가능한가? | 관찰 사실과 원인 가설을 구분 |
| 다음 행동 | 무엇을 확인하거나 바꿀까? | 기존 검토 의견에 추가 확인·설계 변경 방향 기록 |

예: 변형 기준 미충족 → 위치와 발생 시점 확인 → 관련 영상·그래프 확인 → 이전 Run과 비교 → 원인 후보와 검증 방법 기록. 상관관계를 인과관계로 단정하지 않는다.

## 3. 구현 우선순위

1. 잘 보이게: 영상·그래프·표의 잘림, 지나치게 작은 표시, 확대 후 복귀를 해결한다.
2. 간결하게: 중복 설명을 줄이고 값·단위·기준·판정·출처 경고를 유지한다.
3. 분석 흐름에 맞게: 요약 → 주요 근거 → 상세 정보의 읽는 순서를 정돈한다.
4. 대표 사례에서 검증한 뒤 추천 배치를 검토한다. 세 가지 템플릿이나 자동 재배치를 먼저 확정하지 않는다.

## 4. 이번 1차 개발 범위

| 담당 | 변경 | 수용 기준 |
|---|---|---|
| Astra/루트 | 문서 재정리, 결과 첫 화면의 FAIL 집계 문구·필터 일관성 | 사람 검토 상태와 혼동하지 않음 |
| Luna | 기존 영상 위젯의 표시 밀도·목록 탐색 및 넘침 개선 | 서버 목록/판정 의미 유지, 선택 영상 접근, 작은 화면 조작 가능 |
| Terra | 기존 분석 위젯 확대·복귀, 기존 의견 입력 안내 개선 | 데이터·배치 설정 보존, Esc·초점 복귀, 사실/가설 구분 |
| Sol | 코드·계약 검수 | snapshot·Run·데모 의미 보존, 기존 기능 회귀 점검 |

서버/API/DB 구조 변경 없이 기존 렌더러와 상태 흐름을 활용한다. 그래프·영상·표의 관련성 자동 추론, 새로운 원인 분석 엔진, 별도 승인·검토 상태는 추가하지 않는다.

## 5. 화면 원칙

- 한눈에 보인다는 것은 모든 자료를 한 화면에 축소하는 뜻이 아니다. 주요 정보는 즉시, 세부 근거는 쉽게 확인할 수 있어야 한다.
- 기존 위젯 안에서 적정 크기와 확대를 제공하고 복귀 시 원래 문맥을 유지한다.
- 영상이 많으면 읽을 수 있는 표시 단위와 전체 목록 탐색을 구분한다. 재생 제어 대상은 명확히 표시한다.
- 요약 지표는 같은 값과 문구를 반복하지 않는다. 단위·적용 기준·선택 Run·데모·중요 데이터 경고는 숨기지 않는다.
- FAIL 집계는 ‘기준 미충족’으로 표시한다. 상한 초과뿐 아니라 하한·범위 기준도 있을 수 있어 ‘기준 초과’로 일반화하지 않는다.
- 결과 없음·판정 없음·조회 실패를 구분한다. 데이터 없음은 0이나 PASS가 아니다.
- 기존 검토 의견에서 관찰 사실 / 원인 가설 / 추가 확인 / 설계 변경 방향을 기록하도록 안내한다. 새로운 입력 항목이나 필수 절차를 강제하지 않는다.

## 6. 유지할 계약

- 위젯 ID·타입·설정·좌표·크기·보고서 포함 설정을 사용자 모르게 변경하지 않는다.
- 기존 의뢰 snapshot과 업무 유형 버전은 불변이다. 읽기 전용 화면에 편집 권한을 추가하지 않는다.
- 고정 snapshot의 최신 Run 계약과 영속 분석 페이지의 선택 Run 계약을 구별한다.
- 비교는 동일 변수·단위 등 기존 조건을 따른다. 서로 다른 조건의 결과를 같은 값으로 요약하지 않는다.
- 낙하 예제 영상의 합성 평가임을 계속 표시하고 실제 solver 결과로 오인시키지 않는다.
- 기존 재생·페이지 전환·오류 격리를 유지한다. 표시 범위가 바뀌면 재생 버튼이 무엇을 제어하는지 명시한다.
- 사용자 변경이 많은 작업 트리이므로 관련 없는 파일은 수정·복구하지 않는다.

## 7. 후속 후보 — 이번 완료 조건 아님

- 실제 업무별 핵심 위젯과 기본 배치 검증 후 추천 미리보기.
- 비교 악화 필터, 표와 그래프의 근거 이동, 검토 초안 보존은 아래 2단계로 진행한다.
- 축 범위 통일, 시간·위치 매핑이 검증된 경우의 영상/그래프 연동.
- 지표별 정의가 있는 경우 기준 여유 표시.

기능 추가는 대표 사례에서 현재 조작으로 해결되지 않는 문제가 확인될 때 선택한다.

## 8. 검증

- 기존 프로젝트 Playwright로 결과 첫 화면 → 상세 결과 → 영상 탐색/재생 및 위젯 확대 → 복귀를 확인한다.
- 데스크톱과 작은 화면에서 잘림·가로 넘침·버튼 접근·초점 복귀를 확인한다.
- 결과 대시보드 FAIL 집계와 필터가 일치하는지 확인한다.
- 확대 전후 결과와 위젯 설정이 유지되는지 확인한다.
- 타입 검사·빌드·아키텍처 검사와 관련 브라우저 회귀를 수행한다.
- Browser plugin/browser skill이 세션에 없어 기존 Playwright 검증 경로를 사용한다.
- 실제 사용자의 원인 분석 시간 단축이나 설계 품질 향상은 이번 테스트만으로 달성했다고 주장하지 않는다.

## 10. 구현·검증 기록

### 구현 범위

- FAIL 집계 명칭을 ‘기준 미충족’으로 변경하고 필터의 대소문자 처리를 일치시켰다. 기존 ‘결과 보유’는 최신 Run 존재 건수라는 의미를 유지한다.
- 상세 요약에서 ‘판정 없음’, ‘기준 미충족 N개 중 첫 항목’, ‘표시 항목의 기준’을 명시한다. Custom 요약은 Run 전체 scalar 범위와 일치시킨다.
- 공통 WidgetCard에 확대/복귀를 추가한다. 같은 DOM을 유지해 위젯 내용·영상 위치를 보존하고, Esc·초점 복귀·일반 article/확대 dialog 역할을 제공한다. 편집 중에는 확대를 제공하지 않는다.
- 영상은 4개씩 탐색한다. 데스크톱 확대 화면은 2×2 영상과 독립 스크롤 요약을 사용하고, 모바일에서는 영상을 먼저 배치한다. 파일 정보·다운로드는 접어서 열 수 있다.
- 표시 묶음을 바꾸면 이전 영상을 정지한다. 요약 Scene 선택은 해당 묶음으로 이동한다. 합성 예제 경고·판정·단위·기준은 유지한다.
- 기존 검토 의견 안내를 관찰 사실 / 원인 가설 / 추가 확인 / 설계 변경 방향으로 구분했다. 분석 데이터의 근본 원인을 자동 생성하지 않는다.
- 기능을 DropVideoParts, WidgetFocusFrame 모듈로 분리하고 기존 대형 파일 제한을 유지했다. 새 의존성·API·DB 변경 없음.

### 시각 검증에 따른 보정

처음에는 6개 표시로 구현했으나, 실제 1366×768 캡처에서 아래쪽 영상이 잘리는 것을 확인했다. 4개 표시, 영상 영역 높이 제한, 요약 독립 스크롤, 파일 정보 접기로 보정했다. DOM 가시성 테스트만으로 화면 적합성을 확정하지 않았다.

### 제한과 후속

- 1366×768 데스크톱에서는 표시 영상 4개의 프레임이 확대 화면 안에 들어오는지 검사한다. 작은 화면은 모든 영상을 억지로 축소하지 않고 세로 탐색한다. 상세 확인은 기존 개별 영상 전체화면도 활용할 수 있다.
- 확대는 공통 WidgetCard 경로에 적용한다. snapshot 자체는 계속 읽기 전용이며, 전용 비교 화면과 별도의 범용 snapshot 렌더러를 새 구조로 통합하지 않았다.
- 검증 데이터는 예제 환경이다. 실제 사내 해석 데이터의 원인 추적 효과는 후속 사용자 검증 대상이다.
- 추천 배치 엔진·자동 원인 추론·신규 검토 절차는 이번 구현에 포함하지 않았다.

### 검증 결과

- `pnpm.cmd --dir frontend run build -- --configLoader runner`: 통과. 기존 500 kB 초과 번들 경고는 남아 있다.
- `pnpm.cmd --dir frontend run check:architecture`: 통과 (145 source files).
- 결과 대시보드·영상·확대 관련 9개 E2E 통과 후, 시각 보정한 영상·확대 5개를 최종 재검증하여 모두 통과 (58.0초).
- Playwright Chromium, 격리 서버 `http://127.0.0.1:15173`/API 18000. 데스크톱 1366×768·1505×1045 및 모바일 390×844 등 확인.
- 실제 영상 재생·오류 격리·표시 묶음 선택·위젯 이동/크기/저장/복원·확대 DOM/재생 위치 보존·Escape/초점·판정 필터 검증.
- 위젯 집중 보기 테스트 pageerror 없음, 실제 화면과 가로 넘침 및 영상 프레임의 화면 내 위치 확인. 의도적으로 재생 실패를 주입하는 테스트의 네트워크 오류는 별도 정상 시나리오다.
- QA 캡처와 로그는 저장소 밖 Codex visualization 작업 폴더의 `dashboard-qa`에 보관했다.
- 테스트 메뉴 준비 대기와 작업계획 없는 기존 fixture 기대값을 현재 계약에 맞게 수정했다. 테스트 통과만을 위해 제품의 권한·실행 계약을 변경하지 않았다.

## 2026-09-11 영상 가로·세로 설정 확장

- 기존 2×2를 기본값으로 유지하고 영상 위젯 설정에서 가로 열 수·세로 행 수를 개별 선택하도록 추가했다.
- videoColumns/videoRows를 기존 레이아웃 저장으로 보존한다. 최대 20개 조합이며, 한 축 변경 시 반대 축은 그대로 유지하고 초과 조합은 선택할 수 없다.
- 선택 Scene을 기준으로 표시 묶음을 계산하여 배치를 바꿔도 빈 페이지로 이동하지 않는다. 모바일은 표시 열을 줄이지만 저장값은 유지한다.
- 5×4처럼 많은 행은 최소 표시 높이와 내부 스크롤로 접근하며, 좁은 카드의 지표명·값은 줄을 나눠 표시한다.
- 영속 분석 페이지와 snapshot 렌더러가 같은 설정을 읽는다. 기존 snapshot의 편집 권한이나 불변성은 변경하지 않았다.
- 사용법: 대시보드 편집 → 영상 위젯 설정 → 가로/세로 선택 → 설정 완료 → 레이아웃 저장.

검증: 기존 영상·확대 E2E 5개와 새 배치 E2E 1개 통과. 5×4의 실제 5열·4행, 마지막 카드 스크롤 접근, 설정 저장·복원, 모바일 저장값 보존과 pageerror 없음 확인. 최종 빌드·아키텍처 검사 통과(기존 번들 크기 경고 유지).

## 2026-09-11 2단계 — 문제에서 비교 근거와 설계 검토로

사용 경로: 결과 대시보드 → 결과 검토 → Run 비교 → 문제 필터 → 변수 선택 → 연결된 시계열 또는 검토 의견.

| 순서 | 구현 | 의미와 수용 기준 |
|---|---|---|
| 문제 좁히기 | 전체·대상 기준 미충족·이전 대비 악화·비교 불가 필터 및 건수 | FAIL은 대상 판정, 악화는 PASS→FAIL만 의미한다. 값 증가를 일괄 악화로 해석하지 않는다. |
| 근거 확인 | 선택 변수의 기준/대상 값·단위·판정과 공통 시계열 이동 | 실제 동일 변수 키의 공통 시계열에만 연결한다. 연결 없는 경우 명시하며 영상·위치를 추측해 연결하지 않는다. |
| 비교 조건 확인 | 같은 하중 경우의 두 Run 및 출처·신뢰도 유지 | 동일 하중 경우가 solver·메시·입력 조건 전체의 동일성을 보증하지 않는다. |
| 다음 설계 검토 | 선택 근거를 기존 의견의 편집 가능한 관찰 초안으로 전달 | 관찰 사실 / 원인 가설 / 추가 확인 / 설계 변경 방향을 구분한다. 가설과 설계 후보는 사용자가 작성한다. |
| 문맥 유지 | Run 조합별 초안 보존 및 늦은 요청 무효화 | Run 전환 시 이전 결과·신뢰도·검토 의견·보고서 문맥이 섞이지 않아야 한다. |

기존 위젯 위치·저장·영상 가로/세로 설정과 API 응답 형식·DB 스키마는 유지한다. 기능별 모듈로 분리하며 추천 배치 엔진이나 자동 원인 추론을 추가하지 않는다. 위치·영상과 지표의 직접 연결은 명시적 매핑 계약이 마련된 뒤의 범위다.

검수에서 기존 공통 시계열 조회가 변수 키만 확인하고 단위가 다른 데이터도 결합하는 것을 발견했다. 공통 목록의 SQL 조건을 보완하여 두 Run 전체에서 값 단위·시간 단위가 각각 하나이고 누락되지 않은 경우만 비교한다. 단위 변환은 하지 않으며, 시점이 한쪽에만 있는 점은 기존 null 표현을 유지한다. 비교 불가 scalar의 기준 단위는 기존 응답에서 알 수 없으므로 대상 단위를 붙이지 않고 ‘단위 확인 필요’로 표시한다.

검증 계획: 실제 예제 Run의 필터 결과와 API 비교, 근거를 담은 의견 저장·재조회, 초안 보존, 지연 응답 후 Run 일치, 연결 없음/단위 불일치/추가·삭제 변수, 작은 화면 및 기존 영상 설정 회귀. Browser plugin이 없어 기존 Playwright 경로를 사용한다.

구현 세부:

- ComparisonWorkspace와 ComparisonEvidenceTable을 기존 AnalysisWidgets에서 분리했다. 기존 Run 비교 위젯이 그대로 호출하므로 레이아웃을 새로 만들 필요가 없다.
- 기존 의견이 있으면 근거를 아래에 추가하고 이미 추가한 근거는 반복하지 않는다. 작성한 변수 연결·시점·엔티티를 유지한다. 빈 초안에서 대상에 없는 변수를 선택한 경우는 Run 전체 검토로 준비한다.
- 초안은 현재 비교 화면을 유지하는 동안 기준/대상 Run 조합별로 보존한다. 페이지 새로고침이나 결과 문맥을 떠난 뒤까지 보존하는 저장 기능은 아니다. 영구 보존하려면 북마크 저장을 사용한다.
- 저장 대기 중 추가 편집한 내용은 성공 응답으로 지우지 않는다. 늦은 조회 응답은 폐기하며 조회 중에도 Run 선택을 바꿀 수 있다.
- 공통 시계열과 검토 입력란으로 초점을 이동한다. 좁은 화면은 비교·신뢰도·검토를 세로 배치하고 긴 표는 표 안에서 가로 탐색한다.
- 시계열 전환 요청은 정량 근거·신뢰도·검토 목록을 다시 조회하지 않는다. 현재 필터·선택 변수·검토 초안을 유지하고 그래프만 갱신한다.

### 2단계 최종 검증 결과

- 백엔드 단위 및 기존 비교 계약 테스트 16개 통과.
- 신규 Playwright 시나리오 6개 통과: 실제 예제 판정 필터와 의견 저장/재조회, 동일 키 시계열 이동과 초안 보존, 지연 응답 폐기, 단위 불일치/삭제 변수, 저장 중 추가 편집 보존, 시계열 전환 시 근거 유지 및 불필요한 조회 방지.
- 단위 불일치·삭제 변수·시계열 매핑 및 지연 응답 경계 사례는 제어된 브라우저 응답으로 검증했다. 정상 저장·필터 경로는 격리된 예제 서버/API로 확인했다.
- 기존 영상 배치 설정 E2E 1개 통과. 새 분석 화면 데스크톱 1505×1045 / 모바일 390×844 확인, 가로 넘침·pageerror 없음.
- 캡처에서 표의 과도한 여백과 시계열 축 숫자 잘림을 확인해 보정했다. 최종 축 라벨 경계·실제 화면·저장 경로를 포함한 시각 회귀 1개 재검증 통과(13.7초).
- 빌드·TypeScript·아키텍처 검사(152 source files) 통과. 기존 500 kB 초과 번들 경고는 유지된다. Sol 최종 검수에서 추가 차단 사항 없음.
- QA 로그와 comparison-desktop/mobile/chart.png는 저장소 밖 Codex visualization 작업 폴더/comparison-qa에 보관했다. 실제 고객 데이터에서의 원인 분석 효과는 별도 사용자 검증 대상이다.

## 후속 구현: Run 입력 조건 차이

사용자 요청에 따라 결과 변화와 함께 재료·두께·하중·접촉·해석기 및 명시적인 추가 입력의 기록 차이를 표시한다. 현재 설정을 과거 Run에 대입하지 않으며 출처 충돌·미기록·단위 불일치는 확인 필요로 구분한다. 상세 구현·가져오기 방법·Windows 플랫폼 제한은 [Run 입력 조건 비교](run-input-condition-comparison.md)에 기록했다.
