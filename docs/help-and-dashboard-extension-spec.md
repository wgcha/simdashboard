# 사용 시나리오 도움말 및 해석 대시보드 추가 확장 사양

문서 버전: 2.0

## 1. 목적

기존 분석·편집 기능을 변경하거나 제거하지 않고, 사용자가 하려는 작업을 기준으로 화면과 데이터 흐름을 안내한다. 해석용 대시보드의 신뢰성을 높이는 기능은 추가형으로 제공한다.

## 2. 도움말 진입과 구성

- 좌측 메뉴에 `도움말`을 추가한다.
- 기능 목록보다 사용 시나리오를 먼저 보여준다.
- 각 시나리오는 목적, 순서, 주의사항, 관련 화면으로 이동하는 버튼을 제공한다.
- 첫 제공 시나리오:
  1. 새 해석 결과 등록과 확인
  2. 폴더 결과·변수 카탈로그·대시보드 연결
  3. 편집 가능한 PPT 보고서 생성
  4. 대시보드 레이아웃 추가·저장·복구
  5. 이전 Run 비교·데이터 신뢰도 확인·검토 의견 관리
  6. 예제 갤러리에서 전체 기능 빠르게 둘러보기
- PostgreSQL은 현재 DuckDB 실행과 구분해 “전환 구현 후 사용”임을 명시한다.

## 3. 대시보드 추가 개선 원칙

- 기본 화면과 기존 저장 레이아웃은 유지한다.
- 새 기능은 메뉴, 위젯, 필터 또는 저장 가능한 레이아웃으로 추가한다.
- 선언 변수에 데이터가 없으면 `데이터 대기`를 표시한다.
- 차트에는 출처 변수, 단위, 기준, 최신 결과 시점을 추적할 수 있어야 한다.
- 대시보드와 PPT는 같은 `variable_key` 계약을 사용한다.
- 레이아웃 변경은 버전으로 기록하고 복구 가능해야 한다.

### 3.1 해석 상세 편집 동선

- 좌측 `해석 상세`를 누르면 의뢰 진행 현황이 아니라 현재 하중 경우의 실제 분석 대시보드를 먼저 연다.
- 의뢰 진행 현황에서는 `대시보드 편집`과 `진행 단계 편집`을 각각 제공하고, 분석 결과 화면의 `대시보드 편집`과 상태를 공유하지 않는다.
- 의뢰 진행 현황의 `대시보드 편집`은 의뢰 위젯의 위치·크기, 강조 색상, 글자 크기를 편집한다. 위젯은 이동 손잡이와 오른쪽 아래 크기 조절점을 사용한다.
- 진행 현황 레이아웃은 브라우저 사용자 설정으로 저장하며 요청 ID별 위치·크기를 유지한다. 새 의뢰는 기본 전체 폭 위젯으로 배치한다.
- `진행 단계 편집`에서는 단계명, 담당자, 상태, 진행률, 선택 단계 여부와 메모를 수정하고, 단계 추가·삭제와 앞뒤 순서 변경을 지원한다.
- 단계 목록 저장은 의뢰 단위 전체 목록을 한 트랜잭션으로 교체하여 내용·추가·삭제·순서를 함께 확정한다. 의뢰에는 최소 한 단계가 남아야 한다.
- 진행 단계 편집 중에는 전체 의뢰 진행률을 변경된 단계 진행률로 미리 계산하며, 취소하면 모든 단계 값을 편집 시작 시점으로 복원한다.
- 대시보드 편집 모드는 카드 상단 이동 손잡이, 오른쪽 아래 크기 조절점, 위젯별 설정·삭제 버튼을 명시적으로 표시한다.
- 편집 도구 모음에서 현재 레이아웃 이름과 버전, 조작 안내, `위젯 추가·버전 관리` 진입을 제공한다.
- `편집 취소`는 편집 시작 당시의 위젯 구성·위치·크기·설정을 복원한다. 다른 화면 또는 분석 탭으로 이동할 때도 저장하지 않은 변경을 남기지 않는다.
- `레이아웃 저장`이 성공한 경우에만 새 대시보드 버전으로 확정한다.

### 3.2 운영 대시보드 편집

- 운영 대시보드의 차트 순서는 드래그 손잡이와 좌·우 이동 버튼을 모두 제공해 마우스·터치패드 환경에서 동일하게 편집할 수 있어야 한다.
- 글자 크기는 슬라이더와 증감 버튼으로 8~18px 범위에서 조절한다.
- `기본값`은 기본 차트 순서와 글자 크기를 미리 적용하며, 사용자가 `운영 설정 저장`을 눌러야 확정한다.
- `편집 취소` 또는 다른 페이지 이동 시 차트 순서와 글자 크기를 편집 시작 상태로 복원한다.
- 저장 실패 시 편집 상태를 유지하고 오류를 표시한다.

## 4. 후속 업그레이드 후보

1. 결과 최신성·적재 상태·검증 경고를 보여주는 데이터 품질 위젯 — 1순위 구현
2. 여러 해석 Run을 겹쳐 비교하는 버전/Run 비교 탭 — 1순위 구현
3. 판정 기준 변경 전후 영향을 계산하는 What-if 보조 화면
4. 변수별 출처 파일과 파서 이력을 여는 데이터 계보 패널
5. 보고서 출력 이력과 생성 파일을 연결하는 감사 로그
6. 변수·시점·엔티티를 고정하는 결과 북마크와 검토 의견 — 1순위 구현

후보는 기존 판정 로직을 바꾸지 않고 별도 위젯 또는 패널로 추가한다.

### 4.1 1순위 구현 범위

- 기존 `오픈셀 파손 평가`, `Chassis rear 휨 평가`, 저장 레이아웃과 판정 API는 변경하지 않는다.
- `Run 비교·검토` 하위 탭을 추가하고 기준 Run과 대상 Run을 각각 선택한다.
- 같은 `variable_key`와 단위를 가진 정량 결과만 차이와 변화율을 계산한다. 단위가 다르면 비교 불가로 표시한다.
- 판정 변화는 `회귀(PASS → FAIL)`, `개선(FAIL → PASS)`, `유지`로 표시하며 원 판정을 다시 계산하거나 덮어쓰지 않는다.
- 공통 시계열 변수는 같은 시간축에 겹쳐 표시한다.
- 선택 Run의 적재 출처, 체크섬, 스키마·파서 버전, 결과 수, 변수 카탈로그 연결 상태, 단위 일관성, 검증 결과를 신뢰도 패널에 표시한다.
- 북마크는 Run, 변수, 선택 시점, 노드·요소 문맥을 저장할 수 있다.
- 검토 의견은 `OPEN`, `IN_REVIEW`, `RESOLVED` 상태를 가지며 삭제 대신 상태 변경으로 이력을 보존한다.

### 4.2 추가 데이터 모델

- `analysis_run_metadata`: 원본 종류·이름·체크섬, 스키마·파서 버전과 적재 문맥
- `result_bookmarks`: Run·변수·시점·엔티티에 고정한 검토 위치
- `review_annotations`: 북마크에 연결된 의견, 작성자와 검토 상태

기존 `analysis_runs`, 결과 테이블, `validations`, `folder_import_jobs`는 변경하지 않고 외래 참조 키로만 연결한다.

## 5. 수용 기준

- 도움말 메뉴와 여섯 가지 시나리오가 표시된다.
- 예제 갤러리에서 기능·상태·데이터형으로 예제를 찾고 관련 화면으로 바로 이동할 수 있다.
- 각 시나리오 버튼이 관련 화면으로 이동한다.
- 폴더 스키마, 결과 테이블, 변수 카탈로그, 대시보드/PPT의 역할 차이가 도움말에 명시된다.
- PostgreSQL이 아직 활성 연결이 아님을 오해 없이 안내한다.
- Run 비교에서 기준/대상 선택, 회귀·개선·유지 표시와 공통 시계열 비교가 동작한다.
- 신뢰도 패널에서 출처, 최신성, 카탈로그 연결, 단위 및 검증 상태를 확인할 수 있다.
- 결과 문맥에 검토 의견을 생성하고 상태를 `RESOLVED`까지 변경할 수 있다.
- 좌측 `해석 상세`에서 바로 위젯 대시보드로 진입하며, 진행 단계 편집과 대시보드 편집의 버튼명이 구분된다.
- 위젯 이동·크기 조절·설정 패널·추가 도구가 편집 모드에서 보이고, 취소 시 편집 전 상태가 복원된다.
- 의뢰 진행 상태에서 단계명·담당자·상태·진행률·선택 여부·메모를 저장할 수 있고, 취소 시 서버와 화면 데이터가 변경되지 않는다.
- 의뢰 진행 상태에서 `대시보드 편집`과 `진행 단계 편집`이 동시에 노출되지 않고 각각 독립적으로 저장·취소된다.
- 진행 현황 대시보드에서 의뢰 위젯의 위치·크기, 강조 색상과 글자 크기를 변경하고 새로고침 후 복원할 수 있다.
- 진행 단계의 추가·삭제·앞뒤 이동을 저장할 수 있으며 순번은 1부터 연속으로 다시 부여된다.
- 운영 대시보드에서 드래그 또는 이동 버튼으로 차트 순서를 바꾸고 글자 크기를 조절·저장·취소·기본값 복원할 수 있다.
