# 변경 영향 분석과 파일 검토함 사용 안내

- 기준일: 2026-09-15
- 상태: 기능 구현·검증 완료. 운영 배포와 새 설치 패키지 제작은 별도다.
- 구현: `backend/app/routers/semantic_review.py`, `backend/app/services/semantic_impact.py`, `frontend/src/features/data/SemanticReviewQueue.tsx`, `SemanticImpactDialog.tsx`.
- 관련: [의미 매핑 기본 안내](semantic-mapping-guide.md), [기준 정의·별칭](semantic-vocabulary.md), [설계와 배포 계약](semantic-review-impact-plan.md).

## 정의를 활성화하기 전

1. `결과 의미 연결`에서 레시피와 템플릿을 저장하고 샘플 미리보기를 실행한다.
2. 함께 활성화 버튼을 누르면 `활성화 영향 미리보기`가 열린다. 이 시점에는 활성 버전이 변경되지 않는다.
3. 영향을 받는 폴더, 연결된 레시피/템플릿 조합, 과거 Run 수, 대기 중인 검토 항목 수와 호환성 결과를 확인한다.
4. `활성화 가능` 상태에서 `검토 후 활성화`를 누른다. 서버가 참조와 버전을 다시 검사한 뒤 레시피와 템플릿을 함께 활성화한다.

검증은 저장된 레시피 샘플을 사용한다. 폴더 안의 모든 실제 파일을 스캔한 결과가 아니다. 다른 활성 폴더에서 사용하는 위젯과 호환되지 않거나, 필요한 샘플이 없거나, 영향 검사 한도를 넘으면 활성화하지 않는다. 정의·활성 버전·연결이 바뀌면 이전 미리보기 대신 최신 상태를 다시 확인한다.

과거 Run은 저장 당시의 레시피·항목·템플릿 버전으로 보존된다. 활성화 자체는 Run을 생성하거나 기존 결과를 다시 쓰지 않는다.

## 미처리 파일 검토

1. `2. 폴더 연결`의 저장된 폴더에서 `새로고침`을 누른다.
2. 레시피가 없거나 여러 개가 맞거나 파일을 읽을 수 없으면 검토 항목이 저장된다. 해당 폴더의 `검토함`을 연다.
3. 상태 필터로 미처리·검증 만료·검증 완료·등록 완료 등을 조회하고 파일을 선택한다.
4. 폴더에 설정된 활성 레시피를 선택하고 `서버 재검증`을 누른다. 내용·단위·결과 항목과 위젯 입력을 검사한다. 이 단계에서는 결과를 등록하지 않는다.
5. 결과 미리보기와 선택 버전을 확인한 뒤 `명시적으로 등록`을 누른다.

처음 발견한 정상 파일에 단일 레시피가 맞으면 기존 새로고침 방식대로 자동 등록한다. 이미 검토함에 들어간 파일은 새로고침에서 한 레시피만 맞게 되더라도 명시적 검증·등록을 거친다. 잘못된 레시피를 수정한 뒤에는 저장·활성화하고, 필요한 경우 폴더의 적용 레시피를 갱신한 후 다시 판별한다.

| 상태 | 의미와 다음 동작 |
|---|---|
| `OPEN` | 미처리. 원인 확인 후 활성 레시피를 선택해 재검증한다. |
| `READY` | 특정 파일 해시·폴더 개정·레시피/템플릿 버전으로 검증됨. 확인 후 등록한다. |
| `STALE` | 파일 또는 연결이 달라져 이전 검증이 만료됨. 새로고침 후 재검증한다. |
| `IMPORTED` | 새 Run으로 등록 완료. 처리 이력에서 Run 연결을 확인한다. |
| `SKIPPED` | 같은 원본과 레시피 버전의 Run이 이미 있어 재사용함. |

판별 상태는 검토 상태와 별개다. `UNMAPPED`는 맞는 레시피 없음, `AMBIGUOUS`는 여러 레시피 일치, `INVALID`는 내용·위젯 등 검증 실패, `PENDING`은 파일 잠김 등 재시도가 필요한 상황을 나타낸다. 구체적인 오류와 후보를 함께 확인한다.

## 결과와 이력 보존

- 재검증 후 원본이 변경되거나 삭제되면 등록하지 않는다. 현재 원본으로 다시 판별한다.
- 선택만 바꾸어도 이전 검증이 새 선택을 승인한 것이 되지는 않는다. 새 레시피로 다시 검증한다.
- 동일한 원본 해시와 동일한 레시피 버전을 반복 확정해도 Run을 중복 생성하지 않는다.
- 새로운 파일 내용이나 다른 해석 버전으로 처리하면 이전 Run을 유지하며 처리 이력에 이전/새 실행 관계를 남긴다.
- 처리 완료 파일은 레시피의 활성 버전만 변경해도 자동 재처리하지 않는다. `IMPORTED`/`SKIPPED` 항목의 `다시 검토`를 눌러 새 검토를 열고, 원하는 활성 버전을 선택하여 재검증·등록한다. 같은 버전을 다시 확정하면 기존 Run을 재사용한다.
- 검토함 이력은 생성·재판별·검증·만료·확정 전이를 남긴다. 과거 행을 갱신해 이력을 대체하지 않는다.
- 검토함이 원본 전체를 별도로 복제하지는 않는다. 원본이 삭제되면 검토 이력만으로 재처리할 수 있다고 보장하지 않는다.

## 범위와 배포

현재 CSV/JSON과 기존 의미 매핑의 위젯 타입을 지원한다. 탐색은 연결된 폴더 바로 아래 파일을 대상으로 한다. 기존 파일당 5 MiB, 대상 파일 500개, 디렉터리 항목 5,000개, 읽기 총량 128 MiB 한도를 유지한다. 영향 분석은 해당 정의를 참조하는 폴더 최대 200개를 검사하며 초과하면 활성화를 차단한다. 과거 Run 목록은 최대 50개, 항목별 이력은 최근 100개와 잘림 여부를 표시한다. 검토함은 폴더별 상태 필터와 페이지 조회를 제공하며, 프로젝트 전체 통합 검토함과 오류 유형 필터는 후속 범위다.

설정 영향 조회는 기존 카탈로그 관리자 권한, 파일 검토·확정은 대상 하중 경우의 결과 등록 권한을 요구한다. 권한 없는 사용자의 요청은 서버에서 거부한다.

폴더를 다른 하중 경우로 재연결하면 그 대상의 새 검토 항목과 이력을 만든다. 이전 항목은 원래 대상에 남고 새 대상의 목록에 섞이지 않는다. 이전 항목을 직접 조회하려면 현재 연결 대상과 원래 항목·Run 대상의 권한을 모두 요구하며, 이전 대상 항목을 새 대상으로 등록하는 요청은 거부한다.

PostgreSQL `0026_semantic_import_review`는 기존 0025 뒤에 검토 항목과 처리 이력 테이블을 추가한다. 스키마 변경은 기존 배포 절차에서만 수행한다. 앱 시작은 준비 상태를 검사하며 사용자 DB를 자동 변경하지 않는다. `deploy.bat`, `update.bat`, 폐쇄망 패키지·백업·영구 상태 보존 계약은 그대로 유지한다. 기존 설치 EXE에 새 기능이 자동 포함되는 것은 아니므로 배포 시 새 릴리스 패키지가 필요하다.

## 검증 기록

- 기존 의미 매핑 엔진/API·사전·활성화·SPDM·ingestion 경계 회귀와 신규 영향 분석·검토함 검사를 수행했다. Windows 기본 문자셋 때문에 실패했던 기존 소스 읽기 검사는 UTF-8 실행 환경에서 재검증했다.
- 최종 검토함 API 검사 15개를 통과했다. 파싱 도중 개정 변경, 프로젝트 재연결 후 이력 권한 분리, 일시적으로 읽을 수 없는 완료 파일, 고정 버전 확인과 재처리, 권한 검사 전 파일 접근 금지와 감사 실패 rollback을 포함한다. 기존 INVALID 파일이 반복 새로고침에서 PENDING으로 바뀌던 회귀도 수정·재검증했다.
- 폐기 가능한 native PostgreSQL에서 빈 설치와 데이터가 있는 0025→0026 업데이트, 반복 migration, 신규 테이블의 컬럼·CHECK·FK·인덱스 일치, 기본/사용자 지정 앱 역할 CRUD·DDL 차단, dump/restore 보존을 확인했다. 빈 검증 DB의 0026 downgrade/re-upgrade도 확인했으며 일반 배포에 downgrade 절차를 추가하지 않았다.
- 같은 PostgreSQL에서 동시 새로고침 중복 방지, 동시 확정의 단일 Run/provenance/감사 기록, 감사 저장 실패 시 전체 rollback, 명시적 새 버전 재처리와 이전 값·Run 관계 보존을 확인했다.
- 배포 관련 회귀 206개 통과·실행 조건 없는 5개 건너뜀, 영구 경로 관련 2개 통과, Windows 배포 PowerShell 자체 검사 8종과 구문 검사 34개를 통과했다.
- OpenAPI 생성 계약, TypeScript·프런트 아키텍처·정적 빌드를 확인했다. 검증용 격리 사본의 Vite 설정과 DB·QA 산출물은 제품 소스에 포함하지 않는다.
- 실제 API를 사용하는 Playwright에서 새 운영 시나리오 2개와 기존 의미 매핑 4개·사전 5개를 확인했다. 레시피 선택 변경 시 확정 차단, 처리 이력, 명시적 다시 검토와 동일 Run 재사용, 영향 미리보기 후에만 활성화, 조회 전용 계정의 403, 늦은 응답의 화면 혼입 방지를 포함한다. Browser 플러그인이 없어 저장소 Playwright 실행기를 사용했고, 데스크톱 1280×720·모바일 390×844 화면을 검사했다.
- 실제 사용자 DB·서비스는 사용하지 않았다. 실제 폐쇄망 Server 2022 신규 설치·기존 DB 업데이트·재부팅, 새 EXE 제작·운영 배포는 이번 소스 검증에 포함하지 않았다.
